# Uranus UX v1 — 本地交互走查与优化建议

> 日期：2026-10-25。对象：本地 http://127.0.0.1:5173/ ，设置页显示版本 0.2.0-preview.1。
> 方法：使用 web-access 技能选择浏览器工具，实际点击、输入、拖动、右键、撤销、搜索与刷新；结合用户提供的两张截图和 plan_v1 / plan_v2。不是仅根据代码推断。
> 本文是体验评审及建议清单，不是已实施变更，也不自动替代原需求。涉及新增产品行为时，实施前同步需求和验收规则；不改变鉴权、D1/R2、保存与内容 schema 安全约束。

## 1. 总体判断

目前已经具备可用的笔记编辑基础。主要提升空间不是继续增加按钮，而是让操作入口与当前对象一致、减少视觉负担、让操作结果可预期。

最值得先做的五件事：

1. 将表格创建的 36 个文字按钮改为真正的矩形网格预览。
2. 将表格行/列菜单从“小控制面板”改为短小的对象操作菜单。
3. 统一表格手柄、右键、键盘入口背后的选区与命令行为。
4. 收敛顶部工具栏和窄屏布局，突出高频操作，弱化危险操作。
5. 提升列宽、对齐、搜索结果和保存状态的反馈，让用户知道操作影响了哪里。

本次没有验证到需要定为 P0 的数据损坏问题；不能据此证明没有数据风险。下文 P1 为高频操作优先优化，P2 为第二批改善，P3 为后续验证，不与 plan_v1 的功能阶段 P2 混为一谈。

## 3. 表格创建：用空间选择替代阅读 36 个标签

### UX-01｜P1｜实测：创建面板信息过重、距离触发点远

路径：点击工具栏“表格”。面板显示 1×1 至 6×6 共 36 个独立文字按钮，并同时展开行数、列数、表头、插入、取消；桌面面板出现在编辑区域左侧，而按钮位于工具栏更右侧。

建议：

- 使用等大小小方格，悬停/方向键移动到第 3 行第 4 列时，高亮左上 3×4 矩形，底部显示“3 行 × 4 列”。
- 明确顺序为“行 × 列”，不能仅用 `3×4` 让用户猜测。
- 点击格子直接插入；自定义行列收进“自定义尺寸…”二级区域，仅在数值模式显示“插入”确认按钮。
- “包含表头”保留为一个轻量选项，不重复展示两套同等权重的提交路径。
- 面板锚定表格按钮并自动翻转避开边缘；仅在斜杠命令触发时锚定光标。

验收：鼠标两次点击完成常见表格插入；键盘可选择尺寸、Enter 插入、Escape 取消；关闭后恢复原选区，不能把表格插到意外位置。

### UX-02｜P2｜建议：尺寸输入要防错而非提交后报错

- 数值入口标注允许范围，输入非法值或结构预算超限时就地提示；保留用户输入便于修正。
- 显示“包含 1 行表头”，说明表头计入总行数，而不是额外添加一行。
- 不把过大表格创建出来后才告知无法保存；默认不引入“记住上次巨大尺寸”。

## 4. 表格选择、菜单与直接操作

### UX-03｜P1｜实测：列菜单混入行、对齐、更多与退出表格

路径：点击第二列的省略号。菜单标题为“列操作”，却含“行 / 列 / 对齐 / 更多”切换、“在表格下方继续输入”和三个大按钮；桌面约 300px 宽，覆盖操作对象。

建议按对象提供不同菜单，不再所有入口打开同一个综合面板：

| 入口 | 首层内容 | 不宜常驻 |
| --- | --- | --- |
| 行手柄 | 上方插行、下方插行、清空内容、删除所选行 | 列宽、切换到列操作 |
| 列手柄 | 左侧插列、右侧插列、调整列宽、清空内容、删除所选列 | 在表格下方输入、行操作切换 |
| 表格左上角 | 表头、宽度模式、平均列宽、表格前后插入段落、删除表格 | 全部行列命令重复展示 |
| 单元格右键 | 与选区相关的行列插入、内容对齐、清空、更多 | 不相关的全局笔记管理 |

桌面改为紧凑纵向菜单，建议宽 220—260px、菜单项高约 32—36px；触屏使用更宽松目标，不为追求紧凑降低可达性。红色仅用于明确的删除命令，分隔线隔开危险组。

验收：从列手柄打开后，不需要再次选择“列”；高频插列从手柄算起最多两次点击，菜单尽量避开目标文字。

### UX-04｜P1｜实测入口缺口，建议新增上下文右键

本次单元格、笔记列表右键均未出现应用操作菜单。右键应是快捷入口，不是唯一入口：

- 在已选多格内右键保留原选区；在选区外右键切换到目标格，不无意清空整行/列选择。
- 右键打开位置靠近指针，自动避边；键盘 Shift+F10 从当前焦点打开等价菜单。
- 行列手柄和右键复用同一命令与禁用条件，避免两个入口执行不同逻辑。
- 普通正文区域尽量保留浏览器原生文本菜单；不要全页禁止右键。
- 若提供复制/粘贴项，受浏览器权限限制时明确提示键盘快捷键，不显示虚假的“粘贴成功”；右键能力不自动授予剪贴板权限。

验收：分别对单格、多格、整行、整列、只读和菜单临近四角走查；关闭菜单后选区合理保留。

### UX-05｜P1｜实测：手柄与加号视觉权重需要收敛

表格周围出现多处省略号及底部/右侧加号。它们解决了可发现性，但大表格会形成一圈控制点。

- 未交互表格不持续显示所有手柄；hover、键盘焦点或选中表格时显示对应边缘控件。触屏点击选中后显示，不能只依赖 hover。
- 鼠标靠近某行/列时只加强当前目标；在相邻边界显示插入线及加号，提示“在此插入一行/列”。
- 列宽调整边界和插列按钮使用不同命中区，避免拖动变成插列。
- 选中整列可显示“已选第 2 列”或“已选 2 列”；不要让高亮只表达颜色而不表达范围。

### UX-06｜P1｜实测：宽表格的末列与追加入口不易找到

拖宽后桌面右侧表格延伸至视口之外，窄屏只能看到第一列及下一列的一部分。不能把“没撑坏页面”等同于“用户知道可以横向滚动”。

- 可溢出时显示轻量横向滚动条、边缘渐隐或首次提示“左右滑动查看更多列”。
- 行/列手柄随对应表格位置正确移动；菜单定位需计算滚动容器和视口，不能留在旧坐标。
- 即使末列在屏外，也能通过表格菜单追加列，不能强迫用户先找到右侧加号。
- 不在窗口缩小时自动改写已保存列宽；移动端滚动和调整模式要区分，避免拖动手势冲突。

### UX-07｜P2｜实测：列宽可调，但缺少即时量化反馈

本次拖拽成功，更多菜单可以看到 277 的数值；说明核心能力可用。

- 拖拽时给出当前宽度提示，如“277 px”；释放后消失，而不是必须打开更多菜单确认。
- 数值输入显示单位、目标列及范围；“应用列宽”明确是当前列还是所有选中列。
- “恢复自适应”解释会清除手动列宽；“平均分配”解释作用于整表还是选中列，不能暗中扩大范围。
- 以一次完整拖拽为一次撤销，保留现有保存和 schema 规则。

### UX-08｜P1｜实测：对齐选项有入口，但操作语义分散

顶栏存在文本对齐图标，表格菜单内另有水平/垂直下拉框；本次只查看了后者，不能据此认定两者执行错误。

- 顶栏工具提示随对象变化：“段落居中 / 图片居中”；表格菜单明确“单元格水平对齐”“单元格垂直对齐”。
- 常用水平对齐使用三段图标按钮；垂直对齐同样可直接选择，减少打开下拉框步骤。
- 多选属性不同显示混合态；操作后有统一选中态，不必再次展开菜单核实。
- 图片显式对齐优先于单元格对齐时，提供说明或“跟随单元格”，不能让用户误以为居中按钮失效。
- 继续兼容 schema 4；不通过改变整格样式错误覆盖图片或段落自身属性。

### UX-09｜P2｜实测：继续输入入口位置不合理

“在表格下方继续输入”在列菜单中占据明显空间。能力应保留，但移到表格级菜单，并在表格末尾附近提供轻量入口；增加“表格上方插入段落”，解决表格位于文档开头的场景。

验收：在文档首尾表格附近都能继续输入，普通空白点击不生成大量空段落，退出表格不改变其内容。

### UX-10｜P2｜建议：删除结构、清空内容与撤销反馈统一

- 多格 Delete 只清内容；删除行/列显示对象数量；删除最后一行/列沿用整表规则。
- 普通结构操作执行后关闭菜单并回到合理位置，必要时轻提示“已删除 1 列 · 撤销”。
- 非空整表删除确认，空表可直接删除；不要所有插入/删除都弹对话框。
- 本次已验证追加行可撤销，未验证全部删除组合；补测多格、非相邻选区及删除最后一列，不将这些潜在风险写成已复现缺陷。

## 5. 顶部工具栏与整体布局

### UX-11｜P1｜实测：格式工具栏过长，缺少视觉主次

桌面同时展示 H1/H2、六类行内格式、三个对齐、列表/待办、引用、插入等；窄屏首屏仅能看到前段，表格和图片入口需要继续横向寻找。

- 将 H1/H2 合并为“正文/标题”下拉，包含已有支持的层级，不因为减少按钮削减格式能力。
- 常驻加粗、斜体、列表等高频项；删除线、行内代码等放“更多格式”。
- 三个段落对齐合并为当前对齐状态按钮及弹层；在图片选中时正确切换语义。
- 表格、图片、分隔线归入“插入”，桌面可保留表格快捷入口；移动端必须有始终可见的“插入”，不能只能横滑到最末尾。
- 分组保留“撤销重做 / 文字格式 / 结构与插入”，避免所有按钮视觉权重相同。只读和宽度属于视图控制，与正文格式区分。

### UX-12｜P1｜实测：窄屏元信息栏占两行

390px 下返回、收起侧栏、保存状态、置顶、星标、文件夹、历史、删除等换为两行，再叠加格式栏，占据显著垂直空间。

- 手机首行保留“返回、笔记简短标题/保存状态、更多”；将移动、置顶、星标、历史和删除收进更多。
- 当侧栏不可见且已有返回列表时，避免同时放难以理解的“收起侧栏”。
- 格式操作提供紧凑可达入口；真实软键盘弹出后的位置需真机验证，本次没有验证。

### UX-13｜P2｜实测：危险操作与日常操作同等突出

删除按钮位于笔记右上角，与历史/移动相邻。建议收进笔记更多菜单并分组，或至少通过间距和提示区分。普通删除继续可撤销，永久删除必须明确确认；不要为了改布局增加无意义的确认步骤。

### UX-14｜P2｜实测：图标语义与标签不一致

MD 为文字入口，其余多为图标；历史图标、宽度双向箭头、只读眼睛等需要学习成本。

- 所有图标提供一致的可访问名称、悬停说明和快捷键提示；避免只有 title 而触屏无说明。
- MD 改为“导入 Markdown”菜单项或明确导入图标，不让用户误以为切换 Markdown 编辑模式。
- 只读使用“编辑/阅读”状态提示，保留其防误触而非权限控制的准确说明。
- 统一图标尺寸、线宽、控件高度和焦点样式，不用一圈粗焦点框把整个大菜单当主视觉。

### UX-15｜P2｜实测：默认正文比列表更小，层级可再平衡

默认编辑字号 14px，列表标题相对醒目。建议保留用户已确定的字号偏好，不擅自改默认；通过减少列表摘要/时间权重、精简边框和适度行距，使编辑内容成为视觉主角。小字号不是单独的缺陷，应结合实际设备与用户偏好验证。

## 6. 笔记列表、搜索与导航

### UX-16｜P2｜实测：排序独占一行且两个原生选择框较碎

已有排序入口应保留，建议合并为“更新时间 ↓”按钮，打开后分组选择字段和方向；当前排序持续可见。省出的高度用于列表，不通过隐藏入口换取整洁。

### UX-17｜P2｜实测：多条列表摘要重复标题

多篇“边缘操作测试”等标题与摘要相同，增加视觉重复。建议首段被用于标题时，摘要优先选下一段非空内容；无独立摘要则显示内容类型/更新时间，不机械重复。需明确兼容历史派生规则，不能误删正文。

### UX-18｜P1｜实测：列表缺少就地操作入口

右键列表未出现应用菜单；目前管理主要在打开笔记后的顶栏。建议列表 hover/focus 显示省略号，触屏有可见菜单入口，提供星标、置顶、移动、移入最近删除；右键调用同一菜单。右键未选中笔记时作用对象要明显，不能悄悄操作当前编辑笔记。

### UX-19｜P2｜实测：搜索能命中表格内容，但结果解释不足

搜索“状态”能返回本测试笔记，列表仍显示开头摘要“表格交互体验记录”，用户无法从结果判断为什么命中。

- 优先展示包含关键词的安全文本片段，保留标题；显示搜索范围和清空入口。
- 点击结果定位命中属于 plan_v2 后续规划，不在本轮 UI 修整中默认承诺全部实现。
- 添加“正在搜索/无结果/搜索失败”的区别，输入时取消旧结果展示但不闪烁清空整个列表。

### UX-20｜P2｜建议：增强返回路径与位置连续性

本次确认窄屏存在返回按钮，未完整测试多次往返的滚动保持。建议验收返回后保留搜索词、排序、范围和列表位置；普通打开与搜索命中打开区分滚动策略。导航不抢编辑焦点、不卸载尚未保存的草稿。

## 7. 设置、状态与可访问性

### UX-21｜P2｜实测：设置抽屉更像一页配置说明

外观项、安全长文、部署信息纵向堆叠；桌面截图中“关于与部署”已经在首屏下方。

- 常用偏好置顶；安全/部署说明可折叠，或使用清晰小节导航，不必为三个小节立即引入复杂设置系统。
- 字号、宽度和主题提供简短示例或即时预览；控件对齐，排序与其他设置保持同一行高。
- “恢复默认偏好”远离主要选择控件，说明只影响本机偏好；不得顺带清草稿。
- 保留“网页换令牌尚未交付”的真实说明，不添加不可用的伪按钮，不为 UX 优化实施待确认鉴权方案。

### UX-22｜P2｜实测：只读功能正确，但满栏禁用控件仍占空间

本次只读后格式按钮禁用、手柄隐藏。可在只读时收起格式栏，保留查找、显示字号/宽度和清楚的“返回编辑”；尊重现有偏好，不让切换变成另一路编辑器重新加载。危险的笔记管理操作仍需按实际权限处理，不能把只读冒充安全隔离。

### UX-23｜P1｜建议回归：交互优化不能破坏保存可信度

本次看到了“未保存 → 已保存到服务器”及刷新持久化，没有故障注入证据。

- 拖动宽度预览不不断生成保存和快照；最终提交复用既有队列。
- 已暂存本机与已保存服务器不同颜色/文案层级；错误给出重试或保留内容路径，不只有错误码。
- 菜单打开、设置变更、宽度显示切换不修改笔记时间；正文属性变化才进入保存。
- 补测断网、离线草稿失败、冲突和会话失效，不能将“本次正常保存”扩大为所有失败场景可靠。

### UX-24｜P1｜建议回归：完整键盘路径

- 网格选择支持方向键和 Enter；菜单支持上下选择、Enter 执行、Escape 返回，并显示禁用原因。
- 键盘可到达表格手柄，但不能让几十个不可见插入按钮造成冗长 Tab 路径；采用合理的组内导航。
- 已实测 Escape 关闭表格菜单；没有运行读屏软件，读屏表现仍需验证。
- 对齐混合态、选中行列数量、保存失败提供可感知文本；纯颜色不作为唯一反馈。

### UX-25｜P1｜实测：窄屏仍使用桌面式浮动菜单

390px 的列菜单占据大部分可用宽度并盖住表格。建议手机使用底部操作面板，标明“第 1 列”或当前选区，保留背景选中态；桌面继续锚定式菜单。底部面板需考虑安全区和软键盘，测试之后再确定高度，不能用固定大高度压住所有正文。

### UX-26｜P3｜未实测：图片与复杂内容专项

- 上传中的占位、失败重试、尺寸调整、图片右键与单元格选区冲突需要单独走查。
- 图片选中时菜单显示图片操作，表格操作作为次级入口；不把“图片居中”误解释为整列居中。
- 拖动图片和横向滚表的手势冲突，需真实触屏测试。
- 本条是测试建议，不是“图片功能不可用”的结论。

## 8. 推荐交互规则与实施批次

### 8.1 所有菜单遵循同一规则

1. 同一时刻只打开一个同级弹层；从一个对象切到另一个对象时明确更新目标。
2. 先确定选区，再打开菜单；菜单点击不能丢掉选区。
3. 插入/删除这类即时命令执行后关闭；需连续调参的对齐/宽度面板允许保持打开并反馈当前值。
4. 点击外部与 Escape 均可关闭；关闭不自动执行未提交的数值修改。
5. 锚定、避边、滚动跟随和焦点恢复由公共弹层逻辑统一处理。
6. 右键、按钮、键盘只改变入口，不改变同一命令的业务语义。

### 8.2 分批建议

| 批次 | 主要项目 | 收益与边界 |
| --- | --- | --- |
| 第一批：高频操作 | UX-01、03、05、06、11、12、25 | 创建更直观、菜单更短、窄屏能找到功能；不扩展内容 schema |
| 第二批：上下文一致性 | UX-04、07、08、09、10、18、24 | 统一选区、右键、对齐与键盘行为；不能只换视觉而保留歧义 |
| 第三批：整体打磨 | UX-02、13—17、19—22 | 列表信息密度、搜索解释、设置和阅读体验 |
| 独立测试 | UX-23、26及真实手机/IME/读屏 | 保存回归为每批发布门槛，未实测场景不宣称已通过 |

优先采用已有 schema 4 和命令能力。纯菜单、布局、交互提示不需要新增 D1 表或迁移；若新增持久化属性，再按既有版本协议设计，禁止为改 UI 回退旧内容 schema。

## 9. 任务式验收清单

| 场景 | 可观察验收结果 |
| --- | --- |
| 创建 3×4 表格 | 尺寸矩形预览明确，表头是否计入行数清楚，鼠标两次点击可完成 |
| 中间插入一列 | 从目标列手柄两次点击可完成，光标与插入位置正确，原内容不丢 |
| 修改列宽 | 有拖拽指示和宽度反馈，有数值替代；撤销一次还原，刷新保持结果 |
| 多格对齐 | 显示选区范围/混合态，修改仅作用于约定对象，菜单不丢选区 |
| 表格右键 | 选区内外行为明确，与手柄命令一致；普通文本仍有合理原生菜单 |
| 屏幕边缘菜单 | 四角、滚动后均可完整操作；不脱离触发对象，不盖住全部目标信息 |
| 窄屏编辑 | 插入入口可见，危险操作不挤主栏，宽表格横向滚动有提示 |
| 清空与删除 | 清空不删结构，结构删除可撤销，非空整表删除需确认 |
| 搜索表格关键词 | 返回命中片段而非无关首段；定位功能按已批准范围分别验收 |
| 设置与只读 | 不丢草稿/选区，未实现安全功能如实说明，离开设置恢复合理焦点 |
| 保存与升级回归 | 未保存/本机暂存/服务端确认准确区分；schema 1—4 内容不被静默丢弃 |

实施后按上述相同任务复测，记录成功与否、操作步骤数、错误次数和主观困惑点；先建立基线再比较，不凭单次走查编造效率提升百分比。每个新增交互同时覆盖鼠标、键盘和窄屏等价路径。
