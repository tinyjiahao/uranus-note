## 1. 目标与边界

用户通过邮箱注册，设置用户名、密码，通过“邮箱 + 密码”登录；登录后仅能访问自己的笔记本、笔记和附件。支持修改用户名、密码和邮箱，彻底移除 Uranus 应用 `API_TOKEN` 的运行依赖。

- “笔记本”对应现有文件夹 `uranus_folders`，本版不同时引入另一套笔记本/文件夹层级。UI 术语应统一说明，接口可保留 folders 命名。
- “全部笔记、已加星标、最近删除”均为当前用户空间内的视图，不是跨用户视图。
- 用户名为实例内唯一的显示名称，可修改，不作为登录凭据；稳定身份使用不可变 `user_id`，不能使用可修改的邮箱或用户名作为数据主键。
- 邮箱属于当前自部署实例的账号体系，不提供跨实例统一账号。首版仅作为登录标识，不验证邮箱所有权：页面提交邮箱、用户名和密码即可注册，无验证码、验证链接或邮件激活步骤。
- 首版不接入发信服务，不提供邮件通知或邮件找回密码；邮箱可能被误填或他人抢先注册，界面须提示“邮箱仅作为登录账号，暂未验证，请妥善保存密码”。不能将该邮箱当作可信身份或恢复凭据。
- 本版不提供手机号、OAuth、邮箱免密登录、团队、共享笔记本、角色管理后台、公开分享或账号合并。
- 本版不建设自助销号和邮箱丢失后的人工申诉系统；提供清晰的部署者支持说明，不设置绕过身份验证的网页入口。
- 保留 Worker + D1 `DB` + 私有 R2 `UPLOADS`，浏览器不直连数据库或存储，不引入 Cloudflare 管理 API 作为业务鉴权。
- 移除的是应用 `API_TOKEN`，不是部署工具可能使用的 Cloudflare API Token；仍保留 `SESSION_SECRET`，不增加邮件服务 Secrets。

## 3. 注册与登录

### 3.1 邮箱与输入规则

- 邮箱首尾去空格，按统一大小写不敏感策略生成 `email_normalized` 并建立唯一约束；展示保留用户输入形式。登录、注册、改邮箱共用规范化逻辑。格式合法不等于邮箱存在或归用户所有。
- 本版支持常规 ASCII 邮箱地址，最大 254 字符；国际化邮箱支持另行评估。不要去掉 `+tag` 或合并点号，不推断不同地址为同一邮箱。
- 用户名去除首尾空白并做 Unicode NFC 规范化后为 1–32 个 Unicode 码点，允许中文，不允许控制字符或纯空白；按纯文本展示，禁止解释为 HTML。以规范化结果的小写形式生成 `username_normalized`，在实例内唯一，例如 `Alice`、`alice`、` Alice ` 视为同一用户名。展示保留规范化后的大小写，前后端复用同一规则，不依赖数据库默认排序规则推断唯一性。
- 用户名唯一性仅按上述规范化值判断，不新增同形字符检测或复杂名称审核系统；大小写转换使用固定、非 locale 相关规则。
- 密码长度为 **8–128 个 Unicode 码点**，少于 8 个或超过上限拒绝；允许空格、粘贴和密码管理器，但拒绝纯空白密码。不静默 trim、截断或大小写转换，不强制大小写/数字/符号组合。注册和修改密码使用相同规则，前后端校验一致。
- 注册表单包含邮箱、用户名、密码、确认密码；提供密码可见性切换、明确错误提示、键盘和移动端操作。使用正确的 autocomplete 属性。
- 邮箱、用户名、密码、确认密码均必填，确认密码须与密码完全一致；邮箱须满足第 3.1 节格式和长度要求。字段错误在对应输入框附近展示，保留已输入的非敏感字段，不只用通用弹窗。复用现有 Zod 做共享校验，服务端必须独立校验，不能信任前端已校验。
- 字段格式错误返回 HTTP 400 和稳定字段错误标识；邮箱/用户名占用返回 HTTP 409，分别使用 `EMAIL_ALREADY_EXISTS`、`USERNAME_ALREADY_EXISTS`，提示“该邮箱已被使用”或“该用户名已被使用”。不返回占用者信息，不增加公开账号查询接口或每输入一个字符就调用的可用性查询。

### 3.2 页面直接注册

1. 用户填写邮箱、用户名、密码及确认密码，通过格式校验、注册开关、限流及容量预检查后，服务端计算密码安全哈希；最终容量检查必须在数据库创建账号时原子执行。
2. 原子创建可登录用户与唯一的默认 `Notes` 笔记本；不创建待验证申请，不等待邮件或外部服务。
   - 同一 D1 原子操作覆盖容量、唯一性及默认笔记本创建。条件插入零行不等于 batch 自动回滚，后续语句必须受成功条件保护，任一步失败不能留下半成品。无需额外注册工作流、名额预占租约或分布式事务框架。
3. 注册成功返回登录页，预填邮箱但不保留密码；用户使用刚设置的密码登录。提示注册已完成，不显示“待激活”或“请查收邮件”。
4. 邮箱和用户名唯一性以数据库为准；并发注册同一规范化邮箱或用户名最多产生一个账号和一个默认笔记本。重复提交不得覆盖已有账号的用户名、密码或内容，也不能消耗额外名额。
5. 邮箱/用户名占用按第 3.1 节返回字段级错误。此结果可能用于推断注册状态，属于直接注册模式的已知边界，须以限流降低滥用，不能宣称完全防枚举。
6. 网络超时后不盲目再次创建账号，允许用户尝试登录或重试注册；失败不得留下没有默认笔记本的半成品账号。

### 3.3 登录与退出

- 登录仅接收邮箱和密码，不支持用户名、API_TOKEN 或 URL 凭据。失败统一提示“邮箱或密码不正确”；注册成功即可登录，不检查邮件验证状态。
- 成功登录创建全新会话，返回最小用户信息（id、用户名、邮箱）、CSRF token 和到期时间；不返回密码哈希。
- 会话默认 7 天，部署可配置且最长 30 天；本版不新增“永久登录”。独立安装窗口与普通网页使用相同规则。
- 登录后恢复当前用户自己的最后访问笔记；外部深链接无权限时显示通用“笔记不存在或无权访问”，不暴露其他用户信息。
- 退出前沿用未同步内容提示；确认退出后撤销服务端当前会话、清 Cookie 和当前用户敏感缓存。网络失败时不能声称服务端会话已撤销，应锁定界面并提示重试。首版不新增设备列表或独立“退出所有设备”按钮；修改邮箱/密码时仍自动撤销该用户全部会话。

## 4. 账号设置与账号恢复

### 4.1 设置入口

- 现有设置新增“账号与安全”：用户名、当前邮箱、修改用户名、修改邮箱、修改密码；退出沿用现有入口，不重复添加。
- 移除应用令牌展示、更新指引和网页换令牌入口。普通用户不能查看 Secrets、全站维护状态详情或其他用户信息。
- 修改用户名使用独立账号接口，沿用注册时的格式和唯一性规则，不改笔记更新时间、revision 或 user_id。唯一性检查排除当前用户自身，允许只调整自己的显示大小写；与他人规范化用户名冲突则拒绝且保留原值。数据库唯一约束处理并发抢占，不能先查后无条件更新。

### 4.2 修改邮箱

1. 已登录用户输入当前密码和新邮箱；界面说明修改的是登录账号，不会发送验证邮件，并展示“保存后需使用新邮箱重新登录”。不要求重复输入邮箱或新增多步向导。
2. 校验有效会话、CSRF、当前密码和新邮箱格式；用户提交后直接修改，不创建等待验证的改邮箱申请。
3. 原子检查新邮箱唯一性和账号凭据版本，更新邮箱并递增凭据版本；并发修改最多一次成功，不能覆盖其他账号或合并数据。规范化后与当前邮箱相同按无变更处理。
4. 成功后撤销全部会话，要求用新邮箱和原密码重新登录；所有笔记仍属于同一 user_id。错误密码或邮箱占用时保持旧邮箱和原数据不变。
5. 不证明用户控制新邮箱，也不向新旧邮箱发送通知。修改页面展示新邮箱供再次核对；不能仅输入目标邮箱就重置密码、领取或转移账号。
6. 准备提交前提示未同步草稿并处理保存/放弃选择，不在后台自动提交本机草稿后强制退出。响应丢失时提示尝试新邮箱登录，不重复覆盖账号状态。

### 4.3 修改密码与忘记密码

- 修改密码要求当前密码、新密码及确认密码；成功后递增凭据版本、撤销所有会话，重新登录。不支持读取或找回旧密码明文。
- 首版不提供自助密码重置表单、重置 API 或“发送找回邮件”入口；可提供文字说明“暂不支持自助找回密码，请妥善保存密码”。
- 忘记密码不能只凭邮箱、用户名或新注册同邮箱恢复已有账号。部署者如需人工恢复，必须另行核实身份并在受控维护流程中处理，本版不新增人工恢复工具或公开绕过入口，也不承诺必然恢复。
- 用户重新登录后，只能恢复同一 user_id 的未同步草稿。账号变更不能清除尚未确认放弃的草稿而无提示。

## 5. 首版范围与安全基线

### 5.1 无邮件依赖

- 只使用现有 React/Hono/Zod 等依赖、Workers 原生 Web Crypto、D1/R2 和现有限流 binding；不新增认证框架、密码库、邮件 SDK、验证码服务、Redis、KV 或 Queue 等组件/资源。
- 复用现有表单、对话框、API client 和错误处理，不引入新的 UI 库；用户、会话和归属校验按本版最小需要实现，不建设通用认证平台或插件式适配层。
- 不实现验证码、验证链接、邮件激活、找回密码邮件、安全通知、发信适配器或邮件重试队列；部署无需邮件域名、SMTP 或邮件服务 Secret。
- 不为未来邮件能力提前建设验证申请表、重置令牌表、邮件任务表；如保留邮箱验证状态字段，必须为未验证，不能将直接注册伪装为已验证。
- 后续增加邮箱验证和找回密码时需单独定义既有未验证账号的升级规则，不能仅因某人后来验证了同名邮箱就自动移交现有笔记。

### 5.2 密码与会话

- 密码使用带独立随机盐、可调成本和版本标记的密码哈希方案；禁止明文、可逆加密、单次 SHA-256 或把浏览器预哈希当作安全存储。
- 密码派生使用 Workers 原生 Web Crypto 的 PBKDF2-HMAC-SHA-256，使用独立安全随机盐，存储算法版本、迭代次数、盐和派生结果；不新增 bcrypt/Argon2 等依赖，不自行实现密码学算法。实施时在实际 Workers Runtime 验证安全参数、执行限制和登录耗时；不能为通过限制任意降低安全成本，如无法满足要求则报告阻断而非私自增加依赖。
- 2026-10-27 用户明确指定本版新建/修改密码使用 **10,000 次迭代**、16 字节独立随机盐及 256 位派生结果；这是经明确指示调整的安全取舍，不是静默降级。10,000 次低于 OWASP 的 600,000 次建议，数据库哈希泄露后的离线猜密成本明显降低；在线限流和 100 人上限不能弥补这一差距，不宣称达到该推荐强度。每条哈希保存算法版本与实际迭代次数，后续验证按记录参数执行，不直接以新默认值解释已有哈希；不得再擅自下调或提供任意低成本部署开关。
- 采用可撤销的服务端会话：D1 记录会话与 user_id、到期/撤销状态、凭据版本和会话 CSRF 信息；浏览器 Cookie 使用安全随机会话凭据，服务端只存其摘要，不存可重放的 Cookie 明文。
- 实现固定一套 Cookie 契约：随机会话凭据加 SESSION_SECRET 签名，D1 用随机凭据的摘要查找记录；校验签名、记录、期限和用户凭据版本。轮换 SESSION_SECRET 后旧 Cookie 失效，不同时引入 JWT、refresh token 或多套认证方式。
- 登录验证密码后，创建会话时仍检查读到的用户凭据版本，避免并发修改密码后用旧密码签发新会话。过期/撤销会话由现有 Cron 分批清理，不新增调度服务；每次普通请求不更新 last_seen 或延长有效期。
- 每次请求读取权威会话状态，验证用户可用及凭据版本；不再验证 API_TOKEN 指纹。退出、密码/邮箱变更后，旧会话不可继续调用数据 API。
- 生产 Cookie 保持 HttpOnly、Secure、SameSite=Strict、Path=/、无 Domain，服务端和 Cookie 有效期一致。
- 浏览器写请求继续执行 Origin + 会话 CSRF 校验，beacon 同样保护；匿名注册/登录请求检查 Origin。
- 账号安全变更、退出与在途写请求需要明确提交顺序：变更/撤销完成后提交的旧会话写请求必须拒绝，D1 写入条件包含有效会话和凭据版本。已经授权并开始返回的读响应不能承诺被追回；前端通过账号状态隔离丢弃迟到响应。上传结束时再次校验，失效则不绑定附件，并按现有补偿流程清理对象。
- 密码、Cookie、授权头不得进入日志或浏览器持久存储；邮箱作为个人信息不写通用请求日志。安全审计仅记录必要的用户 id、事件、时间和结果。

### 5.3 防滥用与注册控制

- 登录、注册、改邮箱、修改密码复用现有 `LOGIN_RATE_LIMITER` binding；以操作类型和可信来源 IP 构造 key，并对登录/敏感修改追加邮箱规范化值的 HMAC/user_id key 检查，不新增外部限流服务或专门的失败计数系统。
- 首版沿用现有限流配置（默认每 key 每 60 秒 10 次），超限拒绝并提示稍后再试；具体有效值同步部署文档。不为不同流程新增小时/天级配额框架，不宣称平台限流是严格全局计数。
- 不使用可被攻击者触发的永久账号锁定；限流返回通用提示及 Retry-After。密码错误与账号不存在走相近校验路径，避免明显的账号枚举差异。
- 提供部署级 `REGISTRATION_ENABLED`，默认关闭公开注册，部署者可直接显式开启，无发信配置前置条件；关闭后已注册账号仍可登录、改邮箱和修改密码，不提供邀请系统。新部署文档明确开启步骤，页面在关闭时说明注册未开放。
- 沿用现有请求体、正文、上传大小和分页限制；除下述 100 个用户硬上限外，不新增用户配额、计费、预算管理或用量统计系统。公开注册仍有资源滥用风险，默认关闭；首版面向部署者可控的小规模使用，不宣称适合无保护的公众注册服务。

### 5.4 用户数量硬上限

- 当前版本单个 Uranus 实例最多 **100 个用户**，为固定服务端限制；不提供网页调整入口、无限制模式或环境变量绕过。后续放开须另行修改需求、实现并验收，不随功能完善自动解除。
- 按该实例已持久化的用户记录计数，包括历史数据迁移接收账号、运维创建的账号，以及以后可能存在的禁用/软删除账号；不按在线人数、会话数或邮箱是否验证计数。其他应用在共享 D1 中的用户不计入。
- 注册开关开启且人数少于 100 才允许创建账号。第 100 个用户可以成功创建，第 101 个必须拒绝；达到上限不影响已有账号登录、修改邮箱/密码或访问笔记。
- 在 D1 内以原子约束/条件写入保障容量，所有账号创建路径共用此约束；禁止仅在前端限制、在 Worker 内存计数或先 COUNT 再无条件 INSERT。注册用户和默认笔记本仍需原子成功，容量拒绝不得遗留笔记本或占用名额。
- 只有 100 个用户，直接以用户表为计数依据，不另外维护易漂移的名额计数器；可用 D1 同一原子写入中的计数条件或数据库约束实现，不要求为本需求新增计数表。
- 可以在密码派生前做容量预检查以减少无效计算，但预检查不是最终授权；多 Worker 并发也不得超过 100。失败注册、重复邮箱、事务回滚不占名额；响应丢失后重试不能重复占名额。
- 满额注册返回 HTTP 409 与稳定错误码 `REGISTRATION_CAPACITY_REACHED`，页面显示“当前用户数量已达上限（100 个），暂不接受新用户注册”，保留登录入口，不展示已有用户或精确剩余名额。注册关闭和短时限流分别使用各自错误语义，不混同满额。
- 运维迁移/恢复同样校验上限，超过 100 时停止并报告，不静默删用户或绕过限制；现有账号资料恢复不应被计为新账号。本版无自助销号，不新增自动删除账号释放名额的机制。
- 该上限用于限制注册规模，不保证阻止攻击者抢占剩余名额，也不替代注册开关、请求限流和密码派生成本控制；不因此增加外部反机器人服务或依赖。

## 6. 用户数据归属与隔离

### 6.1 数据模型要求

- 新增用户、会话等必要表，不新增邮件验证申请表；所有表、索引、触发器以 `uranus_` 开头；具体 DDL 在实施设计中补充，不修改已发布 migration。
- 用户表的 `email_normalized` 和 `username_normalized` 均为 NOT NULL，并分别建立数据库唯一约束/索引，索引名以 `uranus_` 开头；注册、资料修改、迁移和恢复均遵守。唯一冲突转换为明确业务错误，事务回滚不得遗留用户、默认笔记本或容量占用。
- `uranus_folders`、`uranus_notes` 显式归属 user_id；默认笔记本唯一键改为 `(user_id, system_key)`，名称唯一规则改为用户范围，禁止保留全局默认 id=1 假设。
- 每个用户恰有一个默认笔记本；注册事务失败不能留下空账号或重复笔记本。笔记本删除/回收/恢复只能使用该用户的默认笔记本。
- 笔记与 folder_id 必须属于同一用户；prev_folder_id 若仍可解析，也必须同属该用户，原笔记本已删除时沿用回收到当前用户默认笔记本的规则。版本、搜索记录、附件、引用优先通过受约束父记录确定归属，不要求机械地给所有表复制 user_id；不能只在列表层过滤。
- 幂等操作绑定 user_id 与操作内容；另一用户复用同一 operation_id 不能读取回执或接管租约。维护/清空回收站任务需区分用户范围和平台定时任务范围。
- 用户相关列表、搜索、计数和排序索引以用户范围设计，禁止先跨用户分页再在前端过滤。
- 用户体系迁移独立于正文 content_schema_version，不因增加所有者而重写 v5 正文或历史快照。

### 6.2 服务端授权

- user_id 只能来自已验证会话；请求 body、URL 或查询参数中的 owner/user_id 不构成授权。
- 所有读写查询均带当前用户条件或已验证的关联条件；直接详情、批量操作、笔记移动、导入导出、搜索、历史恢复、附件复制/下载和幂等状态查询都必须覆盖。
- 跨用户资源统一返回不泄露存在性的 404；未登录返回 401。用户提交明确资源列表的批量请求，入队/写入前发现无权资源则整批拒绝；执行时仍检查归属。清空回收站等沿用可重试的分批任务，任务持久化 user_id 并只扫描该用户数据，不强求跨 D1/R2 或长期任务全局原子完成。
- 附件仍通过私有 API 获取；304、Range、缩略图等路径（如存在）同样先鉴权。新 R2 key 可加入 user_id，但路径前缀不是授权机制，老 key 可保留，通过 D1 归属授权。
- 跨笔记图片复制只允许同一用户内执行；引用别人附件、引用别人的版本或把自己的笔记移入别人笔记本均拒绝。
- 普通账号不能调用全实例备份、恢复、维护冻结或全库清理接口。平台 Cron 可按受控任务跨用户维护，但不能误把用户触发的任务扩大为全站操作。
- 继续保持参数化 SQL、乐观锁、串行保存、固定幂等回执及附件引用一致性，不能用前端隐藏按钮代替权限校验。

## 7. 客户端账号边界

- Query Cache、IndexedDB 草稿、最后打开笔记、恢复提示等按“实例 + user_id”隔离；请求缓存键包含用户身份，不能仅使用 note_id。
- 账号退出/过期锁定正文；切换账号时取消上传和排队同步，清除敏感内存、搜索结果、图片 Blob URL 及旧请求回调。已经发出的请求由服务端继续做授权与提交校验。
- 旧账号的迟到响应不能写入新账号的缓存或界面；重新登录其他账号不能自动重试旧账号草稿。多标签页通过账号变更通知使旧视图失效，不广播正文或凭据。
- 会话过期可保留按 user_id 隔离的本机草稿，只在同一用户再次登录后提供恢复；主动退出按保存/放弃确认处理。共享设备上本地草稿不是加密保险箱，应明确提醒。
- 旧版无 user_id 草稿不能归给下一个登录者；升级前引导原用户同步，残留草稿隔离，仅在显式旧数据归属证明后恢复，无法证明则提供受控清理指引，不自动上传。
- 不新增旧草稿认领界面。原浏览器中的旧草稿仅在登录默认 admin 且笔记已确认归其所有后，沿用现有恢复确认流程；不能满足该条件时保留隔离，不展示给普通账号、不自动删除。
- 主题等无敏感信息的偏好可继续作为浏览器偏好；账号设置与云端所有权不能写入此类通用偏好替代服务端状态。

## 8. 从共享令牌迁移到账号

### 8.0 默认 admin 用户

- 实例初始化时通过受控运维步骤建立唯一的默认用户，初始用户名为 `admin`，所有未归属笔记统一迁移到该用户。`admin` 是默认数据所有者，不是可以读取所有用户数据的超级管理员，不新增角色权限系统。
- `admin` 仍使用邮箱和密码登录；初始化邮箱及初始密码由部署者提供，沿用邮箱唯一、用户名唯一和密码长度规则，不猜测邮箱，不设置公开默认密码。提供单一本地初始化脚本，复用现有 Node/Wrangler 和原生加密能力；密码不通过命令行参数传入，使用不回显输入或未提交的本地配置。凭据不进入仓库、SQL migration、日志或前端，D1 只保存密码安全哈希。不建设网页首次安装向导。
- 初始化在公开注册之前完成；凭据未配置时明确提示初始化未完成，不开放业务访问或允许公众领取该账号。初始化过程复用现有运行环境，不新增依赖、外部服务或永久引导令牌。
- 以持久化的默认用户 id 标识该账号，不能在每次迁移时仅凭用户名或邮箱查找并认领。`admin` 名称（含规范化等价形式）为初始化保留，普通注册或其他用户改名不可占用；默认用户可按既有规则修改自己的显示名称和邮箱，其默认身份仍由 user_id 确定。
- 若发现同名账号但没有可信的初始化标记，停止并由部署者核对，不覆盖密码、不自动将历史笔记交给该账号。重复初始化须幂等，不能再建用户或重置现有密码。
- admin 计入 100 人上限，因此新实例完成初始化后最多再注册 99 个用户；注册开关关闭不阻止受控初始化，但初始化也不得突破总人数上限。

### 8.1 既有实例

1. 升级前通知同步草稿，进入维护模式并排空在途写入，完成可验证的业务数据与附件备份，记录计数、校验和和当前数据库迁移版本。
2. 按第 8.0 节初始化或核对默认 admin 的稳定 user_id，不再让部署者另选历史数据接收用户；不发送验证邮件，也不能由首个注册者或旧 API_TOKEN 持有者在公开页面领取历史数据。
3. 追加迁移，仅将未归属的笔记本、笔记及其关联记录回填为 admin。包括回收站笔记、历史版本、附件及引用、搜索记录和相关操作/清理任务；正文、附件字节、revision、版本关系不变。已有明确归属的数据保持原所有者，不全表覆盖为 admin。
   - 未归属笔记如已引用他人所属笔记本，或其附件/版本存在冲突归属，停止并报告，不偷改已有所有者或静默跨用户关联。
   - 既有未归属默认 Notes 优先复用为 admin 的默认笔记本；初始化与迁移协调执行，不能创建两个默认笔记本。若已存在多个默认候选，显式检查并制定迁移映射，不静默删数据。
   - 迁移完成后，新建笔记始终归当前会话用户；缺失所有者的写请求拒绝，禁止运行时兜底到 admin。无法关联到笔记的孤立附件不直接公开给 admin，仍按既有维护规则检查处理。
4. 若采用分批回填，必须有持久化进度和幂等重试；归属未完整校验前保持维护模式，不允许匿名或新用户看到未归属记录。
   - 维护冻结范围包括注册、账号资料/密码变更及笔记写入；不能只冻结正文而让备份期间用户表继续变化。初始化/恢复仅允许部署者受控工具按维护流程执行，不复用公开注册接口绕过维护锁。
5. 校验零遗漏归属、无跨所有者引用、外键完整及附件可读；预置共享 D1 其他应用表和 R2 其他前缀对象，确认迁移不影响它们。
6. 切换新鉴权并一次性失效全部旧会话，禁用旧令牌登录。迁移完成前不接受新用户业务写入，不混用旧版 Worker 和新版多用户 Worker 灰度服务。
7. 验收后退出维护模式。新增多用户数据后禁止直接回滚旧 Worker；故障优先前向修复，确需恢复则在维护窗口按备份恢复方案明确后续写入损失及处置。

### 8.2 新部署与依赖清理

- 全新数据库不需要 API_TOKEN，先初始化 admin 及其专属 Notes，不产生无人归属的全局 Notes；之后每位用户直接注册成功时建立自己的 Notes。
- 删除 Env 类型、配置检查、登录 DTO、前端输入、测试 fixture、配置示例、部署说明中的应用 API_TOKEN 依赖；生产残留 Secret 不能成为备用认证入口。
- 删除旧 tokenFingerprint 会话契约；SESSION_SECRET 继续保留，轮换可用于全站会话失效，不授予任何用户数据访问权限。
- 备份/恢复脚本不得再读取 `URANUS_API_TOKEN`。移除旧 Secret 属于上线切换步骤，不因编写本需求直接操作生产配置。

## 9. 运维、备份与 API 范围

### 9.1 运维权限

- 本版不建设网页管理员角色。平台级运维采用部署者受控 CLI/平台访问执行，普通邮箱账号没有全实例权限；受控工具须保留维护排空和一致性保障。
- 当前 backup/restore 脚本通过 API_TOKEN 登录后访问全实例维护接口，不能仅改成普通邮箱密码登录继续使用。首版将其迁移到现有 Node/Wrangler 所支持的部署者受控运维路径，不新增永久对外运维认证系统；正常对外 Worker 不开放全实例备份/恢复/冻结接口。不得给 admin Cookie 全库权限作为捷径。
- 运维改造是发布前必须验证的技术交付，不要求新增管理后台、备份产品或实时备份。如果现有工具无法覆盖附件字节导出、排空或恢复，应明确阻断并报告，不以“平台可导出 D1”代替完整备份能力，也不能未经确认引入新服务。
- 用户级导出只包含当前用户内容。全实例备份区分内容数据与敏感账号数据，保留稳定所有权映射；密码哈希属于敏感信息，账号备份须加密和受控存放。
- 不备份可重新使用的会话凭据。恢复后统一撤销会话，账号凭据恢复策略需明确；不得将旧实例的会话带入新实例。
- 首版只调整既有全实例备份/空目标恢复能力，不新增选择性单用户恢复、账号合并或跨实例迁移界面。恢复保留 user_id 和默认 admin 身份映射，不按邮箱自动匹配；账号哈希与内容一并在受控备份中恢复，所有会话失效，仍用原邮箱密码重新登录。
- “空目标”指没有用户和业务数据的待恢复实例；恢复入口必须在自动初始化 admin 之前执行，不为恢复先创建第二个 admin。新部署初始化与备份恢复二选一，恢复完成后再开放业务；不回滚共享 D1 中其他应用对象。

### 9.2 建议接口职责

下列为职责基线，最终路径可随实现统一，必须同步 API 文档与测试。

| 接口 | 职责与保护 |
| --- | --- |
| POST `/api/register` | 匿名限流、Origin、格式校验；直接原子创建账号与默认笔记本 |
| GET / POST / DELETE `/api/session` | 当前用户会话 / 邮箱密码登录 / 撤销当前会话；POST 不接受旧 token 字段 |
| GET / PATCH `/api/account` | 当前账号信息 / 修改显示名称；不接受任意 user_id |
| 修改密码 | 登录、CSRF、当前密码；成功后撤销全部会话，无独立设备管理接口 |
| 修改登录邮箱 | 登录、CSRF、当前密码、新邮箱格式与唯一性、并发条件校验；无需邮件证明 |
| 既有 folders / notes / attachments 等 | 业务路径可保留，但强制贯穿用户归属 |

## 10. 验收与测试清单

- **账号流程**：不配置任何邮件服务即可页面注册并登录；覆盖重复邮箱/大小写冲突、并发创建、失败回滚、密码管理器、修改用户名、登录退出及独立窗口恢复；无等待激活界面。
- **输入与唯一性**：空值、非法邮箱、超长邮箱、用户名纯空白/控制字符/超长均拒绝；邮箱及用户名的大小写、首尾空白规范化冲突均拒绝；用户名 NFC 等价形式按同一名称处理。密码 7 个码点拒绝、8 个与 128 个合法码点通过、129 个及纯空白拒绝，确认密码不一致拒绝。覆盖中文和非 BMP 字符的前后端计数一致、修改用户名撞名、并发相同用户名、迁移冲突及绕过前端直接调用 API；失败不占注册名额。
- **100 人边界**：已有 99 人时并发提交多个不同邮箱，最多成功 1 个且用户总数为 100、无孤立默认笔记本；满额后直接调用 API 同样被拒绝，已有用户仍能正常登录和修改账号。覆盖重复邮箱、事务失败、响应丢失重试不占额，迁移账号计入、超额恢复拒绝及 Worker 重启后限制仍有效。
- **账号安全**：错误当前密码不能修改邮箱或密码；邮箱修改成功后仅新邮箱有效；并发改绑/注册同地址最多一方成功；密码修改后旧密码、旧会话失效；无仅凭邮箱即可找回或接管账号的接口。
- **两用户隔离矩阵**：A/B 同名笔记本合法，各自默认 Notes 独立；用 A 访问 B 的详情、搜索、计数、列表、移动、版本、恢复、附件上传/复制/下载/304、清空回收站、幂等回执和导出全部拒绝且不泄露数据。
- **客户端隔离**：A 编辑未同步时退出/过期，再登录 B；覆盖多标签、迟到请求、图片上传和草稿恢复，确认无 A 数据闪现或写入 B。回到 A 后按规则恢复。
- **安全负向**：CSRF、伪造 user_id、错误 Cookie、会话撤销、暴力尝试、注册探测限流、现有大小限制、缺失必要 binding/secret、密码派生执行限制、敏感日志扫描；缺少邮件配置不影响任何本版流程。
- **零新增依赖**：核对 package.json/lockfile 无新增直接或间接依赖，未引入新的服务 binding；不配置邮件或第三方认证凭据即可完成本版全部账号流程。现有 Cloudflare 资源和 SESSION_SECRET 不属于新增第三方服务。
- **迁移**：有历史笔记/附件/版本/回收站、空库、重复执行、中断续跑、旧草稿、非本应用对象保护；公开首位注册不能领取旧数据。
- **默认 admin**：初始化后用户数为 1，仅剩 99 个注册名额；未归属笔记（含回收站）及关联历史/附件迁移后由 admin 正常访问，其他用户不能访问；原有归属不变。覆盖同名抢占拒绝、缺少初始化凭据、重复初始化不重置密码、跨所有者关联冲突、默认笔记本复用，以及 admin 改名后仍按稳定 id 幂等迁移；admin 不得访问其他用户数据。
- **运维**：普通用户不能冻结/导出整站；验证备份恢复、所有权映射和恢复后旧会话失效；去掉 API_TOKEN 后新部署及现有实例仍可正确运行。
- **并发与维护**：密码变更与登录并发不能签发旧凭据会话；退出后的在途写入不能提交；账号注册/修改在冻结期被拒绝；从空目标恢复不额外创建 admin。异步清理任务持续受 user_id 约束，失败重试不扩大范围。
- **既有功能回归**：保存冲突、幂等、搜索、导入、图片引用、版本恢复、回收站定时清理、PWA 独立窗口和全部已发布内容 schema。
- 单元、Workers 集成、浏览器端到端测试齐备；使用两个独立浏览器上下文测试隔离，不能只依赖前端 mock。覆盖跨设备登录与会话撤销，无邮件投递验收门槛。

## 11. 实施顺序与发布门槛

1. **设计门槛**：验证原生密码派生参数，确定最小用户模型、注册策略和基于现有工具的运维替代路径；形成迁移与恢复演练步骤，不进行第三方服务选型或采购。
2. **后端安全基础**：用户/会话、数据归属约束、全 API 授权及测试；此阶段不开放公众注册。
3. **完整账号流程**：页面直接注册登录、账号设置、当前密码校验、限流、前端账号隔离；不实施邮箱验证与自助找回密码。
4. **迁移与运维**：本地及 staging 带历史数据演练，补齐脚本/配置/README/SECURITY/API/部署/备份文档，证明无 API_TOKEN 运行依赖。
5. **发布**：备份、维护排空、显式归属迁移、切换新 Worker、账号流程与隔离验收，通过后开放站点；注册开关按部署者选择单独开启。

任一跨用户泄露、未登录可访问私人笔记、旧令牌仍有效、历史归属未明确、用户数量可突破 100 或全站运维接口对普通账号可用，均阻断发布。注册成功但未验证邮箱的用户可以访问自己的笔记，这是本版预期行为。不得用“登录页完成”代替多用户能力交付。

## 12. 默认决策与上线前确认项

按照首版简化要求，本需求明确：邮箱密码直接注册登录、邮箱及用户名在实例内分别唯一、用户名可修改、密码最少 8 个码点；不验证邮箱、不依赖发信服务、不提供自助找回密码；改邮箱使用有效会话和当前密码授权，校验新邮箱格式及唯一性；每人独立笔记空间、不支持共享、公开注册默认关闭且可由部署者直接开启。

上线前需部署者确认：

1. 当前实例默认 admin 的初始化登录邮箱已确认为 `admin@admin.com`，初始密码已由部署者另行提供，不在本文记录明文；实施时通过受控输入注入，不硬编码为所有自部署实例的通用凭据。历史未归属数据归 admin 已确认；此处只确认初始化配置，不代表账号已创建或密码已修改。重复初始化不得覆盖既有密码，登录后可按账号设置规则修改邮箱和密码。
2. 是否开启页面注册；默认关闭，开启后仍受固定 100 人硬上限约束，不要求服务预算、配额平台或外部凭据配置。100 人上限已确认，不作为待定项。
3. 实施者完成第 9.1 节受控备份恢复演练；这属于技术交付门槛，而非要求用户另选第三方运维产品。未验证前不能移除现有工具后直接发布。

上述确认仅涉及已有数据归属、注册开关及既有运维能力，不引入第三方登录、付费账号、管理员后台或额外依赖。邮件服务商、发件域名、邮件预算和发信凭据均不属于本版需求或待确认项。
