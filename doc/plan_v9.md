## 2. 编辑输入效率（V9-01、V9-05、V9-06、V9-07）

### 2.1 查找替换（V9-01，P1）

现状：`searchHighlight` 插件已提供匹配计算、高亮装饰、当前匹配序号和 Enter/Shift+Enter 跳转；匹配范围覆盖正文与标题（标题匹配显示 `标题 ·` 前缀标记）。查找栏现有输入框、序号、上/下一个、完成按钮。

要求：

- 查找栏增加替换输入框与"替换"/"全部替换"按钮（仅编辑态显示；只读、回收站笔记只保留查找）。
- 单个替换：替换**当前匹配**（与现有 `findIndex` 对齐的正文匹配）后自动跳到下一匹配，序号随之更新。
- 全部替换：一次 dispatch 替换正文全部匹配，组成**单个撤销步骤**；完成后报告数量（走现有 `uranus-editor-error`/notice 通道）。
- 匹配区间直接复用 `searchHighlightKey` 状态中的 ranges，不另写一套扫描；替换操作必须按区间**从后往前**应用，避免位移失效。
- 标题匹配只显示不替换：标题是独立 textarea，不在 `searchHighlight` 的文档区间内；当前匹配落在标题时"替换"按钮禁用（可配 `title` 提示）。
- 大小写规则沿用现有查找实现，不新增选项；组合输入期间（`isComposing`）替换输入框的 Enter 不触发替换，Esc 行为与查找栏一致。
- 替换内容参与正常编辑路径：进入保存队列、计入撤销历史、遵守正文上限；不绕过校验。
- 空查询时替换按钮禁用；查找栏关闭时清空替换输入。

验收：多匹配逐个替换、全部替换为单步撤销、含标题匹配时按钮态正确、只读无替换入口；浏览器用例覆盖替换后保存往返、撤销/重做、组合输入期间 Enter 不触发、Esc 关闭恢复焦点。

### 2.2 Markdown 粘贴识别（V9-06，P1）

- 纯文本粘贴且剪贴板无 HTML 富文本时，检测并转换常见 Markdown 语法为文档结构：ATX 标题（`#`–`######`）、无序/有序/待办列表（`-`/`*`/`1.`/`- [ ]`/`[x]`）、引用（`>`）、代码块（``` 围栏及语言）、行内代码、`**`/`*`/`~~`/`==`/`[文字](链接)`、分隔线（`---`）、GFM 表格。
- 触发范围护栏：单行短文本、含 URL 的文本、纯 JSON/代码内容（`{`/`[` 开头且无 Markdown 结构特征）不触发转换，按纯文本粘贴；已有 HTML 剪贴板内容时维持现有路径不介入。
- 自写简化解析（不引入 marked/remark 类依赖）：按块级结构逐行解析 + 行内 mark 第二遍，未识别语法保持原文本；转换结果必须能通过 `validateAndDeriveContent` 校验，否则整体回退为纯文本粘贴。
- 目标映射到现有 schema：待办→taskList、`==`→highlight、颜色类语法不支持；表格列宽等属性用默认值。
- 图片与附件语法的处理：
  - `![alt](data:image/…;base64,…)`：解码为字节走现有图片上传流程生成 `attachmentId`，粘贴时先插入占位、上传完成替换为 image/inlineImage 节点，失败降级为 `[alt](url)` 链接文本；单个 data URI 超过图片上限或一次粘贴多张时串行处理，不阻塞粘贴事务。
  - `![alt](http(s)…)`、`![alt](相对路径)`、`![alt](attachments/…)`：降级为链接 `[alt](url)`——不直接引用外部 URL 生成图片节点（私有附件模型要求 attachmentId），不做客户端/服务端抓取上传（CORS/SSRF 成本不划算）；导出再导入的还原属于批量导入路径，不在粘贴范围。
  - `[文件名](url)` 形式的附件链接：按普通链接处理，不生成 fileAttachment/inlineFile 节点（白名单校验需要真实字节与 MIME，仅有 URL 无法校验）。

验收：各语法单元测试（含混合嵌套、转义、边界）；护栏用例（URL、JSON、单行、带 HTML 剪贴板）不转换；转换结果保存往返与既有校验一致；data URI 图片成功上传为私有附件、外链图降级为可点链接。

### 2.3 插入当前日期/时间（V9-05，P2）

- 工具栏"插入"区或独立按钮提供两项：当前日期（`YYYY-MM-DD`）与当前日期时间（`YYYY-MM-DD HH:mm`），按本地时区格式化为**纯文本**插入光标处，单个撤销步骤，不引入新的节点/mark。
- 只读、codeBlock 内禁用；codeBlock 内不插入（代码语义不应被静默改写）。快捷键 `Mod-;`/`Mod-Shift-;` 为可选补充，非必需。

验收：插入内容为纯文本、可继续编辑删除、保存往返一致。

### 2.4 无选区复制当前行（V9-07，P2）

- `Mod-C` 且选区为空（`selection.empty`）时，将光标所在**文本块**（段落/标题/列表项/待办项/引用行/表格单元格段落）的纯文本 + 末尾换行写入剪贴板；有选区时完全走现有复制路径。
- "行"按块定义：ProseMirror 无视觉行概念，折行的段落复制整段文本，不做按视觉行截取；codeBlock 内复制光标所在 `\n` 分隔的物理行。
- 实现：`handleKeyDown`/`handleDOMEvents` 拦截 `Mod-C`，`navigator.clipboard.writeText`，失败静默不报错（避免与浏览器复制提示冲突）；不拦截 `Mod-X`（剪切行不在本项）。
- 只读/回收站同样可用（复制不修改文档）；复制行内附件/图片/标签所在块时按现有纯文本投影取值。

验收：无选区 Mod-C 写入剪贴板且粘贴为整行文本+换行；有选区回归不变；codeBlock 物理行；剪贴板权限被拒时静默。

## 3. 代码块增强（V9-03、V9-04）

### 3.1 格式化与常见语言高亮（V9-03，P2）

格式化：

- `code-actions`（codeBlockView 的现有按钮区）在代码块文本经 `trim` 后以 `{` 或 `[` 开头时显示"格式化"按钮。
- 点击后 `JSON.parse` 成功则替换节点文本为 `JSON.stringify(value, null, 2)`，包成单个撤销步骤；失败不改动内容并提示（`uranus-editor-error`），提示中不输出原始内容。
- 沿用现有代码块操作约定：`uranus-fold-only` 类元信息照加，折叠状态不因格式化改变；只读/回收站中按钮不显示或禁用。
- 不支持除 JSON 外的语言格式化。

高亮——依赖变更登记（按依赖约束要求）：

- 新增 `lowlight@^3`（锁定 lockfile 实际解析版本，须为发布满 7 天的稳定版）。~~`@tiptap/extension-code-block-lowlight`~~：实施时改为在现有 `codeBlockView` 装饰插件内直接调用 lowlight（统一处理注册语言、未标 JSON 探测与 50k 上限守卫，避免与扩展双重装饰），该包最终未引入。
- `lowlight` 及其 `highlight.js` 均为纯 JS、无原生模块，浏览器环境运行；提交时同步 `package.json` 与 `package-lock.json`，并在 AGENTS.md 依赖基线中补充本条例外。
- 语言按需注册，包体最小化：用 `createLowlight()` 建空实例，逐个 `registerLanguage` 引入 `highlight.js/lib/languages/<name>` 单语法模块——禁止 `createLowlight(common)`/`createLowlight(all)` 及 `highlight.js` 顶层整包导入（会把 190+ 语法或约 40 种 common 全部打进 bundle）。
- 注册语言：`json`、`javascript`（含 jsx）、`typescript`（含 tsx）、`xml`（覆盖 html）、`css`、`python`、`bash`、`sql`、`yaml`；后续增删语言只改注册表。
- 体积门槛：按需注册后 highlight 相关代码的 gzip 增量目标 **≤ 40KB**（实测值记入交付说明）；如超标，优先裁语言表而非引入异步加载——编辑器主路径保持同步高亮，不做语言模块懒加载。

高亮——要求：

- 在 `codeBlockView` 的 decorations 插件内调用 lowlight 产生 `hljs-*` 内联装饰，不修改文档内容，不占用 schema 版本；与行号/折叠/复制/语言下拉共存，不相互覆盖。
- 语言判定沿用 codeBlock 的 `language` 属性（由 ``` `lang` 输入规则产生）；未标语言但文本 `trim` 后以 `{`/`[` 开头的块按 JSON 高亮（与格式化同一判定函数，通过 lowlight 按 `"json"` 调用，不在文档上落 language 属性）。
- `language` 为未注册语言时不高亮，按纯文本处理。
- 性能护栏：块内字符数超过阈值（建议 50k）跳过高亮（该块视同无 language），避免大文件阻塞输入；lowlight 执行异常时该块降级为无高亮，不得影响编辑。
- 配色：引入 highlight.js 语义 class（`hljs-*`）并定义本项目深浅主题配色表，不自写主题文件以外的样式，不与行内 code 样式串扰。

验收：已注册语言产生 `hljs-*` 装饰；未标语言 JSON 探测生效；未注册语言不高亮；格式化按钮的出现条件、成功替换（含 undo 单步）、失败提示；浏览器用例覆盖编辑中高亮更新、``` `lang` 输入规则、超大块跳过、与折叠/行号/复制共存；gzip 体积实测记入交付说明。

## 4. 界面与观感（V9-02、V9-08、V9-09）

### 4.1 列表首图缩略（V9-02，P1）

- 笔记列表行显示该笔记**第一幅图片**的小缩略图（含块级 `image` 与 `inlineImage`，取文档顺序首个）；无图片的行保持现状。
- 数据来源：优先复用 `uranus_attachment_refs`/服务端派生（列表查询附带首个图片附件 id），不在行内存完整图片 URL，不新增正文存储列；实现方式以不为列表增加 per-note 额外往返为准（一次列表响应内带回）。
- 客户端用现有鉴权下载接口取图：`/api/attachments/:id` 已带 `private, max-age=31536000, immutable`（plan_v7），渲染 `<img loading="lazy" decoding="async">`，固定小尺寸裁切（`object-fit: cover`），点击区域仍整行打开笔记。
- 首图被删除、附件 GC 或引用清除后缩略图随之消失；下载失败静默降级为无缩略，不显示破图。
- 缩略图出现在回收站列表时同样遵守只读语义；搜索结果行同样显示。
- 不引入宫格视图；列表布局其他部分不变。

验收：列表响应携带正确的首图附件 id（含 inlineImage、表格内图片按现有引用规则）；删除首图后列表更新；长列表滚动懒加载；二次打开图片走缓存命中；附件失效行正常降级。

### 4.2 笔记菜单弹层去重标题（V9-08，P2）

- 笔记"…"菜单弹层（`Workspace.tsx` 的 noteMenu `Popup`）顶部不再渲染笔记标题文本——与列表行标题重复；`title` 仍作为 `role="dialog"` 的 `aria-label` 保留，× 关闭与 ‹ 返回（移动到文件夹子菜单）位置不变。
- 实现：`Popup` 增加可选 `hideTitle` 类属性，隐藏标题文本但保留布局占位与 aria-label；其他弹层（笔记信息、导出、表格菜单等）标题显示不变。
- 进入"移动到文件夹"子菜单时可选择继续隐藏或显示"移动到文件夹"标题，取实现便利，不另立验收点。

验收：菜单打开后首项为"置顶"；读屏仍能获得弹层名称；其他 `Popup` 调用方显示回归。

### 4.3 UI 动效与过渡优化（V9-09，P2）

现状：全项目几乎无 CSS transition/animation——弹层（`object-popup`）、通知（`.notice`/`.editor-notice`）、设置抽屉、对话框、按钮 hover、表格插行按钮、拖拽手柄均为瞬时切换，视觉生硬；属纯观感问题，非性能问题。

要求：

- **弹层**：`object-popup` 打开时 120–160ms 的 `opacity` + `transform`（桌面 `translateY(4px→0)`/轻微缩放；移动端底部抽屉 `translateY(100%→0)` 滑入）+ `.popup-backdrop` 淡入；关闭/卸载因节点直接移除，淡出动画为可选——若实现成本明显则保持瞬时关闭，不做强制要求。
- **通知/提示**：`.notice`、`.editor-notice` 出现/消失加 opacity+位移过渡（自动消失处用过渡而非瞬隐）。
- **抽屉与对话框**：`.settings-drawer` 右缘滑入；`.folder-dialog` 类居中弹框淡入。
- **微交互**：按钮/列表行/菜单项的 `background-color`、表格插行按钮与拖拽手柄的 `opacity` 加 80–120ms 过渡；hover 态变化不生硬。
- **性能约束**：只动 `transform`/`opacity`/`background-color`，禁止对 `width/height/top/left` 做动画（避免 layout 抖动）；统一时长 80–200ms，`ease-out` 或系统缓动，不做弹性/物理动画。
- **无障碍**：`@media (prefers-reduced-motion: reduce)` 下全部过渡缩至 ~0ms/瞬时，功能行为不变。
- **实现**：纯 CSS transition + 少量 `@keyframes` 进入动画；不引入动画库、不改组件挂载逻辑（关闭瞬时化的取舍见上）。

验收：人工目验菜单/弹层/通知/抽屉平滑无迟滞、深浅主题一致；`prefers-reduced-motion` 模拟下动效消失、功能正常；弹层定位回归——进入动画结束后必须清除 transform 或用只影响起始帧的 keyframes，避免 transform 残留改变 fixed 定位上下文。

## 4.4 `/` 斜杠命令菜单（V9-10，P2）

- 光标位于**空段落开头**输入 `/` 时打开命令菜单；后续输入作为过滤词（不含空格），↑↓ 选择、Enter 执行、Esc 关闭并将已输入的 `/xxx` 保留为普通文本；空格、光标离开、非段落位置自动关闭。
- 菜单项复用工具栏现有命令（代码块、标题 1–3、引用、列表、待办、分隔线、表格、日期/日期时间），执行 = 删除 `/xxx` 文本 + 运行命令，零新命令逻辑。
- 过滤后只有一个匹配项时仍显示菜单，按 Enter 执行对应样式；Esc 保留原文本。方向键切换选项时菜单保持锚定输入的斜杠。
- 实现：自研插件（不引 `@tiptap/suggestion`），组合输入期间不触发（`/` 由 IME 直出时按普通按键处理）；只读不触发。
- 本项是对 plan_v5"`/` 作为普通文本、不做斜杠菜单"决策的显式变更，以本条为准。
- 验收：空段落 `/` 弹菜单、过滤、Enter 执行（如 `/code`→代码块）、Esc 保留文本、非空段落/中段输入 `/` 不触发、撤销恢复。
