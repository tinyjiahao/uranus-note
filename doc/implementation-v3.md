## 数据与安全

- 没有新增 D1 表、迁移、持久化正文属性或 content schema 5；继续使用 schema 4、DB/UPLOADS bindings 和原鉴权。
- 正文仍经过共享校验、800ms 防抖、串行保存队列、revision 乐观锁和 operation_id 幂等。菜单不直接写数据库。
- 搜索不使用 FTS、不改全量候选排序和分页；不返回完整搜索正文、不逐篇请求正文补列表。
- 列表位置、搜索上下文和失败上传文件仅在内存，不新增敏感内容到 localStorage。
- 本地测试新增了验收笔记及附件；未清理用户已有数据。测试输出位于被 gitignore 排除的 test-results。

本地结果：类型检查及 git diff --check 通过；16 个测试文件、35 项单元/Workers 集成测试通过；最终 Chrome 全量 19 项 e2e 通过（54.2 秒）。e2e 启动流程内的构建、本地迁移和 Worker preview 均成功。桌面/暗色/窄屏/触屏模拟截图已检查。最终复跑包含菜单目标失效、编辑器焦点恢复、稳定表格锚点和多层菜单逐级退出保护。

- 类型检查：`npm run typecheck`。
- 单元及 Workers 集成：`npm test`；包含规范化/emoji/100 码点查询、最大 100 条页、150 条全量排序、schema、附件引用、版本、幂等和安全回归。
- Chrome：`npm run test:e2e -- --workers=2`。脚本先本地迁移、构建并启动 Worker preview；不是纯静态服务器。
- 新用例覆盖矩形创建、自定义错误、多格菜单和数值宽度、列插入/清空/撤销、图片菜单、目标笔记隔离、搜索高亮、320/375/390/768/1440px 格式顺序、只读、触屏模拟、上传失败重试。

- 本地 e2e fixture 为不同测试模拟不同客户端 IP，避免共享十次/分钟的登录配额造成用例互相限流；仅 loopback URL 使用测试头，不修改生产限流逻辑。原 Workers 安全测试继续运行。

## 顶部标题修正（2026-10-25）

- 移除只读标题副本，顶部改为可编辑文本区；首个顶层段落/标题块不再出现在正文编辑区，Enter 进入正文，组合输入不提前跳转。
- 仅做编辑视图拆分：通过 `noteTitle.ts` 合并回完整文档后进入原保存队列，API、schema 4、迁移及鉴权不变。保留原块类型/属性及未修改文字格式，不抽取表格、列表等复杂块的子内容。
- 新笔记保留空标题块；清空标题不会删除正文。空标题的列表名称仍遵循服务端首个非空文本回退规则。标题原生文本撤销与正文格式栏撤销分别作用于各自编辑区。
- 只读、回收站及历史预览不可修改标题；切换/刷新按保存的完整文档重新拆分。标题与正文连续修改使用最新标题节点合并，避免保存响应覆盖本地输入。
- 新增拆分/合并、格式保留、复杂块保护、空标题和多行/emoji 单元测试，以及旧 Markdown 标题移位、标题编辑/正文连续修改、表格保留、刷新、笔记切换、只读和 320px 窄屏浏览器回归。
- 同时修复旧失焦回调可能用过期 note 对象降低已确认 revision 的问题：保存队列空闲时也只接受单调递增的 revision，并增加专门回归测试；不放宽服务端乐观锁或冲突保护。
- 本次最终验证：类型检查通过，18 个文件共 40 项单元/集成测试通过，Chrome 全量 20 项 e2e 通过（含构建与本地迁移），`git diff --check` 通过；本地 5173 返回 HTTP 200，未部署线上。
