## 2. V12-01 版本表 `ORDER BY id DESC` 语义修复（P0）

### 2.1 背景

`uranus_note_versions.id` 由 `randomSafeInteger()`（53 位随机整数）生成——随机资源 id 是项目的刻意设计（防枚举、无中心发号器），本身合理（`uranus_notes`/`uranus_folders`/`uranus_users` 的对外 id 也是同一约定）。但修复前 `worker/services/notes.ts` **五处**查询把 `ORDER BY id DESC` 当作"按时间倒序"，随机 id 下语义错误：

| 位置 | 修复前代码 | 实际后果 |
| --- | --- | --- |
| `listVersions` | `ORDER BY id DESC LIMIT ? OFFSET ?` | 版本历史列表按随机序显示（用户截图现象） |
| 版本保留清理 ×3 | `DELETE ... id NOT IN (SELECT id ... ORDER BY id DESC LIMIT 30)` | 分别位于保存、手动建版本、版本恢复三条路径——**本应"保留最近 30 个版本"，实际随机保留 30 个——最新版本可能被误删**，数据正确性问题 |
| 版本去重判断 | `latest = SELECT ... ORDER BY id DESC LIMIT 1` 后比较内容 | 与随机版本而非最新版本比内容：该复用时未复用（多存），或小概率误复用 |

其他排查：`maintenance.ts` `ORDER BY id LIMIT 50` 是回收站清理的任务分批，id 序只是任意取批方式，与时间语义无关，不算缺陷（可顺手改 `deleted_at` 排序但无必要）。其余表（attachments/operations/maintenance_jobs）使用 TEXT uuid/uuidv7 id，不涉及本问题。

### 2.2 方案

- 五处排序统一改为 `ORDER BY created_at DESC, id DESC`（id 作 tiebreak 保证确定性排序）。

- 保留清理语义修正为"保留 created_at 最新的 30 个版本"；去重判断改为与 created_at 最新版本比较。

- 现有索引 `uranus_note_versions_note_idx (note_id, id DESC)` 对 created_at 排序无帮助，但每篇笔记版本上限 30 条，单篇笔记范围内排序成本有限——**不换索引、不加迁移**；若后续版本上限放大再评估 `(note_id, created_at DESC)` 索引。

- 随机 id 生成器不变（防枚举设计保留）；id 仍承担唯一标识职责，不参与排序语义。

### 2.3 边界

- 仅改 `notes.ts` 五条 SQL，无 schema/迁移/DTO 变化。

- 存量数据无需修复——created_at 本来就在记录，只是没被用于排序；被误删的版本不可恢复（接受，从修复时点起止损）。

- 历史版本存在性依赖此查询的恢复/预览路径行为不变，仅顺序与保留集合正确。

## 3. V12-02 本地标题索引（P1）

「插入笔记链接」弹层（`src/components/editor/noteLinks.tsx` 的 `NoteLinkPopup`）原先每次输入变更都在 250ms 防抖后发起分页 `GET /api/notes?q=` 搜索，逐页拉取后再由前端按标题二次过滤。连续输入产生大量被取消的请求，结果只使用 `id` 与 `title` 两个字段，却执行了标题+正文的服务端搜索。改为弹层打开时一次性拉取全量标题索引，输入过程纯本地过滤。

### 3.1 索引构建

- 弹层打开时通过 TanStack Query 拉取当前账号全部可见笔记的 `{id, title}`：循环调用既有 `GET /api/notes`（不带 `q`、不带 `deleted`），按 `pageSize=50` 翻页直到 `hasMore=false`。

- 结果存入独立的 Query key（`["user", userId, "notes", "title-index"]`，归入既有列表失效前缀），`staleTime` 600 秒（10 分钟）；同会话内索引未过期且未失效时再次打开直接命中缓存，不重复请求。

- 标题索引仅为标签页级内存态，不走 IndexedDB。`staleTime` 不设 `Infinity`，过期后在下一次使用时重建；本标签页写入通过列表失效前缀联动，既有 v11 BroadcastChannel 通知也可使该前缀失效。跨设备没有实时推送，不能把十分钟有效期理解为定时自动刷新。

- 按账号隔离 queryKey，账号切换自动落到对应用户的索引；沿用 `identity` 代次与请求取消约定，旧账号响应不得写入新账号界面。

- 服务端列表默认排除回收站笔记，索引同样不含已删除笔记，与现状一致（不链接到回收站目标）。

### 3.2 本地过滤

- 输入变更时对索引执行 `normalizeSearch(title).includes(normalizeSearch(query.trim()))`，复用现有规范化函数，结果与原先“服务端搜索 + 标题二次过滤”的标题匹配行为等价，并按下述规则排除当前笔记。

- 空查询时按列表默认排序返回排除当前笔记后的前 50 条，匹配结果上限同样为 50 条。

- 过滤在内存中同步完成，取消现有 250ms 防抖与分页循环；输入即出结果，不再产生可取消的进行中请求。

- 保留加载中、错误与空结果提示；索引请求失败按现有错误文案降级显示，不静默吞错。

- **排除当前笔记**：插入链接候选按当前笔记 ID 排除自身，空查询、本地标题过滤及超过 50 页后的服务端搜索降级均适用；先排除再计算 50 条上限，降级分页继续补足其他候选。同名但不同 ID 的笔记仍可选择。共享标题索引保留完整数据，已有自链接不作删除或改写。

### 3.3 新鲜度与失效

- 新建、重命名（标题变化）、删除、还原、移动文件夹等改变笔记列表的写入路径已统一 `invalidateQueries`，将标题索引 queryKey 纳入同一失效面，确保变更后下次打开弹层重建索引。

- `staleTime` 为跨端变更提供过期校验；索引过期后再次打开弹层重建，不设置十分钟定时轮询，也不承诺弹层一直打开时自动收到跨设备更新。

- 弹层展示不需要 revision、snippet 等字段；索引只保留标题匹配所需的最小数据。

### 3.4 规模护栏

- 全量拉取适用于个人笔记量级；设置护栏：拉取到第 50 页（2500 篇）仍未取完时停止拉取，回退到现有的服务端 `q=` 搜索模式（保留原分页循环逻辑作为降级路径），不阻塞弹层使用。

- 索引条目为 `{id, title}`，内存占用按每篇数十字节计，千级规模无压力；不持久化到 IndexedDB（与 v11 的详情缓存正交，标题索引是易重建的派生数据）。

### 3.5 范围边界

- 本项负责 `NoteLinkPopup` 的候选获取与过滤；样式见 V12-03，标题批量解析见 V12-04，节点选中与跳转见 V12-11。共享索引不因排除当前笔记而删除条目。

- 不做：离线可用承诺、增量/差量同步、标题索引持久化、服务端新端点（如专用 titles 接口——可作为后续优化项，当前列表接口已够用）、正文内容搜索（弹层语义本来就是按标题选笔记）。

- 不改动服务端代码、共享 DTO、数据库；不新增依赖。

## 4. V12-03 笔记链接弹层样式收敛（P1）

### 4.1 背景

原弹层过窄且候选区未限高，长标题换行导致弹层过高；候选缺少留白，粗黄色焦点轮廓被滚动区裁切，搜索框与标题区层次不清晰。

### 4.2 方案

- 弹层最大宽度 420px，同时受视口约束；候选区最大高度 280px，内部纵向滚动，不随 50 条候选撑满全屏。
- 长标题单行省略，完整标题保留在 `title` 悬浮提示中。
- 候选统一左右留白与行高：桌面最小 38px、触屏最小 44px。左侧显示笔记图标，键盘聚焦时右侧显示回车提示，装饰图标不影响无障碍名称。
- 键盘焦点使用柔和强调色背景与细内边框；方向键选择时选中项滚动进入可视区。
- 搜索图标与输入框一体化，移除重复内边框；标题区移除强分隔线，统一字号、间距与圆角。
- 兼容 `ui-surfaces.css` 的通用规则，深浅主题均可读；移动端宽度受视口限制，保留限高和单行省略。

### 4.3 边界

仅调整视觉、无障碍提示及滚动行为；不改变 50 条候选上限、本地搜索、缓存复用和插入逻辑。当前笔记的排除规则统一见 §3.2。

## 5. V12-04 笔记链接标题批量解析（P1）

### 5.1 背景

打开一篇含多个 noteLink 的笔记时，原先每个 `NoteLinkView` 各自发一次 `getNote` 详情请求解析目标标题（`noteLinks.tsx` L15）。N 个链接即 N 个详情请求，与附件、列表请求叠加形成并发突发；且详情响应体含完整正文，为取一个标题传输了整个文档，浪费明显。

### 5.2 方案：标题索引优先，`ids=` 批量兜底

- 笔记打开或正文变化时收集文档内全部 `noteLink.noteId`，去重并稳定排序；同一文档的节点共享 ID 集合与 Query，避免每个链接请求一次正文。
- 优先使用 V12-02 中未失效且未过期的标题索引；未命中的 ID 通过既有 `GET /api/notes?ids=…` 补全。所有目标命中新鲜索引时不发标题解析请求。
- **每批最多 20 个 ID**，遵循现有 `RECENT_NOTE_LIMIT` 和 URL 校验，不扩容服务端接口。未命中唯一 ID 数为 M 时，所需请求数为 `ceil(M / 20)`。
- 账号隔离的 Query 保存目标 ID 到标题的映射。命中时显示解析标题；缺失、查询失败或目标已删除时，回退节点内嵌标题快照并标记“（不可用）”。
- `ids` 列表响应照常写入 v11 的可回收 `rememberListVersions` 信息，不新增缓存层。请求取消与身份代次检查防止旧账号响应写回。

### 5.3 边界与取舍

- 列表默认排除回收站；无权限目标同样不进入标题映射。标题索引沿用十分钟新鲜度及列表失效规则，不承诺跨设备实时推送。
- 编辑新增链接后重新收集 ID 集合并补全，等待期间使用标题快照。
- 不改变节点结构、属性或服务端接口；插入候选排除自身见 V12-02，选中与跳转行为见 V12-11。

## 6. V12-05 应用内回退/前进导航（P1）

### 6.1 背景

点击 noteLink 跳转笔记时 `navigate('/notes/:id')` 会正常压入浏览器历史，浏览器自带的前进/后退可用；但应用内没有任何回退入口——PWA 独立窗口没有浏览器导航栏，浏览器标签页中用户也不容易发现可以用浏览器后退，导致"跳转后回不去"的观感。

### 6.2 方案：应用内导航栈与路由同步

- `state/history.ts` 维护标签页级内存栈与当前位置，记录完整 `pathname + search` 及对应的 Router location key。
- 通过 `useLocation` 和公开的导航类型区分 POP、普通 PUSH、应用按钮移动与 REPLACE；不读取 `window.history.state.idx`，不依赖包含站外页面的 `history.length`。
- 浏览器 POP 按已知 location key 定位；普通 PUSH 截断前进栈并追加，即使目标 URL 等于相邻条目，也不能误判成回退。
- 应用按钮导航到明确的站内目标 URL，并携带目标栈位置，使回退/前进移动不重复追加逻辑条目。
- REPLACE 覆盖当前条目，不新增历史。删除当前笔记后显式 `navigate("/", { replace: true })`，避免应用回退重新进入刚删除的当前条目。
- 账号变化清空导航栈；刷新后从当前页面重新建立。浏览器导航与应用按钮混用时保持一致。

### 6.3 界面与交互

- 笔记区顶栏（返回列表按钮旁）增加 `‹ 回退` / `› 前进` 按钮，`pos > 0` / `pos < stack.length - 1` 时启用，否则禁用置灰。

- 回退目标可能是 `/`（列表视图）或 `/notes/:id`，栈内记录完整 location 即可自然支持；不额外记录列表 scope（scope 由现有 `rememberList` 逻辑恢复）。

- 键盘：`Alt+←` / `Alt+→`（浏览器原生后退前进已可用；应用按钮是无浏览器 chrome 场景的补充，不重复绑定冲突快捷键）。

- 按钮触发 导航到栈中 `pos±1` 对应 URL 的 `navigate(...)`，而非 `navigate(-1)`——保证和自维护栈同步，也避免误退到应用外页面。

### 6.4 边界与取舍

- **标签页级内存**：栈仅存内存，刷新后重建；浏览器历史仍由 BrowserRouter 保留，应用栈从刷新点重新开始。多标签页各自独立，不共享。

- **已删除/无权限目标**：回退到已移入回收站的笔记按现有回收站语义展示（详情可读、编辑受限）；回退到已硬删除的笔记按现有 404 处理展示，不算导航栈缺陷。

- **登录态失效**：回退后若会话已过期走现有 401 锁定流程，导航栈不介入鉴权。

- **不持久化**：导航历史是会话内 UI 状态，不进 IndexedDB/localStorage/sessionStorage，与"localStorage 只存 UI 偏好"基线一致。

- 移动端：顶栏空间紧张时按钮可只保留回退（前进价值低），或在更多菜单收纳；以桌面/PWA 为主验收。

## 7. V12-06 数字等宽显示（P2）

### 7.1 背景

界面中多位数字（统计数值、id、计数等）上下排列时宽度不齐：项目使用 macOS 系统字体 SF Pro，其数字默认启用比例宽度（proportional figures），`1` 明显窄于 `3`/`4`/`6`，导致同位数数字串视觉宽度不一致，观感参差。

### 7.2 方案

- 对需要数字对齐或宽度稳定的元素加 `font-variant-numeric: tabular-nums`：SF Pro 内置 `tnum` 特性表，切换为等宽数字，无需引入字体文件。

- 适用范围限于数值型展示位：笔记信息统计（字数、附件计数、链接计数）、版本列表时间与计数、id/计数类数字串。逐类审查样式类名后按需添加，不全局开启。

- 正文段落、普通文本不加——等宽数字会破坏阅读排版节奏。

### 7.3 边界

- 纯 CSS 一行属性，零依赖；无兼容性问题（不支持的旧浏览器自动回退比例数字，仅观感差异）。

- 中英文混排处只影响数字宽度，不改变其他字符渲染。

## 8. V12-07 编辑器焦点指示线弱化（P2）

### 8.1 背景

`styles.css` 中 `.editor-content:focus-within` 显示 2px、45% 琥珀色 inset 顶线，用于提示编辑区焦点。该线与表格单元格选中高亮（同为 amber 系）在视觉上易混淆，用户会误认为"表格选中高亮未清除"。

### 8.2 方案

- 保留焦点提示语义但弱化：线宽 2px → **1px**，透明度 45% → **~20%**（`color-mix(in srgb, var(--accent) 20%, transparent)`）。

- 仅改 `styles.css` 一处声明，无结构变化。

### 8.3 边界

- 不删除该指示（焦点可见性仍有价值）；若后续仍觉得干扰，再评估移除。

## 9. V12-08 自然高度与表头吸顶（P2）

### 9.1 背景

原实现为表头吸顶引入最高 70dvh 的局部滚动区域，导致长表格被裁成固定高度。按用户最新要求，恢复原来的内容自然高度，同时实现随正文滚动的表头吸顶。

### 9.2 方案

- 取消表格 max-height 限制及内部纵向滚动，所有行完整撑开表格，随正文滚动。
- 首行全部为表头单元格时，通过 NodeView 监听编辑区滚动、视口及表格尺寸变化，优先使用浏览器 ScrollTimeline 驱动真实表头和行号角格的 transform，避免 JavaScript 逐次追赶异步滚动。NodeView 仅在表格几何、正文高度或目标节点变化时重建线性滚动关键帧；尺寸变化使用 requestAnimationFrame 合并计算。不支持 ScrollTimeline 时回退至滚动事件直接更新位移，不额外等待一帧，不使用时间缓动。表头到达编辑区顶部后吸顶，位移限制在当前表格内，表格滚出视口时表头同步移走。
- 原生路径通过 Web Animations 驱动真实表头，回退路径仅写入 NodeView 外层的 CSS 变量；不复制表头，不改变正文及选区。横向滚动及列宽仍由原表格布局管理。销毁时清理动画、监听、尺寸观察器和待执行帧。
- 保留原有横向滚动、列宽、行号、表格编辑操作、表头背景及单边框视觉。开启行号时，首行左上角空白格与表头同步吸顶，遮挡滚过的正文行号；吸顶期间使用细底边与轻微阴影区分正文，回到原位及打印时取消阴影。
- 桌面与移动端均保持自然高度，适配编辑区顶部及可视视口变化；只读状态也支持吸顶。打印禁用表头位移，完整输出表格。

### 9.3 边界

复用现有 NodeView 和浏览器原生 API，不新增依赖、正文节点、schema 或迁移；不引入克隆表头的独立交互、序列化或保存路径。

## 10. V12-09 代码块操作按钮图标化（P2）

### 10.1 背景

代码块右上角操作区（`code-actions`）全部为文字按钮：`JSON`（语言菜单）、`格式化`、`复制`、`选中整块`、`删除代码块`，占宽较大且视觉上拥挤。

### 10.2 方案

- 将动作按钮改为**图标按钮**：`格式化` → 格式化类图标、`复制` → Copy、`选中整块` → 选框类图标、`删除代码块` → Trash2；保留 `aria-label` 与 `title` 悬浮提示（图标无语义文本，无障碍与可发现性靠这两者兜）。

- 图标来源：`codeBlockView.ts` 是非 React 的 NodeView，沿用 `tables.ts` 的既有模式——inline SVG `innerHTML` 字符串（lucide 同款 stroke 风格），不引入 lucide-react 到该层。

- `JSON` 语言按钮**保留文字**：它是语言标识而非动作，文字本身就是信息；可收窄 padding 让其更像徽章。

- “已复制”反馈采用 Copy → Check 图标切换，同步更新 `title` 与 `aria-label`，短暂显示后恢复。

- 图标按钮尺寸对齐现有工具栏按钮密度（24px 可点区域，14px 图标本体；触屏扩大点击区域），hover 态沿用 `.code-actions button:hover` 规则。

### 10.3 边界

- 仅 `codeBlockView.ts` 的按钮渲染与 `styles.css` 对应类名调整；点击行为、语言菜单触发（`uranus-code-language` 事件）、格式化/复制/删除逻辑全部不变。

- 打印样式下 `.code-actions` 已整体隐藏，无回归。

## 11. V12-10 Markdown 导出转义兼容修复（P1）

### 11.1 背景

旧版 Markdown 导入仅解析部分块结构，表格、加粗与行内代码可能仍以普通文本保存。原导出器统一转义，使表格分隔符输出为 `\|`，加粗输出为 `\*\*`，行内代码反引号也被转义；每个表格行又按独立段落输出，产生空行。

### 11.2 方案与边界

- 对旧导入产生的纯文本段落，只有在表头与合法 GFM 分隔行列数一致时识别为源表格；允许行间空段落，将匹配列数的连续表格行合并输出，保留结构性 `|`，不插入段落空行。
- 普通文本中完整配对的 `**加粗**`、`__加粗__`、`~~删除线~~` 和反引号行内代码保留 Markdown 源语法，不重复转义。
- 字母或数字之间的下划线无需转义，如 `plan_v12.md`、`created_at`；其他必要转义继续保留。
- 不把任意管道文本都转换成表格；未配对符号、普通管道文本与非代码中的 HTML 继续执行必要转义。代码块原文及已有富文本标记的导出路径保持不变。
- 独立 Markdown 下载与 ZIP 中的 Markdown 共用 `shared/markdownExport.ts`。仅修复导出，不重写已保存笔记，不改变导入器，也不自动修复已下载的旧文件；用户须重新导出。
- 不承诺任意 Markdown 方言或富文本格式无损往返；本项兼容识别范围以以上规则为限。

### 11.3 已有验证

- `npm run typecheck` 通过。
- `npm run test -- tests/unit/markdown-export-source.test.ts tests/unit/v7-content-export.test.ts`：10 项通过，覆盖旧表格、完整源语法、标识符下划线、必要转义、普通管道文本、代码块及既有导出回归。
- `tests/e2e/markdown-export.spec.ts` 浏览器用例通过：保存含旧格式文本的笔记，通过实际导出菜单下载 `.md`，读取文件确认连续表格行及加粗、行内代码未被重复转义。

## 12. V12-11 笔记链接选中与剪贴板操作（P1）

### 12.1 背景

原笔记链接单击立即导航，无法稳定保留编辑器节点选区，用户难以执行复制、剪切、删除等编辑操作。

### 12.2 交互与边界

- 编辑状态单击笔记链接选中完整 `noteLink` 节点，显示单层细内边框与柔和背景，并在链接下方弹出与普通链接相同样式的操作菜单；链接内部不再附加打开箭头。右键同样打开此菜单，阻止浏览器默认链接菜单。
- 操作菜单提供“打开笔记、复制、剪切、删除”，复用普通链接的 `link-actions-popup` 样式，删除项单独分隔。鼠标打开菜单不抢走编辑器焦点，保留节点选区和编辑快捷键；Escape 或点击外部关闭菜单。只读时隐藏剪切和删除；不可用目标禁用打开。复制/剪切触发既有 ProseMirror 剪贴板事件，保留富文本节点；失败时显示提示，可改用快捷键重试。
- 普通链接与笔记链接操作菜单统一使用紧凑关闭按钮（桌面 28px），键盘焦点采用柔和背景和单层细内边框，避免粗黄色外轮廓。普通链接通过鼠标打开时保留编辑器焦点，不自动聚焦“×”；键盘激活打开菜单时初始聚焦“打开链接”。首次和再次打开遵循相同规则，Escape 在焦点仍位于编辑器时也能关闭菜单；不移除键盘焦点提示。
- 复用 ProseMirror 原有复制、剪切、删除、粘贴及撤销路径，不自行用标题纯文本替换节点；富文本剪贴板保留目标 ID 与标题快照，跨笔记粘贴后仍为链接节点。
- 编辑状态通过菜单中的“打开笔记”、双击或 Ctrl/⌘ 单击跳转。链接获得键盘焦点后 Enter 仍可激活；只读状态保留单击跳转，不开放修改。
- 不可用目标仍可在编辑状态选中和删除，但禁止跳转；组合输入期间不主动选中或跳转。
- 提示文案支持中英文。无 schema、API、依赖、存储或迁移变更；沿用既有保存队列和账号鉴权。

### 12.3 已有验证

类型检查通过。Chrome 浏览器使用实际剪贴板验证单击节点选区、复制 HTML 保留 ID、剪切、删除、撤销、跨笔记粘贴及打开按钮；双击跳转与应用/浏览器前进回退混用回归通过。真实 Safari/iOS、IME 与各操作系统剪贴板兼容性仍需人工验收。
