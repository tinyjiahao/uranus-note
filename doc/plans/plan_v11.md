# Uranus v11 — 笔记本地缓存

日期：2026-11-19。状态：本地实施及验证见 `../implementation/implementation-v11.md`，不代表已上线。已完成开发前最终复核，本文为实施基线。

## 1. 目标与范围

使用 TanStack Query 内存缓存和 IndexedDB 持久缓存，减少重复获取笔记正文的请求及传输量，改善重复打开笔记的速度。以服务器 `revision` 判断内容是否变化，`updatedAt` 仅用于展示，不作为新旧判断依据。

沿用 v6 用户隔离、现有保存队列、草稿与冲突机制，以及 v8–v10 的内容格式和浏览器兼容约束。不新增依赖、内容 schema、数据库迁移、Service Worker、离线同步或后台定时轮询。

首版仅持久缓存笔记详情。笔记列表、筛选、排序和分页继续使用 TanStack Query；图片及附件字节沿用现有私有缓存，不重复保存到正文缓存。localStorage 仅保存偏好，不存正文和凭据。

## 2. V11-01 缓存结构与容量（P0）

缓存存储服务器确认的完整 NoteDetail，附带：

| 字段 | 用途 |
| --- | --- |
| userId、noteId | 账号与笔记联合标识 |
| revision | 服务器版本 |
| contentSchemaVersion | 正文格式版本 |
| etag | 服务端返回的原始详情 ETag，可为空；不得由客户端猜测 |
| representationVersion | 详情表示格式契约版本，用于防止部署后错误复用 |
| cacheFormatVersion | 本地缓存结构版本，与正文 schema 独立 |
| note | 已确认的笔记详情 |
| validatedAt | 最近一次可信服务端校验的时间 |
| lastAccessedAt | 最近访问时间，用于淘汰 |
| byteSize | 序列化记录的 UTF-8 字节数，用于容量预算 |

- 默认开启，按 origin、账号隔离命名空间，并在异步读写前后核对当前账号及身份代次。TanStack Query 管理请求与界面状态，IndexedDB 只保存已确认副本；由统一详情读取模块负责有效期、版本比较和失效，不允许两层各自实现不同规则。只持久化详情白名单字段，不持久化整个 QueryClient、搜索命中片段或乐观更新值。
- 每账号最多 100 篇或 50MB（50,000,000 字节），达到任一限制按最久未访问淘汰；实际浏览器存储开销可能高于记录字节数。
- 每次仅按需载入当前笔记，不把所有缓存正文一次性装入内存；缓存写入不阻塞正文显示与保存确认。LRU 访问时间可合并更新，不能每次渲染都写 IndexedDB。单条记录超出预算时跳过持久化，配额错误最多淘汰后重试一次。
- 不兼容的缓存结构、未知正文版本或损坏记录不得加载到编辑器，删除该缓存并重新请求。不能降级解释或静默删减正文。
- IndexedDB 不可用、配额不足或写入失败时降级为网络读取，不能阻断笔记编辑与保存，也不能把缓存失败报告为保存失败。

## 3. V11-02 读取与有效期（P0）

校验有效期默认固定为 60 秒，首版不提供时长调节。优先级为：身份/可见性限制 → 清理或失效代次 → 首次权威读取 → 已知更新版本 → 60 秒有效期 → 条件校验。下表仅适用于身份有效且未被显式失效的副本。

| 场景 | 行为 |
| --- | --- |
| 没有详情缓存 | 获取完整详情，成功后写缓存 |
| 缓存最近 60 秒内校验通过 | 直接复用，不请求详情 |
| 新鲜列表条目的笔记 revision 与缓存相同，且详情表示格式兼容 | 复用详情，不请求正文 |
| 列表条目的笔记 revision 高于缓存 | 获取最新详情 |
| 缓存过期且没有新鲜列表版本 | 发起详情条件请求 |
| 手动刷新 | 忽略有效期并强制校验 |

- 应用启动先确认登录身份，再显示该账号缓存；不能凭本地缓存推断会话仍有效。
- 新鲜列表必须来自成功的鉴权请求且仍在有效期内。复用列表版本时，validatedAt 使用该列表请求发起时记录的客户端时间（不是响应到达或 UI 渲染时间），不能按每次打开笔记的时间不断延期。
- 列表版本低于缓存时视为列表过时，不回退正文，也不将其作为验证依据；重新校验。
- 详情 200/304 和正常笔记列表响应须携带统一的详情表示格式标识响应头（例如 X-Note-Representation-Version），由共享常量定义。它描述接口格式，不是列表版本号，不随笔记写入递增，也不写数据库。仅当列表响应标识、客户端支持标识和缓存标识三者相同时，才允许用列表条目的 revision 延长详情校验期。缺少标识的旧服务端响应不得走此优化。
- 每次应用启动或账号重新激活后，每篇笔记首次使用持久缓存都必须进行一次无条件 GET 详情，不能仅用列表 revision 或 304 解锁。可先只读展示缓存，再用该响应建立本次运行的可信基线。通过运行内的已确认集合记录，不将该状态持久化；后续访问才使用列表版本复用、60 秒有效期和条件请求。这样跨启动缓存主要改善首屏展示，减少正文请求的收益主要发生在同次运行的重复访问。
- validatedAt 对详情 200/304 同样取请求发起时间。响应耗时超过 60 秒、系统时间回退或时间戳异常时视为过期，不循环自动请求，等待下一次校验触发。运行期间可使用单调时钟判断有效期。
- 每次访问不会刷新 validatedAt。内存、持久缓存与 Query 的 staleTime/失效规则保持一致，避免同一次打开重复校验。
- Query 的 dataUpdatedAt 不得以 IndexedDB 载入时间重置新鲜度；默认 refetch 行为需接入同一校验入口。明确失效、已知更高 revision、不可访问及正在硬删除的状态优先于 60 秒有效期。
- 已知会话到期时不得以缓存命中绕过身份确认；收到 401 沿用全局锁定，缓存有效期不是会话有效期，也不保证立即检测远程撤销。
- 同一账号、笔记的并发读取合并；账号切换或页面取消后，旧响应不得更新新账号界面或缓存。
- 已打开笔记在窗口重新获得焦点、网络恢复或再次访问时，若过期则校验；隐藏页面不主动校验。没有定时轮询，因此持续停留且没有校验触发时，不保证 60 秒内发现其他设备修改。

## 4. V11-03 条件请求（P0）

复用 GET /api/notes/:id，增加 ETag 和 If-None-Match 支持。

- ETag 对应用户、笔记、revision 及详情表示格式版本；表示格式发生不兼容变化时必须失配，不能只考虑正文 revision。
- 服务端先完成会话和用户归属校验，再检查条件头，不允许匿名或越权获得 304。
- 缓存原样保存响应 ETag，GET 条件头按 HTTP 契约处理；不能把单篇 revision、内容 schema 和表示格式版本混为一谈。
- 版本一致返回 304，无正文，并携带当前 ETag 和 Cache-Control；版本变化返回 200、完整 NoteDetail 和新 ETag。
- 条件请求可先读轻量版本元数据；若相同则以该查询时刻为验证点返回 304。若不同，则按原有权限条件读取完整详情，并从实际返回的那一行生成 ETag，不能沿用第一次查询的版本。无条件请求直接读完整详情，避免额外一次元数据查询。
- 轻量查询必须包含与现有 getNote 一致的 user_id、purge_pending 等可见性条件，不能只查 revision。软删除笔记按现有回收站语义返回并限制编辑，不一律当作 404。
- 客户端在通用错误和 JSON 解析之前处理 304；仅在持有对应有效缓存时发送条件头。若缓存因容量淘汰而丢失，304 后最多回退一次无条件获取；若账号已变化、主动清理、关闭缓存或退出，则丢弃旧请求，不自动重填缓存。304 仅确认本次请求携带的 ETag 所对应副本，不得给并发写入的新副本刷新 validatedAt。
- 维持敏感 API 的 Cache-Control: no-store；这是应用显式管理的 IndexedDB 缓存，不开放共享 HTTP 缓存。
- 返回 401 时执行现有身份锁定流程；404 时移除对应缓存并提示不可访问；不能使用旧缓存掩盖鉴权或删除结果。
- 304 仍经过账号代次与请求取消检查，并在前台真实交互条件满足时接入既有成功业务请求的会话续期逻辑；缓存命中、后台校验不单独增加续期心跳，不能为缓存改变 7 天会话及小时节流规则。
- 304 减少正文传输量，但仍产生请求和服务端版本查询。列表版本复用及 60 秒有效期负责减少请求次数。
- 所有会改变 NoteDetail 的写入必须纳入 revision 变更契约，包括标题、正文、文件夹、星标、置顶、删除状态及历史恢复。实施前审核现有路径，不以 updatedAt 弥补漏增版本。

## 5. V11-04 缓存、草稿与界面更新（P0）

缓存是可淘汰的服务器副本；草稿是尚未同步的用户修改。两者使用独立存储，不混用清理与覆盖规则。

- 成功获取详情、保存、元数据更新或历史恢复后，以服务端返回的完整详情更新缓存；以 note.revision 为准，不把幂等回执 applied_revision 当作返回详情的版本。写响应未携带 ETag 时存空值，下一次必要校验无条件获取，不拼装 ETag。
- 同一记录写入在 IndexedDB 事务内比较 revision；低版本不能覆盖高版本，旧校验响应不能给更新内容错误地延长有效期。
- 正在保存、正在组合输入或存在未同步草稿时，不用缓存/后台响应直接重建编辑器。
- 服务器版本变化且无未保存修改时，安全更新详情、内存和磁盘缓存；尽量保持滚动位置。
- 存在未同步修改时，保留草稿并沿用原有 baseRevision、revision 乐观锁及冲突流程。不能用缓存版本替换草稿基线，也不能自动覆盖较新 editSequence。
- 只读校验门槛仅适用于新打开的笔记，不能因为 60 秒过去或后台请求失败就把正在编辑的笔记强制只读。现有用户只读偏好、移动端默认只读和回收站状态优先；校验成功只解除临时校验门槛，不自动开启编辑。
- 新打开的过期缓存可先只读展示，标记“正在检查更新”，校验成功后再允许编辑；网络失败显示“本地副本，暂未确认最新”。既有草稿恢复流程保持有效，不增加通用离线编辑能力。
- 缓存状态与“已存本机草稿”“已保存到服务器”分开表达；展示缓存不等于完成保存或确认服务器最新。
- 返回 404 或硬删除状态时删除服务器副本缓存并停止该笔记保存重试，但保留未同步草稿供现有恢复/导出流程处理，不能把它重新写回已删除笔记。从列表分页中没有看到某条笔记，不能据此推断删除。
- 手动刷新和强制校验不得丢失未保存内容。所有新增提示支持简体中文与 English。

## 6. V11-05 失效、账号隔离与跨标签页（P0）

- 收藏、置顶、移动、软删除、恢复和版本恢复成功后同步更新详情缓存，并失效相关列表。硬删除确认或服务器返回不可访问后删除缓存。
- 删除和清理须阻止在途旧请求重新写回缓存，必须在 IndexedDB 中维护账号清理代次，并在写入事务内校验，单条笔记另有失效保护；内存检查和广播仅作加速，不能替代持久化写入屏障；不能只有一次 delete 操作。
- 多标签页通过 BroadcastChannel 广播账号 ID、笔记 ID 和版本/失效通知，不广播正文或凭据。接收后按需校验，不能仅凭广播内容认定服务端已确认。
- 切换账号立即清空旧账号界面和内存；旧账号持久缓存可保留于独立命名空间，只在重新确认该账号身份后读取。
- 主动退出清理本浏览器本次退出所涉及账号的正文缓存；移除记住账号时清理该账号缓存。未同步草稿按原退出保护流程处理，不纳入缓存清理。
- BroadcastChannel 不可用时仍须在焦点恢复、账号激活和读写前检查本地清理代次，保持跨标签页清理有效；不要求凭广播自动拉取全部笔记。
- 退出或会话失效时，即使磁盘清理失败也完成身份锁定、取消请求和内存隔离。用户手动清理/关闭缓存失败时不退出登录、不锁定编辑器，仅停用该账号持久缓存并提示清理未完成。可用的偏好存储仅记录不含正文的待清理标记；存储全部不可用时，不承诺跨重启记住补清理任务，后续仍受每篇首次无条件验证保护。不能将失败报告为已删除成功。
- 会话失效立即隐藏正文、取消请求并锁定身份；缓存不得成为继续访问数据的凭据。
- 本地缓存不是加密保险箱，受当前浏览器配置和设备访问权限约束；不缓存密码、会话 Cookie、CSRF 或其他认证凭据。

## 7. V11-06 设置与手动清理（P0，随缓存一同交付）

设置新增“笔记本地缓存”，提供开启/关闭和“清理笔记缓存”，作用于当前账号。

- 关闭时停止正文持久缓存读写并清理已有正文缓存；正常请求合并和内存查询机制继续工作。
- 清理时失效当前账号详情内存缓存的可信状态并阻止旧请求回写；正在编辑的文档和草稿保持不动，清理动作本身不立即重新下载。下次打开重新请求；不能删除服务器笔记、未同步草稿、最近打开记录或阅读位置。
- 明确提示清理范围及结果，清理失败可重试。阻止在途请求将旧缓存重新写回。
- 首版不建设缓存管理列表、自动下载全部笔记或复杂容量仪表盘。

## 8. 恢复与版本异常

- 现有运维恢复仅支持空目标，继续保留会话清理且不恢复旧会话；不扩展为在线回滚工具，不引入服务器恢复版本号。
- 恢复后登录或应用重启，每篇持久缓存的首次无条件 GET 取得完整权威内容，因此即使 revision 相同而正文不同，也不会仅凭旧 ETag/列表版本解锁编辑。不能依赖所有用户手动清缓存来保证正确性。
- 正常请求继续遵循版本不回退。首次权威读取或异常修复的强制无条件读取需要先建立单篇读取屏障、取消旧读取，并检查账号代次、清理代次及读取期间是否有新写入；只有无较新确认写入时，才可用其完整响应重建缓存基线。响应不是因为“最后到达”就自动更权威。
- 首次读取遇到较低 revision 或同 revision 不同正文时，替换服务器副本缓存；若有未同步草稿，保留草稿并标记基线不可信，禁止自动提交或仅因 revision 相同就视为可安全重放。由既有冲突/导出流程让用户保留修改。
- 正常运行发现服务端版本异常降低时，停止该笔记自动提交，进行一次强制无条件验证。异常仍无法确认时提示重开笔记或重新登录，避免循环请求。
- 原有页面在服务端恢复后尚未发请求时可能短暂展示缓存；下一次鉴权/校验负责锁定失效身份。这是无推送方案的限制，不承诺恢复瞬间清除所有设备屏幕上的数据。

## 9. 实施顺序

1. 审核详情所有字段的 revision 契约，完成条件请求与鉴权测试。
2. 建立独立 IndexedDB 缓存模块，实现版本比较、容量淘汰、异常降级和账号隔离。
3. 接入详情查询，复用新鲜列表版本；统一 Query 与持久缓存有效期及请求合并。
4. 接入保存确认、删除/恢复、草稿冲突、跨标签页失效和退出清理。
5. 完成双语状态提示、设置与缓存清理，再进行浏览器验收。

## 10. 验收清单

- 无缓存首次打开仅获取一次详情；有效期内重复打开不发送详情请求。
- 新鲜列表与缓存版本一致时不发送详情请求，过期列表不能无限延长缓存寿命。
- 版本未变的条件请求返回 304 且不传正文；变更返回完整最新详情。
- 其他设备修改可在下一次有效校验中发现；手动刷新绕过有效期。
- 旧响应、跨标签页并发写入和迟到的保存回执不回退缓存版本。
- 服务端变更与本地草稿同时存在时进入既有冲突流程；真实 IME 输入不能被后台缓存更新打断。
- 删除、清理和退出后，在途请求不会复活缓存；切换账号不泄露另一账号正文。
- 匿名、过期会话和越权条件请求不能获得 304 或笔记数据。
- 缓存清理、格式升级、配额不足、IndexedDB 禁用和损坏均不丢失草稿、不影响服务器数据。
- 浏览器刷新后可只读展示持久缓存，但每篇首次无条件详情校验之前不能仅凭旧 revision 解锁；同次运行后续访问验证请求减少。过期缓存校验期间和网络失败时状态明确。
- 原有保存、历史恢复、搜索、附件展示、最近打开和阅读位置无回归。
- 单元测试覆盖容量/版本/失效规则；Workers 集成测试覆盖条件请求、鉴权与并发；浏览器测试核对真实请求次数、保存冲突与多账号切换。
- 验证慢响应、系统时钟回退、缓存格式升级、无 ETag 写回、304 与并发更新交错、清理期间请求完成、BroadcastChannel 缺失等边界。
- 验证后台校验不强制退出编辑，不覆盖移动端只读偏好；304 与缓存命中的会话续期行为符合原有规则。
- 验证恢复后低版本和同版本不同正文的首次完整校验；旧读取晚到不能覆盖新写入，草稿基线不可信时禁止自动重放。
- 验证新旧前后端表示格式标识不匹配时跳过列表复用；无条件详情获取不额外查询版本。
- 验证手动清理失败不会退出账号，退出时清理失败也不会继续展示正文。
- Safari/iOS、真实 IME 与真实跨设备人工测试单独记录，不以浏览器模拟替代。

## 11. 交付边界

本次范围确认：v11 仅聚焦单篇笔记详情缓存。暂不实施笔记本目录或笔记列表持久缓存、列表 ETag、账号级或笔记本级列表版本号，不为缓存增加数据库写入或迁移。文中“列表版本”均指现有列表条目携带的单篇笔记 revision；仅在正常列表查询已取得这些信息时复用，不为正文缓存额外请求列表。列表继续沿用现有 TanStack Query 查询机制。

本方案不承诺零请求实时同步或可靠离线编辑。60 秒有效期允许短暂使用已验证副本；跨设备变化的实际可见延迟还取决于焦点、导航及手动刷新等校验触发。现有服务端乐观锁继续作为写入一致性的最终保障。
