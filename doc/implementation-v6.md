> 日期：2026-10-27。当前状态：本地已切换 v6，补充验收见 §9；§1–7 是阶段历史。开发模式同步时序及生产/人工验收仍有未关闭项，不能视为完整生产交付。

## 1. 密码派生门槛

按 `plan_v6.md` §5.2、§11，先验证原生 PBKDF2-HMAC-SHA-256。初次采用 OWASP 当前建议的 600,000 次迭代作为评估基线；该次数是安全设计选择，不是原需求中已给出的数字。用户随后明确要求调整为 10,000 次，当前实现基线以该决定为准，初次测试作为历史记录保留。

- [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) 对 PBKDF2-HMAC-SHA-256 建议 600,000 次。
- Cloudflare 官方仓库的 [workerd #1346](https://github.com/cloudflare/workerd/issues/1346) 记录迭代上限问题，[提高上限的 PR #7550](https://github.com/cloudflare/workerd/pull/7550) 在本次核对时尚未合并。以下结论以实际远程验证为主要证据，不只依据该讨论。

## 2. 实测结果

工具版本：Wrangler 4.152.0、本地 workerd 1.20261019.1；compatibility date 为项目当前的 `2026-10-23`。使用固定的非用户测试字符串和随机 16 字节盐，派生 256 位结果；不使用真实密码、不输出派生结果。

| 环境 | 100,000 次 | 600,000 次 |
| --- | --- | --- |
| 本地 Vitest / workerd | 成功 | 成功 |
| Cloudflare 远程预览运行时 | 成功 | 拒绝：`Pbkdf2 failed: iteration counts above 100000 are not supported (requested 600000).` |

远程测试 HTTP 返回 200，报告中 600,000 次派生失败，因此不是网络故障推断。首次通过本地代理转发远程预览的请求超时，后改用 Node 的代理感知请求访问预览，才取得上述结果。预览输出的计时值为 0，不作为实际 CPU 或登录耗时基准。

### 用户调整后的复测（2026-10-27）

- 10,000 次：本地 workerd 专项通过，Cloudflare 远程预览返回 `supported: true`，检测脚本退出码为 0，预览已关闭。
- `npm run typecheck` 与文档/差异格式检查通过；没有新增依赖或修改线上配置。
- 此结果仅解除该参数的运行时兼容性阻断，不代表登录耗时基准、多用户功能或完整安全验收已完成。

# 使用当前已登录的 Wrangler 账号；不绑定 DB/R2，不替换线上版本

如环境需要代理，使用本机已有 `HTTPS_PROXY` 配置，不在代码中硬编码地址。远程脚本只使用临时预览凭据，不打印或持久化凭据；结束时关闭预览。当前脚本检查用户批准的 10,000 次，运行时不支持时退出码为 1；不能将本地测试的成功视为远程门槛通过。

配套文件：`scripts/password-runtime.worker.ts`、`scripts/password-runtime.wrangler.jsonc`。配置不包含业务 bindings、Secrets 或生产域名路由；没有执行部署、迁移、admin 初始化或线上数据操作。

## 5. 账号服务层基础（2026-10-27）

本阶段只增加内部服务与测试，不开放新的 HTTP 接口。原 API_TOKEN 鉴权继续生效，不能把内部服务测试通过描述成已经支持多用户登录。

### 已实现

- `shared/account.ts`：前后端可复用的严格 Zod 输入契约；ASCII 邮箱规范化、NFC 用户名、码点长度、密码原样处理、确认密码及保留 admin 名称。拒绝额外的 `user_id` 等字段。
- `worker/lib/password.ts`：原生 PBKDF2-SHA-256、10,000 次默认成本、随机独立盐和版本化记录；验证使用记录内成本，未知邮箱执行虚拟密码派生。此成本的安全取舍沿用 §1–2。
- 追加 `0007_account_foundation.sql`：用户唯一约束、100 人插入触发器、稳定默认账号标记、可撤销会话，以及原子写入会话检查触发器。
- 追加 `0008_account_folders.sql`：文件夹可携带用户归属，默认文件夹和名称唯一性按用户范围约束；NULL 仅保留旧数据待受控迁移的状态，不代表授权给任何用户。
- `worker/services/accounts.ts`：内部注册与默认 Notes 原子创建、邮箱密码验证、修改用户名、当前密码验证、修改邮箱/密码及撤销全部会话。注册默认关闭且要求初始化完成标记；并发唯一性与容量由数据库兜底。
- `worker/services/accountSessions.ts`：随机凭据加签名，数据库仅存凭据摘要；默认 24 小时、最大 30 天，凭据版本 CAS 签发、撤销及分批过期清理。`sessionWriteBatch` 将有效会话/维护状态检查与写入放进同一 D1 batch，失败回滚整批。该方法不替代每条业务 SQL 的所有者条件。
- Workers 测试覆盖 Unicode/格式、哈希成本、随机盐、伪造会话、密钥轮换、到期、撤销后写入、维护冻结、batch 回滚、账号变更、并发注册/密码修改、默认文件夹失败回滚和 100 人边界。

## 6. 归属约束与初始化事务（2026-10-27）

- 追加 `0009_ownership_foundation.sql`：笔记、操作回执、维护任务增加 `user_id`；所有者不可被改写；笔记的当前/原文件夹必须同属一个用户；初始化完成后禁止缺省所有者。版本与附件通过受约束父笔记归属，引用必须指向同一笔记的附件和版本。
- `initializeDefaultAccount` 是部署专用服务，不暴露 HTTP 路由。在同一 D1 batch 中检查冻结标识及排空状态、创建默认账号/稳定标记、仅回填 NULL 所有者、复用默认 Notes、验证全图归属、撤销会话。任一失败整批回滚；完成后仍保持冻结，不自行切换鉴权或解除维护。
- 已有稳定默认账号标记时按 id 重试，不改邮箱、显示名或密码；发现未标记的同名账号则拒绝认领。既有明确所有者保持不变，无法证明归属的交叉关联阻断初始化。
- `assertOwnedResource` 为笔记、文件夹、版本、附件、操作回执和任务提供统一 404 授权预检，admin 无越权特例。当前尚未接入旧业务路由；预检不能替代最终写入 SQL 的所有者条件。
- 新增只读本地预检命令：`npm run account:check -- --email admin@admin.com`。通过 Wrangler 的本地 bindings 读取状态，显式禁用远程 bindings，不接受命令行密码、不打印凭据，不执行迁移/初始化/解除冻结。

## 7. 业务隔离与暂存 HTTP 入口（2026-10-27）

### 已实现

- 文件夹、笔记详情/列表/计数/搜索、历史版本、保存、恢复及导入的业务路径传递会话身份；列表在 SQL 排序分页前限定所有者。默认文件夹按用户查找，同名文件夹可跨用户存在。

- **尚未将新入口设为 `worker/index.ts` 的运行入口**。这不是同时公开两套鉴权；当前本地/线上仍使用旧入口，新入口仅被隔离 Workers 测试调用。前端身份隔离及运维替代完成后才允许一次性切换。
