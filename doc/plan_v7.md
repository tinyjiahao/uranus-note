## 1. 目标与边界

- 修复中文/日文等 IME 组合输入被强制中断的问题，并消除同类"无关渲染干扰编辑器"的结构性原因。
- 降低高频笔记打开成本：附件图片走浏览器 HTTP 缓存并懒加载。
- 建立数据可迁移能力：单篇 Markdown 导出、打印输出干净、可带附件整体导出。
- 扩展内容能力：以行内标签 chip 为首个新节点，借此完成版本号常量收敛与 schema 升级流程；其后是文件附件与笔记互链。
- 本版不实现：多光标协同、CRDT/OT 合并、服务端全文分词检索（FTS 虚表继续禁用，沿用字面子串搜索）、公开分享链接、端到端加密、AI 功能、任意类型附件（仅白名单扩展）、Callout/分栏/数学公式/网页嵌入等低频块类型、笔记级标签/筛选系统。
- 已明确排除：`/` 斜杠菜单（plan_v5 的决定继续有效：`/` 及 `/table`、`/code` 等均作为普通文本，不做键盘拦截，块插入使用工具栏入口）；请求体 gzip 压缩（实测 PATCH 慢在服务端而非上传体积，收益仅几十毫秒，且有 keepalive 退出提交与边缘透传风险）。
- 不改变既有保存协议、幂等、revision 乐观锁、草稿与冲突语义。

### 1.1 菜单入口补充（2026-10-27）

- 设置、切换主题和退出从左下角移至右上角三个点菜单，移除原侧栏底部按钮和悬浮设置按钮；保留原有设置、主题偏好及保存后退出流程，不绕过服务器退出确认。
- 未选中笔记（含空列表）时也提供右上角菜单；选中笔记时与标题栏“笔记更多”菜单合并，用分隔线区分全局操作。笔记列表行菜单/右键菜单仍仅包含笔记操作。
- 三栏、双栏、专注及窄屏均能访问；设置关闭后焦点返回右上角入口，Esc 关闭菜单也返回触发按钮。只读笔记不影响全局设置和退出功能。

### 1.2 多账号登录补充（2026-10-27，用户确认）

- 右上角三个点菜单增加“切换账号”，使用与设置一致的右侧模态抽屉，窄屏适配全宽。上方以账号卡片显示已登录账号、当前账号标记和各自到期时间，当前账号保持清晰可读；下方为左对齐、等宽输入框的邮箱/密码表单，提供显示密码和主色“登录并切换”按钮。支持关闭按钮、Esc 与关闭后焦点返回入口，操作进行中禁止关闭。首次添加账号输入邮箱密码，后续有效期内一键切换，无需重复输入密码。最多记住 5 个账号，可移除非当前账号，移除不删除笔记。
- 每个账号自密码登录起固定 24 小时，刷新、重开浏览器和账号切换均不延长期限；过期、撤销、禁用或凭据版本改变后必须重新登录。活动会话失效时，登录页也可选择尚未过期的已登录账号。
- 不保存密码；已签名随机凭据仅放 HttpOnly Cookie，生产启用 Secure、SameSite=Strict、Path=/，不设 Domain。记住账号不是本地用户 id 白名单，切换时仍逐一验证 D1 会话与凭据版本，校验 Origin 和账号集合专属 CSRF，不向页面返回会话凭据。
- 切换前沿用未同步内容的保存/放弃/取消确认；取消请求和保存队列、清空旧账号查询缓存与敏感页面，草稿仍按 user_id 隔离。其他标签页同步锁定并重查身份；由于同源 Cookie 共享，不支持各标签页同时保持不同活动账号。
- 切换响应丢失或失败时锁定编辑，并提供“重新确认账号”；不得假设 Cookie 未改变后直接继续写入旧账号。
- “退出”撤销本浏览器记住的全部账号会话并清 Cookie，其他设备会话不受影响；“移除”仅撤销指定非当前账号在本浏览器的凭据。仅在信任设备启用，已缓存附件仍遵循 §4 的既有风险说明。
- 复用现有 D1 会话表、签名、限流与用户隔离，不新增依赖、迁移或云资源；不建设设备管理面板。

### 1.3 注册其他账号与入口说明（2026-10-28）

- 注册入口在未登录页面：点击“注册账号”，填写邮箱、用户名、密码及确认密码，提交成功后再登录；沿用 v6 的输入校验、唯一约束和单实例 100 人上限，不新增邮箱验证或密码找回功能。
- 注册按钮仅在服务端返回 `registrationEnabled=true` 时显示；部署者通过 `REGISTRATION_ENABLED=true` 开启注册。入口未显示时不表示账号切换故障，不由前端绕过注册开关。
- 切换账号抽屉下方的“登录其他账号”只登录已有账号，不直接创建账号。添加成功后才进入上方已登录账号列表，并按 §1.2 保持 24 小时有效期。
- 当前登录状态下直接访问 `/login` 会返回工作区。注册新账号可先退出再进入登录页，但“退出”会撤销本浏览器记住的全部账号会话；若希望保留当前登录，可在独立无痕窗口或其他浏览器打开应用注册，再回到原窗口通过“切换账号”添加该账号。
- 无痕窗口与原窗口不共享登录 Cookie；在无痕窗口完成注册/登录，不会自动把账号加入原窗口的已登录列表。使用结束后关闭无痕窗口。
- 本节记录现有行为与操作路径，不表示新增“抽屉内注册”入口，也不更改注册安全约束。

## 3. IME 组合输入与渲染路径（V7-01、V7-02）

### 3.1 现状判断（假设，须先验证）

- 现象：拼音输入中途停顿后，已输入的拉丁字母残段与已上屏汉字一并提交（例如期望"正常"，得到 `zheng长`）。
- 高度可疑的原因（尚未实测证实，不得当作已确认根因）：
  1. `useEditor` 的 `editorProps` 及事件回调每次渲染生成新对象；`useEditor` 在重渲染时发现 options 变化会调用 `editor.setOptions`，其内部 `view.setProps/updateState` 可能在 composition 期间触发 DOM 观察器 flush，强制提交输入法残段。
  2. 重渲染来源：每次 `onUpdate → onChange → enqueue → report → setSaveStatus/setSaveInfo` 驱动 Workspace→NoteEditor 重渲染；此外 800ms 草稿防抖、3s 强制落盘、同步完成回调的 `report` 在用户停顿时仍会触发，与"停顿后出问题"的现象吻合。
  3. 标题受控 `textarea` 在组合期间遇到无关渲染时，受控值回写可能覆盖组合文本。
  4. 其他候选（需排除）：`onBlur`/`onPersistLocal` 路径、`setEditable`/`closePopups`、查找高亮 `dispatch`、React StrictMode 开发期双渲染。

### 3.2 V7-01 要求（先复现、再修复）

- 先建立自动化复现：Playwright（Chromium）使用 CDP `Input.imeSetComposition`/`Input.insertText` 模拟"组合中途停顿 1–3 秒并触发保存状态变更"，在修复前稳定失败。若无法自动化复现，须在真机 IME 上记录复现步骤与浏览器版本。
- 复现后用最小修改逐一验证上面的候选原因，记录哪一项使问题消失；若 3.3 的修改不足以消除问题，继续沿 `domObserver` flush 的调用栈追查，不以"已做 memo"宣称修复。
- 正文编辑器与标题输入框都须覆盖。

### 3.3 V7-02 要求（结构性解耦）

- `useEditor` 的 options（`editorProps`、`onUpdate`、`onBlur` 等）保持引用稳定：使用 `useMemo`/`useCallback` 或模块常量，回调通过 ref 读取最新的 `note`/`onChange`/`readOnly`。
- 保存状态（`dirty/saving/saved/error/conflict`、`SaveInfo`、上传状态）不再通过 Workspace 的 `useState` 驱动整树渲染：改为 `NoteSaveQueue` 外部订阅（如 `useSyncExternalStore` 或现有 Zustand store），仅保存状态指示组件、重试横幅订阅。现有标题旁状态文案与"本机已存/服务器已确认"的区分语义保持不变。
- `queueFor` 内的 `updateRevision`/`setSyncInterval` 副作用移出渲染阶段（移入 effect 或队列创建/更新回调）。
- 所有会 `view.dispatch`/`setProps`/`setEditable` 的非用户输入路径（查找高亮刷新、只读切换、表格手柄布局等）在 `editor.view.composing` 为真时延后到 `compositionend`。
- 验收：渲染计数用例证明打字及保存状态流转期间 `NoteEditor` 不重渲染；保存、草稿落盘、冲突、重试行为与 v5/v6 回归一致。

## 4. 附件图片缓存与懒加载（V7-03）

### 4.1 背景与决策

- 现状：`GET /api/attachments/:id` 返回 `Cache-Control: private, no-cache` + ETag/304。浏览器每次使用图片前仍须发条件请求，每次经 Worker 并查询 D1 做归属校验，图多时开销在往返次数而非字节。
- 不采用 localStorage 缓存图片：容量约 5MB、base64 膨胀、同步 API 阻塞主线程（会加重 V7-01 的输入问题），且违反"localStorage 只存 UI 偏好"的约定。图片缓存交由浏览器 HTTP 缓存管理。
- 附件 id 为随机值，上传后字节不可变，没有修改附件内容的接口，因此可长期缓存。
- 浏览器缓存容量与清理由浏览器决定（空间淘汰、用户清理、隐私设置），`max-age` 不是保留保证；缓存缺失只会回退到当前行为，无需特殊处理。

### 4.2 要求

- 附件下载 200 响应改为 `Cache-Control: private, max-age=31536000, immutable`，保留 `ETag`、`Content-Type`、`X-Content-Type-Options: nosniff`；必须保持 `private`，不得进入共享缓存。
- 304 响应使用相同的 `Cache-Control`；缓存未命中或用户强制刷新时，仍先鉴权再比对 If-None-Match，校验顺序不变。
- 其他 `/api/*`（笔记详情、列表、会话等）继续 `no-store`，不扩大缓存范围。非图片附件（V7-10）同样适用该头，下载仍为 attachment。
- 编辑器图片 NodeView 的 `<img>` 增加 `loading="lazy"` 与 `decoding="async"`，保持宽度、对齐、调整手柄行为；打印时按 5.2 强制加载。若懒加载造成明显的布局跳动，可只对首屏之后的图片启用，具体取舍记录在实施说明中。
- 跨笔记复制图片生成目标专属附件（新 id），不受缓存影响。

### 4.3 已接受的风险（个人自用场景已确认）

- 强缓存命中时不再经过服务端鉴权：同一浏览器内退出登录后，已缓存图片仍可能被本机读取。个人单用户场景接受，不增加 `Clear-Site-Data` 等清理机制（该响应头会清空整站缓存，副作用大于收益）。
- 附件被删除或不再被引用后，本机缓存副本保留至浏览器淘汰；对用户不可见，无功能影响。
- 此项是对 plan_v1 附件下载缓存策略（`no-cache` 校验）的显式变更，以本节为准；"条件下载与 Range 不得绕过鉴权"对未命中缓存的请求继续有效。

### 4.4 验收

- 集成测试：下载响应头为 `private, max-age=31536000, immutable`；ETag 与 304 流程保持；未登录、越权下载仍被拒绝。
- 浏览器验证：打开含多图笔记，二次打开时 DevTools Network 显示图片来自缓存，无逐图请求；离屏图片滚动接近视口才开始加载；打印预览中所有图片可见。
- 回归：图片调整宽度、对齐、跨笔记复制粘贴、删除附件不受影响。

## 5. 导出与打印（V7-04、V7-05）

### 5.1 单篇 Markdown 导出（V7-04）

- 在客户端用本地 Blob 下载生成，不新增服务端路由；文件名 `笔记标题.md`，消毒非法字符并限长，标题为空使用 `uranus-note-{id}`。入口放在笔记菜单/设置；格式工具栏按 §20.1 整理。
- 序列化规则：
  - 首块标题投影写作 `# 标题`；段落、标题（#）、有序/无序列表、`- [ ]`/`- [x]`、引用、水平线、硬换行、代码块（带语言）直接映射。
  - mark：加粗 `**`、斜体 `*`、删除线 `~~`、行内代码、链接直接映射；下划线、高亮、小号文本无 Markdown 等价，保留文字并丢弃样式；对齐、表格列宽、图片宽度/对齐一律丢弃。
  - 表格→GFM 表格：无表头行时生成空表头行；单元格内多段/列表降级为以 `<br>` 连接的纯文本，转义 `|`；文件附件例外，保留 `[文件名](attachments/文件名)` 相对链接，不只输出文件名。
  - 图片→`![alt](attachments/文件名)`；文件名重名时追加 id 后缀。单独导出 .md 时该相对路径不会带有图片文件，须在导出提示中说明，完整离线可用见 V7-09。
  - 后续新增节点的降级规则（须随各节点需求一并落地，不得缺省为丢内容）：标签 chip→`[文字]`；笔记链接→`[[标题]]`；文件附件→`[文件名](attachments/文件名)`。
- 不承诺 Markdown 往返无损；导出是可迁移性能力，与现有 Markdown 导入互不要求逆向一致。
- 验收：快照单测覆盖每种节点/mark 的降级规则、含特殊字符的标题与单元格、空笔记。

### 5.2 打印样式（V7-05）

- `@media print`：隐藏侧栏、笔记列表、工具栏、状态/横幅、按钮、弹层、表格手柄与行号；正文取消最大宽度，浅色配色，保留表格边框、链接可见、标题在最前；表格与图片避免跨页断开。
- 与 V7-03 的交互：图片 `loading="lazy"` 会导致离屏图片在打印中缺失。须在 `beforeprint` 将正文图片改为 eager 并等待加载完成（`afterprint` 恢复），或在打印态强制 `loading="eager"`。
- 浏览器"打印为 PDF"作为 PDF 导出途径，不另建服务端渲染。
- 验收：人工截图验收（含多图、表格、长笔记分页、深色主题下打印为浅色）。

## 7. 行内标签 chip（V7-07，content schema 6）

### 文本颜色补充（content schema 11）

- 原高亮入口改为同一颜色弹层，包含 30 种文本颜色、10 种突出显示颜色，色块不显示颜色名，读屏保留名称；支持独立恢复默认文本颜色和清除突出显示。工具栏采用圆角方框“A”图标，点击后弹层锚定按钮下方，不跟随正文选区；随工具栏滚动/窗口变化重新定位，空间不足时避让，窄屏复用底部面板。完整工具栏分组见 §20.1。
- `textColor` mark 与 `highlight.attrs.color` 使用 `shared/textColors.ts` 固定色值白名单，schema 11 起可写；兼容读取 1–10 的无颜色高亮。复制、历史与保存保留两种颜色；Markdown/ZIP 中的 Markdown 降级为保留文字，颜色不导出。
- 沿用 0010 的范围约束，无新增数据库迁移。产生 schema 11 内容后禁止回滚不支持该版本的 Worker。

### 7.1 数据模型

- 标签外观采用紧凑彩色底纹与边框；编辑弹层提供两行五列的十种预设色块（灰、蓝、青、绿、浅绿、黄、橙、红、粉、紫），不显示颜色名，选中色块显示勾选标记；颜色名仅作为读屏名称。沿用现有颜色 key，红色对应 `rose`，无需新增 schema 或迁移。
- 新增 inline atom 节点 `label`：attrs `{ text: string, color: string }`；`text` 为 NFC 规范化后 1–50 个码点、不含控制字符/换行；`color` 为固定白名单 key（`gray/blue/cyan/green/lime/yellow/amber/pink/rose/purple`），不存色值，由 CSS 变量映射并适配深浅主题。
- 允许位置：正文段落、标题块之外的正文标题、列表项/待办项/引用内的段落、表格单元格内的段落；禁止出现在 `codeBlock` 内；节点不得含子节点和 marks。笔记顶部"标题投影"仅支持纯文本，不允许含 label（沿用 `splitNoteTitle` 对非纯文本首块不做标题投影的现有规则，须有回归用例）。
- `walk()`：label 的 `text` 计入 `plainText`、规范化搜索文本、`snippet` 与 `charCount`，同时受 `MAX_SEARCH_BYTES`/`MAX_CONTENT_BYTES`/`MAX_NODES` 现有预算约束；不产生附件引用。

### 7.2 版本与迁移

- 新增 schema 版本 6：`CURRENT_SCHEMA_VERSION` 升为 6，`SUPPORTED_SCHEMA_VERSIONS` 增加 6；服务端新写入按 `Math.max(2, …)` 规则沿用；旧客户端读取/覆盖 schema 6 内容按既有 `CLIENT_UPDATE_REQUIRED`/`UNSUPPORTED_CONTENT_SCHEMA` 规则拒绝。
- 现有 `content_schema_version` 列带 `CHECK(... IN (1,2,3,4,5))`，SQLite 无法原地修改；沿用 0006 的"重命名旧列 + 新增列 + 回填"模式追加 `0010_*.sql`（`uranus_notes` 与 `uranus_note_versions` 两张表）。新列的 CHECK 放宽为范围约束（如 `BETWEEN 1 AND 99`），具体取值合法性由应用层 `SUPPORTED_SCHEMA_VERSIONS` 把关，使后续新增节点版本不再需要重建列。

## 8. iOS 显示适配与安装指引（V7-08，P1）

### 8.1 背景

v4 安装体验只验收了 macOS Chrome；当前在 iOS Safari 上存在已确认问题：`env(safe-area-inset-*)` 因 viewport 缺少 `viewport-fit=cover` 全部解析为 0；输入框字号小于 16px 导致聚焦时页面自动放大且不回缩；主布局 `height:100%` 未跟进 `dvh/svh`，地址栏伸缩时底部留白或被裁；"安装应用"按钮依赖 Chromium 专属的 `beforeinstallprompt`，iOS 上永不出现，且"如何安装"指引是桌面 Chrome 步骤，对 iOS 用户是错误引导。

### 8.2 要求

- **viewport**：`index.html` 的 viewport 增加 `viewport-fit=cover`；此后所有 `env(safe-area-inset-*)` 才真正生效，须复查刘海屏竖屏（底部弹层/设置按钮不被 Home 指示条遮挡）与横屏（侧边栏/内容不进刘海区，必要时为 `.sidebar`、工具栏补 `safe-area-inset-left/right`）。
- **输入防自动放大**：`@media (pointer: coarse)` 下 `input/textarea/select` 字号不低于 16px（标题 textarea、搜索框、查找栏、登录表单、弹层内输入均在范围内）；不允许用 `maximum-scale=1`/`user-scalable=no` 规避。
- **布局高度**：`.workspace`、`.login-shell` 等占满屏容器改用 `100dvh`（需要更稳的可用 `100svh`），替代 `height:100%` 链条；键盘弹起时编辑器与底部弹层行为依赖现有 `visualViewport` 逻辑（Popup 已实现），真机验证不被键盘盖住。
- **触控细节**：按钮与列表项去点按高亮（`-webkit-tap-highlight-color`）并 `touch-action: manipulation`；UI 控件区禁长按系统菜单（`-webkit-touch-callout: none` + `user-select: none`），但 `.prose-editor` 内不得禁用文本选择；`-webkit-text-size-adjust: 100%` 防横竖屏切换文字放大；编辑器滚动容器加 `overscroll-behavior: contain`。
- **独立模式 meta**：补 `apple-mobile-web-app-capable`/`mobile-web-app-capable`/`apple-mobile-web-app-status-bar-style`，与 manifest `display: standalone` 并存。
- **安装指引分流**：`InstallApp.tsx` 按平台出对应步骤——iOS 显示"分享 → 添加到主屏幕"，桌面 Chromium 保留现有 Chrome 步骤，其他桌面浏览器显示"不支持安装，可继续使用网页版"；`beforeinstallprompt` 按钮逻辑不变。

### 8.3 验收

- 真机 Safari 逐项验收：聚焦任意输入框页面不放大且收键盘后不回弹错位；刘海屏竖/横屏安全区正确；键盘弹起时底部弹层可见可用；长按工具栏不弹系统菜单；"添加到主屏幕"后独立窗口启动、无地址栏。
- 模拟器不能替代真机验收（自动缩放与安全区行为模拟器不可靠）；未完成真机验收不得宣称本项完成。
- 回归：桌面 Chrome 安装按钮、深色模式、三栏布局不受影响。

## 10. 白名单文件附件（V7-10，P2）

### 10.1 展示与交互补充

- 文件附件支持紧凑和卡片两种展示，默认紧凑；旧附件未设置样式时也显示紧凑。紧凑显示文件图标和可点击文件名，卡片增加边框、留白和文件大小。卡片宽度随内容收缩，最大 420px 且不超过编辑区宽度，不铺满整行。两种样式的文件名展示区最大 280px，窄屏进一步收缩；超出时单行省略号展示，悬停显示全名，完整文件名与下载名称不变。
- 点击附件选中并显示浮动操作栏，不直接下载；操作栏提供显式下载以及紧凑/卡片图标按钮，当前样式高亮，不再使用常驻下拉框。优先显示在附件上方，空间不足时避让，窄屏复用底部菜单，支持 Esc 和点击外部关闭。只读时仅提供下载，不允许切换样式。
- 每个附件独立切换样式，命令定位到当前附件节点，不依赖菜单取得焦点后的编辑器选区；变更支持保存、刷新、撤销和历史恢复。跨笔记复制保留样式，Markdown/ZIP 导出仍为普通文件链接。
- 开发热更新若保留不含 display 属性的旧编辑器，切换时须明确提示“先保存再刷新”，不能静默失败，也不自动刷新或重建以免影响未保存内容。该情形是已增加防护的可能原因，不代表已确认用户原页面的故障根因。
- `fileAttachment.attrs.display` 为可选 `compact | card`，显式属性使用 content schema 9，兼容读取 1–8，旧客户端不得覆盖 9。现有 0010 的 1–99 数据库范围无需再扩列，但上线前必须确认已应用该迁移并备份；不改写已发布迁移。
- 此补充只改变显示，不扩展上传格式或加入 PDF 预览；下载继续经过鉴权 API。
- 表格附件补充：表头和普通单元格允许插入文件附件，单元格内合法列表/引用也允许；内容使用 schema 10，兼容读取 1–9。前后端同步放开节点位置，保留矩形表格、元数据、归属和引用校验，不开放嵌套表格。紧凑/卡片、保存/刷新、历史恢复和跨笔记专属复制保持一致，Markdown/ZIP 表格内保留附件相对链接。沿用 0010 的数据库范围，无需新增迁移。

### 10.2 上传、数据与安全

- 允许类型：`application/pdf`、OOXML（docx/xlsx/pptx）、`application/zip`、`text/plain`、`text/markdown`、`text/csv`；白名单外格式拒绝上传。单文件上限沿用现有 `MAX_FILE_BYTES`（10,000,000 字节）与全局 `bodyLimit`（10.5MB），**不为本项放宽请求体上限**；分片上传不在本版范围。
- 校验：声明 MIME 必须在白名单内；魔数——PDF `%PDF`，OOXML/ZIP `PK\x03\x04`，文本类无 NUL 且为合法 UTF-8；扩展名与 MIME 的映射表扩充 `MIME_EXTENSIONS`；对象 key 仍由服务端生成，不使用用户文件名。
- 下载（对非图片附件）：一律 `Content-Disposition: attachment`，附 `X-Content-Type-Options: nosniff` 与 `Content-Security-Policy: default-src 'none'; sandbox`；`Content-Type` 使用已校验的白名单 MIME。PDF 暂不提供 inline 预览（`sandbox` CSP 会阻止 Chrome 内置 PDF 查看器，放开 inline 需单独评估安全面，不在本版）。图片附件的 inline 行为与缓存头（V7-03）保持不变。
- 内容模型：块节点 `fileAttachment`，attrs `{ attachmentId, fileName, size, mime, display? }`；文件名、大小、MIME 须与所属附件表记录一致，display 是笔记内的展示属性，不改变附件元数据；校验器把它计入 `attachmentIds`，复用引用计数、零引用宽限、版本快照引用、跨笔记复制与删除状态机；完整 `fileName` 计入搜索文本，不使用视觉省略后的文字。版本分配见 7.2。
- 复制粘贴：现有粘贴逻辑仅处理 `image` 节点的 `copyAttachment`，须扩展到 `fileAttachment`，否则跨笔记粘贴会得到悬空附件引用。
- 前端：附件 NodeView 按 10.1 提供紧凑/卡片及浮动操作栏，下载入口位于操作栏；文件上传入口收纳到“+”菜单，与常驻图片入口分流，表格内也可用；上传占位与失败重试沿用现有上传状态机。
- 验收：魔数伪造被拒、越权下载被拒、下载安全头断言、引用计数/宽限/GC/复制/备份恢复用例、旧客户端拒绝覆盖。

### 10.3 补充验收

- 两种样式切换并持久化，旧附件默认紧凑；只读时只提供下载，点击文件名不自动下载。
- 短文件名不撑满整行，卡片不超过 420px；文件名区不超过 280px，窄容器内单行省略且不溢出；悬停全名、下载名称与存储内容一致。
- 表头/普通单元格上传后仍在目标单元格，保存刷新保持；整表跨笔记复制生成目标专属附件 id 并保留展示样式，历史版本引用不被误删。
- schema 9 拒绝表格附件、schema 8 拒绝 display；schema 10 仍拒绝非法元数据、非法位置与嵌套表格。Markdown/ZIP 表格中附件链接可定位到导出文件。

## 11. TOC 大纲浮层（V7-11，P2）

- 以浮层/抽屉形式（工具栏入口，不占用三栏布局宽度）列出正文 heading 层级，点击滚动并聚焦对应标题；纯前端遍历文档，不入库、不进搜索表；无 heading 时入口禁用。
- 浮层打开期间不得引起编辑器重渲染（遵守 V7-02）。

## 12. 标题↔正文焦点闭环（V7-12，P2）

- 标题 `Enter`（非 Shift、非组合输入）聚焦正文起点，维持现状。
- 反向：正文光标位于首个正文块起点且选区折叠时按 `Backspace`，**仅当默认命令链没有任何效果时**才移焦点到标题末尾（`setSelectionRange` 置末）。若首块是标题/列表/引用，先沿用原有"降级/提升"行为，再次 Backspace 才移焦点；不删除任何正文内容。
- 组合输入期间（`event.isComposing` 或 `view.composing`）不触发。
- 标题块与正文的拆分投影规则不变（plan_v3 §7.2 补充）：首块含非文本节点时不作为标题投影。

## 13. 笔记互链（V7-13，P2）

- 入口：工具栏"插入笔记链接"弹层（`Popup`），搜索当前用户空间笔记标题（复用现有字面子串搜索 API），选择后插入 `noteLink` inline atom 节点，attrs `{ noteId, title }`。
- 渲染为可点击链接，点击走客户端导航（`/notes/{id}`）；`noteId` 为权威，`title` 为快照，显示时可用当前标题（若已缓存）；目标不存在、已进入回收站或被永久删除时显示降级样式，不阻断渲染和保存。
- 作为 schema 新节点占用一个新版本号（见 7.2）；`title` 计入搜索文本；校验 `noteId` 为正整数、`title` 长度受限。导航后仍由服务端按当前用户鉴权，链接不得暴露他人笔记标题。
- 导出降级为 `[[标题]]`。反链面板不在本版范围。

## 20. 编辑器与界面统一补充（2026-10-28）

本节汇总后续交互反馈的最终实现，覆盖早期规格中“不分组、不重排、不收纳”的工具栏限制。此前试用过的黄色标签确认/颜色清除按钮方案已被灰色次按钮方案替代；不将中间方案继续列为要求。未明确调整的数据、安全与保存规则沿用原基线。

### 20.1 工具栏分类与段落菜单

- 主工具栏按顺序保留撤销/重做、段落样式、常用文字格式、对齐、列表、常用插入及阅读操作，用分隔线区分用途。常用文字格式为加粗、斜体、下划线、文本颜色与突出显示；对齐保留左/中/右；列表保留无序/有序/待办；链接、表格、图片保留直接入口。右侧保留大纲、阅读宽度和只读切换。
- 段落样式菜单参考 Confluence，将普通文本、小号文本和标题 1–6 放在同一入口，入口显示当前样式，菜单用不同字号呈现标题层级。小号文本仍使用行内 mark；转标题清除目标段落的小号 mark，表格中的标题继续受内容模型限制。不凭空新增快捷键或展示未实现的快捷键提示。
- “+”（可访问名称“更多格式与插入”）按三组收纳低频操作：文字格式（删除线、行内代码、代码块、复制代码）、段落与列表（增加缩进、减少缩进、引用）、插入（分隔线、标签、笔记链接、文件附件）。图标旁显示文字，不只依赖图标猜测用途。
- 复用原命令、禁用条件、选区、撤销和保存队列，不增加另一套编辑路径；复制代码仅在代码块可用，缩进仍受列表上下文限制。执行菜单命令后关闭菜单；需要进一步输入时进入对应弹层。只读时禁止编辑入口。
- Esc 关闭菜单并返回触发器焦点；窄屏仍可局部横向滚动访问主工具栏，“+”复用底部弹层和键盘导航，不使整个页面横向溢出。现有快捷键保持不变。

### 20.2 标签、颜色弹层与按钮的最终视觉规则

- 标签采用 Confluence 风格的紧凑彩色 chip；预设十色为两行五列，不显示颜色名称文字，保留读屏名称与选中勾。数据、即时改色和复制规则见 §7。
- 文本颜色面板提供 30 种文本颜色与 10 种突出显示颜色，允许组合应用，分别恢复默认文本色/清除突出显示；不能因清除其中一种而清除另一种。工具栏图标为带圆角细边框的“A”，打开或存在相关格式时显示选中态。
- 标签弹层基础宽度 220px，颜色弹层基础宽度 300px，并受视口限制；不随正文大字号放大控件。窄屏使用现有底部弹层适配。
- **“确认标签”“默认文本颜色”“清除突出显示”统一使用灰色次按钮**：主题变量 `--ui-secondary-bg` 背景、`--text` 文字、`--line` 细边框、统一圆角和字重；hover 使用同一主题混色和边框规则。深色下使用对应深灰底，不使用黄色主按钮。保存账号设置、登录等其他主操作仍按其用途保留主色，不把所有按钮无差别改为一种语义。

### 20.3 对话框、设置和账号表单

- 屏幕控件统一入口为 `src/ui-surfaces.css`，在基础样式后加载，复用主题变量：普通界面文字 13px、标题 14px、辅助文字 12px；桌面控件基准高度 32px，触屏/窄屏 44px。色块、标题层级预览和正文不机械套用表单规格；触屏输入防放大仍按 §8 验收。
- 字段背景、文字、边框、圆角、主/次按钮、错误信息及遮罩统一，避免浅色页面出现深色原生输入框/复选框。共享屏幕样式不覆盖打印规则。
- 当前按独立挂载入口盘点为 **17 个自绘弹层入口**：14 个共用 Popup（笔记排序、工作区更多、笔记操作、附件操作、笔记互链、标签插入/编辑、链接操作、ZIP 导出、段落样式、笔记大纲、文本颜色/突出显示、插入表格、表格操作、“+”菜单），2 个原生 dialog 元素内的自绘表单（设置、切换账号），1 个 role=dialog 超链接表单。同一菜单子页和新增/编辑模式不重复计数。
- 版本历史侧面板和登录/注册表单一并对齐基础样式，但不计入上面的弹层数量。另有 13 个浏览器原生调用点（confirm 8、prompt 2、alert 3），由浏览器绘制，不声称网页 CSS 已统一其外观；明细见 [ui-surfaces.md](ui-surfaces.md)。
- 设置中的字号、宽度、主题、布局选择器提供足够宽度与箭头空间，避免“三栏”、默认字号等被截断；窄屏可改为纵向标签/控件。同步间隔数字输入采用相同主题字段样式。
- 账号与安全区域按“修改用户名/邮箱/密码”切换模式，字段纵向排列、标签在上、输入框等宽，显示密码复选框与文字居中对齐，保存按钮布局统一；保留当前密码、确认密码及前后端校验。
- 登录页修正显示密码复选框与文字错位，移除“当前实例未开放注册”和“邮箱仅作为登录账号，暂未验证。暂不支持自助找回密码，请妥善保存密码。本机草稿不是加密保险箱。”两段页面提示；这仅是文案精简，不代表加入邮箱验证、找回密码或加密草稿。注册开启方式仍见 §1.3。
