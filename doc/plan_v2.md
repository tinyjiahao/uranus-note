# Uranus v2 — 编辑体验、表格、排序与设置

> 状态：评审整理后的 v2 需求定稿，用于后续实施与验收，不代表功能已实现。基于用户反馈、线上截图及本地代码核对；未对线上服务进行测试。
> 本文是 `plan_v1.md` 的增量需求，不重建项目。未明确调整的架构、安全、保存、附件与数据隔离约束继续沿用 v1。
> 发布划分：v2 核心体验可独立发布；第 5 节网页更换登录令牌为独立安全里程碑，方案实施前仍需确认，不得当作已获批准的 Secret 存储规则变更。第 8 节仅为后续规划。

## 1. 目标与当前问题

| 用户需求 | 已观察到的情况 | v2 交付目标 |
| --- | --- | --- |
| 用好编辑区两侧空间 | 截图正文居中且左右空白明显；本地 `.prose-editor` 最大宽度 820px，专注模式 760px，另有左右内边距 | 默认自适应宽版，保留舒适阅读模式 |
| 表格更容易编辑 | 本地 TableKit 配置 `resizable: false`；当前样式统一铺满，单元格垂直顶部对齐 | 拖动列宽、便捷增删行列、水平/垂直对齐 |
| 按时间和标题排序 | v1 已规定排序，客户端请求已有 `sort_by` / `sort_dir` 参数 | 完善列表入口、状态记忆、服务端排序与分页一致性 |
| 设置及令牌管理 | 当前登录直接验证 Worker Secret `API_TOKEN`，会话依赖其指纹 | 新增统一设置入口，区分本机偏好、应用凭据和部署配置 |

排序属于已有要求的体验补齐；列宽调整由 v1 后续规划提升为本次交付。不据此宣称其他 v1 要求均已验收完成。

### 1.1 本次范围

- 编辑区宽度模式、合理留白和窄屏适配。
- 表格列宽、表格宽度模式、行列快捷操作、单元格对齐与持久化。
- 笔记列表的创建时间、更新时间、标题排序及升降序。
- 设置入口、偏好设置、安全设置、部署配置说明。
- 为上述改动补齐保存、版本恢复、旧数据兼容和测试。
- 补齐保存状态、撤销/删除反馈和窄屏返回流程；这是既有能力的体验验收，不重建保存系统。

核心目标是“写得顺、找得到、知道内容是否安全”。核心体验验收覆盖第 2—4 节、第 5.1 节及部署配置指引、第 6—7 节和第 9 节对应部分；网页直接换令牌单独验收，未交付时必须明确说明。新增规划不得无标识地并入本次范围。

### 1.2 不包含

- 多用户、角色权限、公开分享、实时协作和数据库迁移到其他平台。
- Excel 公式、表格内数据排序、合并单元格、复杂 Excel 格式无损粘贴。
- 自由拖拽全部布局分栏、任意 CSS 配置、后台云资源管理控制台。
- 网页填写 Cloudflare 管理 Token、动态更换 D1/R2 bindings 或回显任何 Secret。
- 本次不新增独立手工标题字段、内容修改时间字段、多端偏好同步或字体/行距自由配置。

## 2. 编辑区宽度优化

### 2.1 交互与布局

- 默认“自适应宽版”：正文使用右侧编辑面板的可用宽度，不再固定为 820px；编辑面板宽度至少 600px 时正文左右内边距各 32px，否则各 16px。宽度基于编辑面板而非整个浏览器窗口计算。
- 提供“舒适阅读”模式：正文外容器居中，最大宽度 860px（包含内边距）；可用区域不足时自动收缩，不出现页面级横向滚动。
- 编辑器顶部提供带提示的宽度切换按钮；设置页提供同一选项，两处状态保持同步。
- 三栏、双栏、专注模式均遵循所选宽度，不再为专注模式强制另一个最大宽度；折叠面板、窗口缩放后立即重新布局。
- 工具栏固定在编辑面板顶部，正文独立纵向滚动；切换宽度保留笔记、光标、选区和尽可能接近原位置的滚动视口，不重建正文或触发保存。
- 大图片不超出正文，宽表格和长代码块仅在自身容器内横向滚动，不把工具栏或整个页面撑宽。
- 保留清晰的键盘焦点指示，但避免整篇正文形成截图中类似固定纸张边框的强烈视觉分隔。
- 检查截图中大块纵向间距是空段落还是样式导致；仅修正不合理样式，不删除用户有意输入的空段落。正文默认行高约 1.6—1.75，普通段落间距以 0.5em 为起点，标题/列表/表格采用统一间距规则，不重复叠加默认 margin。
- 点击正文末尾的可编辑留白可定位到文档末尾继续输入，不批量生成空段落；只有真正输入或显式插入段落才改变正文。

### 2.2 偏好与验收

- 宽度是本浏览器全局偏好，存 `uranus.editor.widthMode`，值限定 `fluid` / `reading`；没有值时为 `fluid`。不写入正文、不产生 revision 或历史版本。
- 在 1440、1920、2560px 视口和三种分栏布局下，宽版应使用除必要内边距外的编辑面板空间。
- 在 375、768px 视口下不出现页面横向溢出；菜单、编辑、表格滚动仍可操作。
- 编辑中切换宽度或改变窗口大小不重置选区；切换笔记按既有队列处理未保存内容。刷新按 IndexedDB 草稿恢复流程验收，不承诺浏览器强制关闭时恢复尚未落盘内容或精确选区。

## 3. 表格编辑增强

### 3.1 列宽与整体宽度

- 鼠标接近列边界出现拖拽提示与调整光标；拖动实时预览，释放后作为一次可撤销编辑提交。
- 默认列宽下限 64px；保存值必须是有限正数，并设置合理上限（单列不超过 2000px），拒绝 NaN、Infinity、负值和任意样式字符串。
- 自适应表格也遵守最小列宽；正文宽度小于列数 × 64px 时改为容器内横向滚动，不强压单元格。拖动一个列边界只改变对应列宽，其他列保持不变。
- 支持“适应正文宽度”和“按列宽显示”两种表格模式。旧表格默认适应正文；首次手动拖拽切换为按列宽显示，表格总宽取各列宽之和。
- 按列宽显示时允许总宽超过正文，表格容器提供横向滚动；不能为塞入窄屏而覆盖已保存的列宽。末列也可调整，不隐式压缩其他列。
- 提供“恢复自适应”操作，清除手动列宽；提供“平均分配列宽”，在当前表格总宽下重新均分，仍遵守最小列宽。
- 处理 pointerup、pointercancel、窗口失焦、切换笔记和组件卸载。取消操作恢复拖拽前宽度；一次拖拽不能产生大量撤销记录、保存请求或历史快照。
- 触屏和键盘用户可在表格菜单中输入当前列宽作为拖拽替代。

### 3.2 行列操作

- 插入表格提供 1×1 至 6×6 网格选择器，默认 2×2，表头默认开启且可取消；键盘和触屏提供等价行列选择入口，更多行列可插入后追加。
- 不再显示编辑器顶部的独立表格工具条，改用贴近表格的边缘手柄和弹出菜单：左上角为表格菜单，左侧/顶部为行列菜单，分隔处提供插入按钮。菜单期间保持表格选区，不能因编辑器失焦立即消失；菜单限制在视口内，支持 Escape 关闭。
- 行列手柄选中对应整行/整列并打开操作菜单；对齐、列宽和危险操作放在表格菜单中，不再常驻占用编辑区高度。
- 提供“上方插行 / 下方插行 / 左侧插列 / 右侧插列 / 删除行 / 删除列 / 表头开关 / 删除表格”。
- 表格底部与右侧提供紧贴实际表格边缘的“+”入口，分别追加一行、一列；行列菜单提供定向插入，不能只靠 hover 或右键才能完成操作。
- 保留 Tab / Shift+Tab 在单元格间移动，最后一个单元格按 Tab 追加行；新行列继承合理宽度和相邻格式，不复制原内容。
- 复制行格式时不把表头自动扩展到所有新行；新列继承邻列宽度，追加后总宽度按第 3.1 节处理。超过服务端正文/结构预算时拒绝追加并提示，不生成无法保存的巨大表格。
- 点击工具条不丢失表格选区；多单元格选择支持明确的选中态，操作作用于所选行/列，跨越表格的无效选择禁用并提示。
- 删除最后一行或最后一列等价删除表格，采用相同确认规则；删除整张非空表格需确认，空表格可直接删除，所有结构删除可撤销。普通行列删除无需连续弹窗，但必须有明确名称和撤销提示。
- 增删行列后将光标放到合理的相邻单元格；不得跳到笔记开头。
- 多单元格选区按 Delete/Backspace 只清空内容，保留结构和格式；普通文本选区沿用文本删除行为，结构删除必须使用明确的行列命令。
- 提供“在表格下方继续输入”入口，在表格后创建或聚焦相邻段落；末尾表格同样可用，不要求用户记忆隐藏快捷键。

### 3.3 单元格内容对齐

- 水平：左对齐、居中、右对齐；垂直：顶部、居中、底部。
- 无多选时作用于光标所在单元格，多选时作用于所选单元格；不同对齐值显示“混合”，不伪装成统一值。
- 对齐作用于单元格内容，不是整张表格在页面中的位置；影响文字和单元格允许的内联内容，不扩展 v1 对复杂嵌套块的支持。
- 新正文单元格默认左对齐/顶部，表头默认水平居中/顶部；旧内容未声明属性时维持原视觉，不批量改写正文。
- 对齐、列宽、表格宽度模式保存在 TipTap JSON 的白名单属性中，例如单元格 `colwidth`、`textAlign`、`verticalAlign` 与表格 `widthMode`；实际命名需在前后端共享 schema 中统一。
- 只读及回收站预览禁止所有修改，但正常展示宽度和对齐，允许选择复制及表格滚动。

### 3.4 保存、兼容与验收

- 列宽、对齐、行列修改复用既有保存队列、revision、幂等和本地草稿；不引入单独绕过乐观锁的“表格保存”。
- 扩展客户端编辑 schema、服务端校验、导入清洗、版本预览和恢复；仅调整 CSS 不算实现完成。
- 新属性使用内容 schema 新版本（当前为 1 时升级为 2）。旧正文按默认值读取，保存时升级；旧历史版本无需全量重写，恢复时显式转换。不兼容的旧客户端应提示刷新并禁止覆盖，不得丢弃新属性。
- 刷新、另一设备打开、版本恢复后列宽与对齐保持；撤销/重做能恢复拖拽及结构操作，旧笔记仍可编辑。
- 验收覆盖 1 列、2 列、10 列、长文字、空单元格、表头、多选、窄屏滚动、拖拽取消和编辑冲突。

## 4. 笔记列表排序

### 4.1 入口与规则

- 笔记列表顶部搜索框附近增加“排序”按钮，不能藏在某一篇笔记的菜单中；显示当前字段及方向。
- 字段为“更新时间 / 创建时间 / 标题”；时间方向显示“最新在前 / 最早在前”，标题方向显示“升序 / 降序”。默认更新时间最新在前。
- 这里排序的是笔记列表，不改变正文顺序、不增加独立的手工标题字段；标题仍由首个文本行派生。
- 置顶笔记始终在前，并显示置顶标识；组内按所选字段与方向排序，同值以 id 升序稳定排序。仅标题排序时无有效标题的笔记放在各组末尾，显示用的“未命名笔记”不作为真实标题；时间排序不因标题为空改变时间顺序。
- 标题沿用 SQLite 字符序，不承诺中文拼音、自然数字顺序或 locale 排序；界面不使用容易误导的“拼音排序”名称。
- 全部笔记、星标、普通文件夹、最近删除及搜索结果共用规则；过滤条件先作用，再进行全量候选排序和分页。
- 更新时间沿用服务端 `updated_at` 的定义，包括正文或元数据实际更新；仅切换布局、设置偏好和排序不修改笔记时间。
- 时间排序时列表展示对应时间并有“创建/更新”说明；标题排序默认展示更新时间。近期使用“今天 HH:mm / 昨天 HH:mm”，其他日期显示年月日，悬停或可访问说明提供本地时区的完整时间，不改变服务端 UTC 数据。

### 4.2 状态与数据

- 本浏览器统一记忆一组排序偏好，写入 `uranus.notes.sort`；切换范围沿用，不为每个文件夹引入独立配置。
- 复用 `GET /api/notes` 的 `sort_by=updated_at|created_at|title`、`sort_dir=asc|desc`；服务端白名单校验，不在前端只排序已加载的 100 条。
- 排序和筛选进入 Query key；改变顺序重置分页和列表滚动，取消旧结果展示，保留当前编辑笔记与未保存状态。
- 自动保存成功后合并刷新列表，不在每次按键时重排、不抢焦点或重载编辑器；当前选中 id 保留，不强制跳回列表顶部。选中笔记暂不在已加载页时，编辑器仍保持打开，不能注入一条破坏排序的伪列表项。
- 验收至少使用 150 篇静态测试笔记，覆盖相同时间、相同标题、空标题、中英文、置顶、搜索与跨页，确认没有遗漏、重复或局部排序。并发变更沿用 v1 页码分页重置/去重规则，不承诺跨请求快照一致性。

## 5. 设置入口与安全配置

### 5.1 页面结构

- 全局仅保留左下角齿轮“设置”，与主题、退出区分；侧栏收起、专注模式和窄屏时仍在左下角保留同一个入口。操作图标统一使用 SVG 尺寸和线宽，不混用文字字符图标。
- 桌面使用右侧设置抽屉，移动端全屏展示；Esc/关闭返回原笔记，焦点回到原入口。使用焦点约束与可访问名称，不因打开设置卸载编辑器或丢失草稿。
- 分为“编辑与外观 / 安全 / 关于与部署”。偏好即时生效，注明“仅此浏览器”，敏感修改必须显式提交、二次验证并提示影响范围。令牌表单未提交即关闭时提示确认并清理明文。
- “关于与部署”展示应用版本、配置是否齐全及实际检查到的服务状态；仅检查 binding 存在不能显示“读写正常”。不暴露资源 ID、原始错误、完整配置或 Secrets，提供项目与部署文档入口。
- 提供“恢复默认偏好”，明确仅重置布局/主题/排序等偏好，不清除笔记、草稿、凭据或云端数据；localStorage 不可用时本次会话仍生效，并提示无法记忆。

| 设置项 | 可操作范围 | 持久化位置 |
| --- | --- | --- |
| 编辑宽度、主题、默认排序 | 网页可改，仅本浏览器生效 | localStorage，统一现有偏好状态 |
| 应用登录令牌 | 推荐支持网页更换，见下述待确认方案 | D1 中仅存校验摘要，不存令牌明文 |
| `API_TOKEN` Worker Secret | 展示用途与部署端更新指引，不读取或直接修改云端 Secret | Cloudflare Secrets |
| `SESSION_SECRET` | 不展示值、不网页编辑；提示更换会让会话失效 | Cloudflare Secrets |
| D1/R2 bindings、APP_ORIGIN、会话时长 | 展示允许公开的有效状态及配置说明，不提供任意键值编辑器 | 部署配置，仍按 v1 管理 |

### 5.2 API_TOKEN 与网页换令牌的边界

`API_TOKEN` 是 Uranus 应用登录凭据，不是 Cloudflare API Token。当前代码直接验证 `env.API_TOKEN`；普通应用设置接口不能通过赋值 `env` 持久化修改 Worker Secret。Cloudflare Secret 的更新属于平台管理操作，应通过 Dashboard、Wrangler 或平台 API 完成。[Cloudflare Secrets 文档](https://developers.cloudflare.com/workers/configuration/secrets/)

本次推荐：网页修改“有效应用登录令牌”，不让应用获得管理 Cloudflare 账号的权限。具体采用“部署 Secret 引导 + D1 令牌校验记录”方案；这是相对 v1 的鉴权变更，实施前需用户确认。

- 保留 `API_TOKEN` 作为初始化凭据：尚未启用网页令牌记录时，沿用 v1 登录；首次成功更换后只接受 D1 中当前有效凭据，不再把旧 Secret 当作备用登录入口。
- 初始化状态必须显式、持久化，区分“从未启用”和“启用后记录异常丢失”；后者拒绝登录并要求运维恢复，不能因为查不到记录就自动重新接受旧 Secret。schema 缺失或查询失败也不能视为首次初始化。
- 设置页称“更换登录令牌”，明确提示“不会修改 Cloudflare 中的 API_TOKEN Secret”；不能显示成“云端 API_TOKEN 已更新”。
- 新增单例 `uranus_auth_config`，记录高熵令牌的校验摘要、credential_version、updated_at；不存原始令牌，不开放通用 SQL 或配置写入接口。令牌由安全随机数生成至少 32 字节，不支持把简单口令当令牌使用。
- 校验摘要采用经安全评审的高熵令牌校验方式（如 SHA-256），恒定时间比较；不得将这套快速摘要方案扩展为低熵密码登录。
- 会话绑定当前 credential_version；启用网页凭据后每次鉴权读取权威状态，轮换提交后到达的请求不得接受旧会话。D1 不可用返回 503，禁止回退旧 Secret 或公开模式。
- 已通过鉴权但尚未提交的写请求需在提交点校验凭据版本；令牌轮换后的旧请求不能继续提交。长上传仍按既有补偿机制处理，不以取消浏览器请求代替服务端隔离。
- 旧 v1 会话在启用该模式时全部失效；单用户空间中所有设备权限相同，但更换令牌仍要求重新验证当前有效令牌。

### 5.3 更换流程与失败处理

1. 用户进入安全设置，输入当前有效令牌完成二次验证。
2. 使用浏览器安全随机源生成新令牌，仅在本次表单内显示并允许复制；用户确认已保存。刷新或关闭不提供重新查询明文的能力。
3. 提交前处理当前未保存笔记，默认等待保存成功；存在错误时阻止轮换，提供取消返回，不静默丢弃草稿。
4. 以已有 Cookie + Origin + CSRF 保护提交当前令牌、新令牌、expected credential_version 和 operation_id。接口独立限流，不能仅验证已有 Cookie 就更换凭据。
5. 服务端在同一 D1 原子操作中以二次验证时的凭据版本和摘要为提交条件，更新摘要、递增版本并记录无敏感值的幂等回执；避免先验证后无条件写入。并发更换最多一次成功，另一方返回冲突或会话已失效，不能覆盖胜出结果。
6. 成功后清除当前会话并返回登录页，明确所有设备需要新令牌重新登录；其他标签页收到状态通知或下一次请求 401 后锁定，未提交草稿按 v1 会话过期规则保留。

- 原令牌、新令牌、摘要均不得进入 URL、localStorage、IndexedDB、Query 持久缓存、日志、分析事件或幂等响应；仅表单短暂持有明文，关闭时清理。
- 网络错误且提交结果未知时，不能自动恢复旧令牌或再次轮换。提示使用已保存的新令牌尝试登录；若失败再用旧令牌检查状态。认证仍执行统一限流。
- 重试携带原 operation_id，不重复增加版本；已失效 Cookie 不因幂等而绕过鉴权，先重新登录再查询必要状态。
- 安全页面只显示“已配置”、当前版本和更换时间，不返回完整或部分令牌；敏感响应使用 no-store。

### 5.4 恢复、部署和备份

- 忘记网页令牌后的恢复仅由部署者在维护窗口通过明确的运维步骤完成：更新 API_TOKEN Secret，并显式重置该实例认证记录/递增凭据版本，随后重新初始化；只改 Secret 不能假装覆盖 D1 中的当前凭据。
- 重置操作不能删除笔记、附件或共享 D1 其他应用数据，必须提供精确命令与测试；不提供匿名恢复接口，也不把旧 Secret 保留成后门。
- 运维重置还必须轮换 SESSION_SECRET 或使用不重复的凭据代际标识，防止版本计数重置后旧 Cookie 再次有效；不允许简单删掉认证表记录就认为完成安全恢复。
- `SESSION_SECRET` 仍只由部署端持有和轮换；更换后所有会话失效，D1 中令牌摘要仍可用于重新登录。
- 常规笔记备份不包含认证摘要及会话；新实例恢复内容后使用目标实例凭据，不能因恢复业务数据重新激活旧令牌。
- 如果不批准上述鉴权调整，则本次设置页只提供部署端更换 API_TOKEN 的指引；这应明确标为“网页直接换令牌未交付”，不能用展示设置按钮代替该需求完成。

## 6. 保存反馈、撤销与导航

### 6.1 可理解的保存状态

| 状态 | 界面反馈及操作 |
| --- | --- |
| 有修改或正在保存 | “未保存 / 正在保存”，不提前显示成功 |
| 当前编辑序号已获服务端确认 | “已保存到服务器”，可查看最近确认时间 |
| 网络异常，当前草稿已落盘 | “未同步，草稿已暂存此浏览器”，提供重试 |
| 服务端保存和本机暂存均失败 | 显著提示“内容尚未安全保存”，提供复制未保存内容和重试 |
| 其他设备已更新 | 提示冲突，提供查看服务器版、保留/复制本机草稿，不自动覆盖 |
| 会话过期 | 锁定敏感内容并要求登录，按 v1 规则保护本机草稿 |

- “本机已暂存”仅在 IndexedDB 确认对应 edit_sequence 落盘后显示，不与服务器保存使用相同成功提示。复制按钮失败时提供可手工选择复制的替代方式。
- 保存进度使用稳定状态区，错误持续到解决，不在每次自动保存弹 toast；状态更新不抢焦点，读屏仅在必要状态变化时播报。
- 不新增离线同步保证、不扩大重试次数或绕过现有并发控制。登录失效后不能为了方便复制而继续公开显示正文。

### 6.2 撤销与危险操作

- 普通删除笔记进入回收站，显示“已移到最近删除 · 撤销”，不增加重复确认；撤销调用正式恢复流程，失败需提示，不伪装本地恢复成功。
- 表格和正文编辑通过编辑器撤销栈恢复；跨笔记切换和刷新后不承诺撤销栈仍存在，历史恢复是另一能力。
- 永久删除和清空回收站必须确认对象数量、范围及不可恢复性；后台任务未完成时显示“处理中”，不把已入队称为已完成。
- 删除文件夹提示会将其中笔记移入最近删除；不使用含糊的“删除文件夹”确认文案隐藏内容影响。

### 6.3 窄屏与操作可达性

- 窄屏编辑页始终提供“返回笔记列表”；返回保留原范围、搜索词、排序及尽可能接近的滚动位置，不因导航丢草稿。
- 图标按钮有可访问名称和提示，活动态不只靠颜色；主要触摸操作采用约 44px 点击区，桌面紧凑工具至少提供清楚间距和足够命中区。
- 所有 hover/拖拽能力有可点击菜单或键盘替代；表格菜单、设置抽屉和确认框可键盘进入、关闭并恢复焦点。

## 7. 数据与接口增量

- UI 偏好优先复用现有 store/localStorage，不新增业务表，不影响笔记 revision。
- 表格属性进入版本化内容 schema；所有渲染、校验、导入和历史恢复路径保持一致，不接受任意 style 注入。
- 排序复用现有笔记列表 API，核对真实分页行为，不另造一套仅前端排序接口。
- 若确认网页换令牌，增加 `GET /api/settings/security`（仅状态）与 `POST /api/settings/security/token`（条件轮换）；具体 DTO、限流及错误码在实施设计中固定。
- 新增数据库对象一律 `uranus_` 前缀，迁移只追加；新认证接口不能绕过维护模式、CSRF 或统一错误处理。
- 认证迁移先发布兼容 schema/读取逻辑，再开放更换入口；内容 schema 升级前验证旧客户端拒绝覆盖能力，必要时要求刷新。回滚不能让旧代码重新接受已撤销 Secret，也不能静默丢失新表格属性。

## 8. 后续规划，不阻塞 v2 核心发布

- 搜索闭环：明确搜索范围、返回命中片段、点击结果定位并高亮正文匹配；清空搜索恢复原列表上下文。全文规范化与原文位置映射正确后再开放定位，不能按错误偏移跳转。
- 简单表格粘贴：支持 TSV 制表符分列、换行分行，不承诺 Excel 样式；实施前定义覆盖/扩展单元格、超限和撤销行为。
- 阅读位置恢复：按笔记记忆普通打开时的位置；从搜索进入优先命中定位，用户编辑后不反复抢回旧位置。与第 6.3 节列表返回位置分开管理。
- 暂缓长文目录、最近访问、快速切换器、复杂表格和更多排版设置，按实际使用反馈单独评估。

| A | 编辑区自适应、排序入口与偏好 | 大屏空间利用改善，跨页排序正确，草稿和选区不丢失 |

- 单元测试：宽度/对齐属性校验、内容升级、偏好默认值、排序参数及凭据轮换状态。

- 浏览器测试：宽度切换、表格鼠标/键盘操作、多选、撤销、刷新、只读、深浅主题、移动端；输入中打开设置不丢草稿。
- 安全测试：CSRF、错误当前令牌、重复提交、并发轮换、响应丢失、多设备会话失效及运维恢复；请求和响应日志均不得记录凭据。
- 发布前完成 typecheck、构建、相关单元/集成/e2e 与 staging 冒烟；生产发布由部署流程另行执行，本需求整理不授权直接修改线上配置。
- 最终验收逐项标记已实现、实测结果及未交付项，不能把本文件或设置页面的存在当作功能完成证据。

### 9.1 发布前任务走查

1. 在大屏新建笔记、切换宽度并连续输入：布局合理，光标稳定，不产生无意义保存。
2. 插入 3×4 表格、追加行列、调列宽、设置多单元格居中、在表格下方继续输入：无需隐藏快捷键即可完成，刷新后结果保持。
3. 在超过一页的笔记中切换三种排序和方向：全量顺序正确，当前编辑内容不丢失，时间展示与排序一致。
4. 模拟断网及 IndexedDB 写失败：能明确分辨服务器已保存、本机暂存、完全未保存，且有实际可用的补救入口。
5. 误删笔记后撤销、误删表格行后撤销、尝试永久删除：恢复与确认规则可理解，失败不会显示成功。
6. 窄屏打开设置再返回笔记和列表：搜索、排序、草稿与导航上下文保持，键盘焦点合理。
7. 仅在 D 阶段：两设备轮换令牌，验证旧会话拒绝、未知提交结果处理、认证记录异常拒绝及部署者恢复流程。

每个任务记录操作路径、预期/实际结果、截图及发现的问题；发布前完成一轮不依赖开发者口头提示的走查。量化性能继续沿用 v1 基线，不因新增表格和鉴权逻辑忽略回归。
