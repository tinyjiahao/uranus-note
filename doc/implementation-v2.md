## 数据升级

新增 `migrations/d1/0003_content_v2.sql`，不改写已发布 migration。原 schema=1 的 CHECK 列改名为 `content_schema_v1`，保留为兼容占位列，新增真实 `content_schema_version` 列支持 1/2。这样不重建有外键引用的父表，避免 D1 DROP TABLE 引发级联删除。业务写入只使用新版本列；新历史记录显式写入占位值 1。旧内容和旧快照不批量重写。

升级测试先应用 0001/0002，写入旧笔记/历史/附件/正文与历史引用/搜索，以及非 Uranus 哨兵表，再应用 0003，检查数据与外键完整性。

生产发布必须先备份、进入维护窗口，再应用迁移、发布 v2 Worker 和静态资源，随后验证新旧笔记。**产生 schema 2 数据后不能直接回滚到 v1 Worker**：旧代码不认识新表格属性，且旧 SQL 不适配新历史表写入。旧浏览器保存 schema 2 笔记会收到 `CLIENT_UPDATE_REQUIRED`，需刷新页面。

2026-10-24 已完成生产升级：先进入维护模式备份并校验 SHA-256，再应用远端 `0003_content_v2.sql` 并发布 Worker 与静态资源。Cloudflare 部署版本为 `4a2ef42b-5527-4f39-a15f-f3728010f361`。

生产备份包含 1 篇笔记、1 个历史版本、1 个文件夹，无附件。升级后通过应用 API 逐字段比对全部业务记录，与升级前备份一致；确认生产版本为 `0.2.0-preview.1`，登录及 Cookie 安全属性正常。后续站点请求出现间歇性连接超时，维护 API 重试受阻，改用 Cloudflare D1 管理通道按本次 maintenance_id 条件解除冻结，并读回确认 `mode=normal`；未修改笔记或其他应用数据。未完成真实生产写入及第二设备验证，不将本次上线等同于全部发布退出条件通过。

## 正文对齐增量

工具栏新增段落/标题的靠左、居中、靠右对齐，支持多段选区、撤销和只读展示。对齐保存到正文 JSON，使用 content schema 3；草稿、历史版本、备份恢复同步支持，旧客户端不能覆盖新版笔记。

新增 `0004_block_alignment.sql`，保留原受限列为兼容占位列，并复制既有版本号到支持 1/2/3 的新列；不重建父表或批量改写旧正文。上线前须备份并应用迁移，再发布 Worker 与前端。产生 schema 3 数据后不可直接回滚到仅支持 schema 2 的版本。

2026-10-24 已发布正文对齐增量：代码提交 `47af747`，Cloudflare 版本 `9d820737-8f72-42c1-8ffe-e06f459784d9`。生产先冻结并备份 5 篇笔记、6 个历史版本、2 个文件夹、1 个附件及 1 条引用，校验全部备份文件 SHA-256 后应用 `0004`。应用 API 间歇超时，备份剩余部分改由 Cloudflare 管理通道读取，范围仅限 Uranus 表与附件。迁移后逐字段核对全部业务记录与备份一致；线上首页已引用新构建，健康检查返回 200/ok。未进行生产真实编辑或跨设备验证。
