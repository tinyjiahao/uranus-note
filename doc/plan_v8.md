## 2. V8-01 拖拽手柄对齐

- 问题：每个顶层块前的拖拽手柄挂在高度为 0 的锚点上，位置固定为 `top: 3px`。标题的上边距会穿过锚点，且各级标题字号不同，导致手柄相对首行忽高忽低（段落偏低约 6px，二级标题偏高约 14px）。
- 方案：不依赖 CSS 固定偏移，改为按块首行实际位置计算。手柄 `top = 块顶部 − 锚点顶部 + 块上内边距与上边框 + 首行行高/2 − 手柄高度/2`。表格取第一个单元格内的段落作为首行参照。
- 触发时机：编辑器每次更新、编辑区宽度或字号变化（`ResizeObserver`），用 `requestAnimationFrame` 合并，销毁时清理。
- 约束：不改变拖动、Alt+↑/↓ 移动、取消和只读隐藏逻辑；仅调整手柄位置。
- 验证：Chrome 实测 4 篇测试笔记共 70 个手柄，与首行中心偏差均在 ±1px 以内（代码块已计入内边距）。未验证窄屏（≤767px）和深色主题下的外观。
- 显示策略（后续调整）：手柄默认隐藏，**以鼠标位置为准**：指针所在行（按 y 坐标取该行的顶层块，含左侧留白）显示该块手柄，不再跟随光标；移出编辑区隐藏，滚动时按指针当前位置刷新（`mousemove`/`scroll` + `requestAnimationFrame` 合并，类名 `is-hover`）。手柄自身悬停、获得焦点（拖动或 Alt+↑/↓）时保持可见，拖动期间不切换。触屏（`hover: none`）没有鼠标，仍在编辑器聚焦时显示光标所在块的手柄（`is-current`）。只读模式不渲染手柄。Chrome 实测：初始与鼠标在外时 0 个；悬停段落显示该行；移到文字左侧间隙和手柄上保持；移到其他行切换；滚动后随指针更新；`block-drag` 端到端用例通过。
- 附件手柄位置：同一行并排的文件附件，手柄改为各自卡片左上角内侧的 18×18 小角标（偏移 −4px/−4px，随反馈由 −10px 向内、向下收），不再挂在相邻两个附件的缝隙里；悬停判断对附件同时看 x，鼠标在哪个附件上就显示哪个附件的手柄（此前同一行总是显示最右边那个）。Chrome 实测五个附件逐个悬停，手柄均在各自左上角。引用、列表项、表格单元格内的附件仍无手柄（块拖拽只作用于顶层块）。
- 拖动落点提示：普通块仍显示横线；排成一行的文件附件（V8-21）按指针 x/y 二维定位插入点，在相邻附件之间显示与卡片等高的竖线（`block-drop-guide` 宽 3px），落点在所指附件左半侧为其前、右半侧为其后，不再整行横线。Chrome 实测：把第三个附件拖到第一个附件左半侧，提示为 3×85px 竖线，放开后顺序由 a b c 变为 c a b。未验证触屏拖动。
- 实现位置：`src/components/editor/blockDrag.ts`。

## 3. V8-02 深色模式行内代码

- 问题：行内代码背景使用 `--panel-soft`（`#2c2b26`），与编辑区背景 `--panel`（`#22221e`）亮度接近，几乎不可见。
- 方案：仅深色主题下使用更亮的背景 `#3f3e36`，并用 1px `--code-border` 的 `box-shadow` 勾边（不改变行高和布局）。浅色主题不变。
- 引用块内（背景 `--quote-bg` 与代码背景几乎相同）：深色主题下行内代码和代码块使用更深的 `#1d1c19` 背景与 `#55524a` 边框，Chrome 已查看深浅两种主题。
- 实现位置：`src/styles.css`。

## 4. V8-03 深色模式高亮文字可读性

- 问题：带颜色的高亮在行内样式中写死 `color: inherit`，深色主题下继承浅色正文色，浅色高亮背景上的文字几乎看不见。默认黄色高亮同样受影响。
- 方案：
  - 高亮不再输出 `color: inherit`；文字颜色 `<span>` 增加 `data-text-color` 标记。
  - 深色主题下 `mark` 的文字使用深色 `#292a2e`；若高亮位于文字颜色内部，则继承该文字颜色，因此“红字黄底”等叠加仍然生效。
- 已知限制：调色板中最深的文字颜色 `#292a2e` 在深色背景上仍几乎不可见，属于既有调色板设计，未处理。
- 实现位置：`src/components/editor/textColors.tsx`、`src/styles.css`。

## 5. V8-04 行内图片（content schema 12）

### 5.1 问题与范围

- 图片原为独占一行的块级节点 `image`，多张图片无法并排对比。
- 新增行内节点 `inlineImage`，与块级 `image` 并存：旧笔记、旧图片及其缩放、对齐、拖动手柄行为不变，不自动迁移。

### 5.2 数据格式与校验

- 节点：`inlineImage`，行内、原子节点、可拖动，不含子节点和 marks。
- 属性（`shared/inlineImage.ts`，严格模式）：`attachmentId`（`[a-zA-Z0-9_-]{1,128}`）、`src`（必须等于 `/api/attachments/{attachmentId}`）、可选 `alt`（≤255，无控制字符）、可选整数 `width`（40–900）。
- 位置：只能位于段落内（含表格单元格内段落，也允许出现在单元格富文本的段落中），不能位于标题。
- 版本：`shared/schemaVersion.ts` 的 `CURRENT_SCHEMA_VERSION` 升为 12，新增 `SCHEMA_FEATURE.inlineImage = 12`，兼容读取 1–11；schema 12 以下写入 `inlineImage` 被拒绝。
- 附件引用：校验时把行内图片的 `attachmentId` 纳入引用集合，沿用当前正文与历史版本共同引用、跨笔记复制生成目标专属附件的规则。
- 迁移：沿用 0010 的 `content_schema_version BETWEEN 1 AND 99` 约束，无需新增迁移。产生 schema 12 内容后，不得回滚到旧 Worker，旧客户端不得覆盖。
- 导出：Markdown 导出为 `![alt](attachments/...)`，ZIP 导出包含其附件文件；搜索文本不包含图片。

### 5.3 编辑行为

- 新插入（上传或粘贴）的图片默认一律为行内图片：光标在段落（含空段落、单元格段落）内时直接插入，连续插入的图片停留在同一段落并排；光标在标题、代码块或选中了某个节点时，在当前块之后新建一个段落放置该行内图片，不再插入块级图片。块级图片仅存在于旧内容，或通过“转为独立图片”得到。
- 工具栏上传图片支持一次选择多张，按顺序上传并全部插入同一行；任一失败则停止，沿用既有重试与错误提示。
- 图片菜单（右键或 Shift+F10）：
  - 块级图片：新增“转为行内图片（可并排）”。若紧邻其前的是仅含行内图片的段落，则并入该段落，否则新建段落。
  - 行内图片：“转为独立图片（单独一行）”，会拆分所在段落；另有“复制图片”“移除图片”（菜单内不再附说明文字），在表格内保留“表格操作”入口。
- 转换保持显示尺寸：转换时按图片当前实际渲染宽度写入 `width`（行内限制在 40–900px，块级不限），因此两种形态互转前后显示宽高不变；行内图片的间距加在外层容器上，不再挤占图片可用宽度。
- 独立（块级）图片拖动调整宽度的下限由 120px 改为 80px（上限 900px 不变，服务端不校验块级图片宽度）；行内图片仍为 40–900px。
- 显示：默认高度约 300px、宽度自适应且不超过容器，一行放不下自动换行；选中时描边；双击放大预览；拖动右下角圆点调整宽度（40–900px，写入 `width`），Esc 取消，只读模式不显示圆点。
- 行内图片不提供对齐；自带的小拖拽手柄见 V8-21 末；不改变块级图片的现有功能。

### 5.4 验证

- 单元测试 `tests/unit/inline-image.test.ts`：同段落多图并收集附件、schema 11 拒绝、标题内/错误来源/越界宽度拒绝、表格单元格内允许、Markdown 导出。
- Chrome 实测：行内默认 450×300、显式 150×100，块级 666×444、260×173 互转前后尺寸均不变。
- Chrome 实测：光标在标题、代码块、空段落（连续两次）时上传，均得到行内图片（前两者新建紧随其后的段落，后者并排于同一段落）；独立图片拖动时最小宽度为 80px。
- Chrome 实测：往空段落连续上传 3 次得到 1 个段落、3 张行内图片、顶部坐标一致；块级与行内互转；以 schema 12 保存到服务端。
- 未验证：真实 iOS/Safari、多图粘贴的真实键盘操作；从文件管理器拖入文件见 V8-26。

## 6. V8-05 图片复制、粘贴尺寸与副本去重

### 6.1 复制图片

- 图片菜单新增“复制图片”（块级与行内均有）。写入系统剪贴板两种数据：
  - `image/png`：图片像素，供其他应用粘贴；非 PNG 先经 canvas 转成 PNG（GIF 仅复制第一帧）。
  - `text/html`：带 `data-attachment-id`、`width`（及行内标记、对齐）的 `<img>`，供回到本编辑器时还原节点。
- 浏览器不支持异步剪贴板写入时给出错误提示；成功后提示“图片已复制”。

### 6.2 粘贴保持显示尺寸

- 粘贴处理发现剪贴板 HTML 含 `data-attachment-id` 时，优先使用 HTML 还原节点，不再把 PNG 文件当作新图片上传（外部来源的图片文件仍按新图片上传，使用默认大小）。
- 修复：
  - 异步剪贴板 API 会把相对地址改写为绝对地址，导致被误判为外部图片而丢弃；现将同源 `/api/attachments/{id}` 归一化为相对地址。
  - 块级图片 `width` 原从 HTML 读成字符串，被节点视图忽略；现解析为数字。
  - 行内图片解析规则提高优先级，避免被块级图片的 `img[src]` 规则抢先匹配。
- 验证：菜单“复制图片”和原生复制粘贴两条路径，行内（150px）与块级（260px）粘贴后宽度均保持不变。
- 若粘贴时当前选中的是一张图片，则替换该图片，与通用编辑器一致。

### 6.3 同一笔记内重复粘贴只保留一个副本

- 从其他笔记粘贴图片会为目标笔记生成专属附件副本（既有规则）。此前每次粘贴都会再复制一次。
- 现在编辑器按“目标笔记 id + 来源附件 id”记录已复制的副本：同一次粘贴中的重复引用共用一次复制；之后再次粘贴同一来源时，若副本仍在正文中被引用则直接复用，若已被删除则重新复制，复制失败则清除记录以便重试。文件附件走同一逻辑。
- 同一笔记内复制粘贴本笔记已有附件原本就复用同一附件 id，不产生副本。
- 范围：记录仅存于当前打开的编辑器；刷新或重新打开笔记后，再从别的笔记粘贴同一张图仍会生成新副本。后端按来源附件或文件哈希去重不在本版范围。
- 验证：向一篇笔记粘贴来自另一篇笔记的同一张图，一次粘贴含 2 个引用并重复 2 次，共 6 个节点，附件 id 仅 1 个；保存后服务端正文也只引用 1 个附件。

## 7. V8-06 笔记信息

### 7.1 入口与形态

- 笔记菜单（列表“···”和编辑区“笔记更多”，含最近删除中的笔记）新增“笔记信息”，以弹层展示，内容较多时弹层内部滚动。只读，不新增页面或数据库字段。

### 7.2 展示内容

- 概览：创建时间、更新时间（含相对时间）、所在文件夹、状态（置顶/星标/最近删除）、删除时间、版本号 `r{revision}`、内容格式 `schema N`、笔记 id。
- 正文（前端计算，优先使用本机未同步内容）：字符数（含空白/不含空白）、字数（中日韩逐字，其他按词）、预计阅读时间（300 字/分钟）、正文 JSON 大小、段落数与标题数。文本口径与搜索/`char_count` 一致（含标签文字、笔记链接标题、附件文件名）。
- 内容元素：图片（块级与行内）、文件附件、表格、代码块、链接、笔记链接、标签数量，以及任务完成数。
- 附件与版本（后端）：ready 附件的数量与大小，图片/文件分组；“仅历史版本引用”（当前正文已不引用但历史版本仍引用）；“待清理”（无任何引用）；历史版本数量与最近一次时间。

### 7.2.1 弹层样式（2026-10-29 优化）

- 顶部为 4 个概览卡片：字数、字符数（附不含空白数）、预计阅读、正文大小；其后依次为“时间与位置”“内容元素”“附件”“版本”。
- 内容元素以带图标的标签展示，只显示数量非 0 的项；无附件显示“没有附件”，“仅历史引用”“待清理”仅在非 0 时出现并带说明提示；时间附相对时间；状态用小标签。
- 版本号、内容格式、笔记 id 收纳到默认折叠的“技术信息”。弹层宽度 360px，内部细滚动条，深浅色主题均已用 Chrome 查看。
- 实现位置：`src/components/NoteInfo.tsx`、`src/styles.css`；数据与接口不变。

## 11. V8-11 段落与标题缩进（content schema 13）

- 问题：工具栏“增加/减少缩进”原本只作用于列表（调整嵌套层级，见 plan_v5），普通段落、标题没有缩进能力，光标不在列表时按钮置灰。
- 数据格式：`paragraph`、`heading` 新增整数属性 `indent`，取值 1–6，空/缺省/0 表示无缩进（`shared/indent.ts`）。校验：非 1–6 的整数返回 `INVALID_INDENT`；`CURRENT_SCHEMA_VERSION` 升为 13，`SCHEMA_FEATURE.indent = 13`，低于 13 的客户端写入非空缩进被拒绝并要求刷新；兼容读取 1–12。沿用 0010 的 1–99 范围约束，无新增迁移；产生 schema 13 内容后禁止回滚旧 Worker。
- 编辑行为（`src/components/editor/indent.ts`）：
  - 光标在列表项内：沿用列表嵌套（`sinkListItem`/`liftListItem`），行为不变；
  - 光标/选区在普通段落、标题（含引用内、表格单元格内）：每次增减一级，范围 0–6，多块选区逐块处理，已到上限/下限的块跳过；
  - 代码块内不可用（仍使用 Tab/Shift+Tab 缩进空格）；只读时置灰；保持一次撤销一步，走原保存队列。
  - “+”菜单里的“增加缩进/减少缩进”点击后菜单保持打开，可连续点击；其他菜单项仍然执行后关闭菜单。Chrome 实测连续增加两次、减少一次菜单都保持显示，点“引用”后关闭。对应 `v5.spec.ts` 缩进用例改为“菜单已打开则不再点“更多””（单元格 3 个用例通过，正文 3 个仍受既有焦点问题影响）。
  - 按钮可用性随当前上下文计算：能增/减时才可点击；键盘使用 Tab/Shift+Tab（见 V8-20），不使用 Cmd+[ 以免与浏览器后退冲突。
- 显示：每级缩进为 `编辑器字号 × 2`（窄屏 ×1.25）的左内边距，标题与正文同级缩进宽度一致；复制粘贴经 `data-indent` 属性保留，外部 HTML 中的非法值被忽略。
- Markdown/ZIP 导出不体现段落缩进；首块作为笔记标题时不提供缩进入口；Tab 键缩进见 V8-20。
- 验证：单元测试 `tests/unit/indent.test.ts`（1–6 接受、空/0 视为无、旧 schema 与非法值拒绝）；Chrome 实测段落/标题增减、多块选区、列表仍嵌套、代码块置灰、到 6 级后“增加缩进”置灰、保存为 schema 13 且刷新后保留。未验证窄屏与撤销/重做的完整组合。

## 12. V8-12 行内代码边界光标

- 问题：行内代码标记默认是“包含式”（inclusive），代码末尾与后续文字之间只有一个文档位置且视为在代码内，方向键从代码末尾直接越过后面第一个字符，无法在代码与后文之间（代码外）输入普通文字。TipTap 自带的 `exitable` 退出只在整段末尾生效。
- 方案（`src/components/editor/NoteEditor.tsx` 的 `CodeBoundary`）：保持包含式（连续输入仍留在代码内，Cmd/Ctrl+E 后连续输入、反引号输入规则不变），在行中代码末尾边界用方向键切换“代码内/代码外”光标状态：
  - 在代码内按 → 不移动，只通过 stored marks 去掉代码标记，之后输入为普通文字；再按 → 才越过后面的字符；
  - 在代码外按 ← 不移动，恢复代码标记，回到代码内；
  - 仅处理空选区、非组合输入、代码后紧跟非代码文字的位置；整段末尾仍使用 TipTap 原有退出（插入空格）。
- 不采用非包含式（`inclusive: false`）：实测会使 Cmd/Ctrl+E 后只有第一个字符在代码内，无法连续输入代码。
- 已知限制：光标在两种状态下位置相同，没有视觉区分；点击代码末尾默认处于“代码内”，需按一次 → 退出。
- 验证：Chrome 实测边界输入留在代码内、→ 后输入为代码外、← 回到代码内、再按 → 越过下一字符、切换代码后连续输入、反引号规则。未验证真实 IME 与触屏。

## 13. V8-13 局部复制不带外层结构

- 问题：复制引用、列表项、标题或单元格内的一小段文字后粘贴到空行，会生成带引用/列表/标题/表格外壳的新块。原因是 ProseMirror 剪贴板在 `data-pm-slice` 里记录来源上下文（如 `["blockquote",null]`），粘贴到空段落时会重建该结构；粘贴到非空段落则按行内文字合并，所以表现不一致。
- 方案（`NoteEditor.tsx` 的 `PasteInline`，`transformPasted`）：当粘贴内容只是“单个文本块内的局部内容”（逐层只有一个子节点直到文本块，且开放深度等于嵌套深度+1）时，去掉外层，仅保留行内内容，落入目标段落。
- 保持原行为：复制多个块或整块结构（如含多段的整个引用、整个列表/表格）仍保留结构；代码块内的局部复制不变；本身就是普通段落的内容不变。
- 验证：Chrome 实测引用内行内代码、标题文字、列表项文字、单元格文字粘贴到空行均为普通段落，含两段的整个引用粘贴后仍是引用。未验证真实键盘复制粘贴、跨浏览器和 iOS。

## 14. V8-14 移动端 P0 优化

> 来源：移动端截图走查（列表页、编辑页顶部与工具栏、“更多格式与插入”菜单）及 iPhone 13 尺寸（390×664，触屏模拟）的实测数据。本节定义范围、验收与实现结果。无 schema、API、数据库变化，零新增依赖。

### 14.1 范围与不做

- 范围：A 标题被截断；B “更多格式与插入”菜单改为满宽底部弹层；C 列表页搜索行空白与“导入 Markdown”入口；D 列表页控件触控尺寸。
- 不改动：桌面（≥768px）布局与行为。
- 断点沿用现有 `max-width: 767px`（及 `pointer: coarse` 触屏规则），不引入新断点。

### 14.2 A 编辑页标题被截断

- 现状：顶栏标题是固定 28px 高、`overflow: auto` 的 `textarea`（`.note-header-title`，移动端 13px）。较长标题折成两行（实测内容高 46px），只露出约一行半，下半行被裁切（截图红线处）。
- 方案：
  - 未聚焦：标题单行显示，超出用省略号；不改变 `textarea` 节点（避免重新挂载打断中文/日文输入法组合输入），用同位置的 `aria-hidden` 展示层叠加显示省略文本，聚焦时隐藏展示层。
  - 聚焦（点击标题）：`textarea` 按内容自动增高，最多 4 行，超过后内部滚动；顶栏高度随之增长并把工具栏下推，不再裁切；失焦后恢复单行。
  - 只读/最近删除：同样使用单行省略展示，点击不展开。
  - 保存与标题投影规则不变（标题仍是首个顶层块的编辑投影，沿用 `splitNoteTitle`/`updateTitle`），不改变保存队列。
- 验收：320、375、390、430px 宽度下，未聚焦时标题单行无半行裁切；聚焦后能完整看到并编辑 ≥2 行标题；组合输入期间标题框不被替换、不丢字；返回键、保存状态、更多按钮位置不抖动。

### 14.3 B “更多格式与插入”菜单改为满宽底部弹层

- 现状与根因：移动端已有统一规则 `.object-popup { left:0 !important; width:100%; border-radius:14px 14px 0 0; max-height ≈60% }`，但 V8-09 为桌面设置的 `.toolbar-more-popup { width: 248px }` 位于 `ui-surfaces.css` 且无媒体查询，覆盖了 `width:100%`，实测移动端该菜单靠左、宽 248px、高 398px（屏高 664px），内部还有滚动条。
- 方案：
  - 将 248px 宽度限定在 `min-width: 768px`；移动端恢复满宽、贴底，沿用现有 `popup-backdrop` 遮罩和 `--popup-bottom` 机制，底部留 `env(safe-area-inset-bottom)`。
  - 菜单项改为两列网格（分组标题横跨两列），最大高度约 70% 屏高，目标是 390×664 下无需内部滚动；行高保持 ≥44px。
  - 触屏（≤767px）隐藏当前不可用（`disabled`）的项，仅显示与当前位置相关的项（例如不在列表/可缩进位置时不显示缩进项）；桌面保持“灰显但保留”。
  - 点击项目后仍然关闭菜单；Esc/遮罩/关闭按钮行为不变；上传文件附件项保持可点击且样式一致。
- 验收：390×664 下菜单满宽贴底，左右无空隙，圆角仅上方；无横向和（在常见项数下）纵向内部滚动；各项可点击，上传文件附件可选文件；桌面宽度下样式与 V8-09 一致。

### 14.4 C 列表页搜索行空白与导入入口

- 现状与根因：移动端规则 `.workspace:has(> .workspace-more) .list-header { padding-right: calc(68px + env(safe-area-inset-right)) }` 给整个列表头部右侧预留 68px，原意是避让右上角“更多”按钮；但该按钮位于第一行（文件夹选择器所在行），搜索行也被连带缩进，实测搜索框 204px + “导入 Markdown” 55px + 新建 38px 只占约 297px，右侧留下空白（截图红框）。另外“导入 Markdown”是低频操作，却占据两行小字的主位。
- 方案：
  - 只在需要避让的第一行保留右侧预留，搜索行使用满宽：搜索框 `flex: 1`，右侧仅保留“新建笔记”按钮。
  - 移动端隐藏搜索行的“导入 Markdown”，在右上角“···”菜单（`appActions`）增加“导入 Markdown…”，沿用现有导入逻辑与文件选择（`.md`/`text/markdown`/`text/plain`）、导入到当前文件夹的规则；桌面保留现状。
  - 导入成功/失败的提示沿用现有 notice。
- 验收：搜索行无多余空白，搜索框占满除新建按钮外的宽度；移动端搜索行不再出现“导入 Markdown”，菜单里可导入并跳转到新笔记；桌面搜索行不变。

### 14.5 D 列表页控件触控尺寸

- 现状（实测）：排序“更新时间 ↓”73×19px、新建笔记 38×38px、导入 55×34px、搜索输入框约 34px 高，均低于 44px 推荐值；文件夹选择器 281×44px 达标，但下拉箭头图标较小。
- 方案（均仅限 ≤767px 或触屏）：
  - 排序控件所在行 `min-height: 44px`，控件命中区至少 44px 高；输入类控件（搜索框、笔记本选择）字号 ≥16px（既有规则 `input, textarea, select { font-size: 16px !important }` 已覆盖，实测搜索框 16px）。
  - 新建笔记按钮 44×44px；搜索框容器高度 ≥44px。
  - 文件夹选择器隐藏原生箭头（`appearance: none`），用 22px 的 `ChevronDown` 图标替代，命中区仍为整个选择器。
  - 不改变桌面尺寸，不改变信息密度以外的视觉层级。
- 验收：以上控件在 390px 宽实测高宽均 ≥44px；排序控件可单手点击并正常切换；搜索框聚焦时页面不被 iOS 放大。

## 16. V8-16 行内标签与笔记链接支持拖拽

## 18. V8-18 引用块内编辑不拆分

- 问题：在引用块中间删除或修改某一行后，引用被拆成多个独立引用，个别行甚至跑到引用外。
- 原因：(1) TipTap 的 Blockquote 在“光标位于引用内非首个子块开头”时按 Backspace 会把该子块整体 `lift` 出引用，从而把引用劈成两段；(2) ProseMirror 默认在空段落按 Enter 会 `liftEmptyBlock`，当空行位于引用中间时同样把引用拆开。清空一行后再 Backspace、行首 Backspace、连按两次 Enter 都会触发。
- 修复（`NoteEditor.tsx` 的 `QuoteKeys`，高优先级快捷键）：引用内非首行开头的 Backspace 改为与上一行合并（`joinBackward`）；位于引用中间的空行按 Enter 只新建一行而不退出引用。仍保留：引用首行开头 Backspace 取消引用，引用最后一个空行按 Enter 退出引用；组合输入期间不拦截。
- 验证（Chrome）：清空第 3 行后 Backspace 得到连续的 4 行；行首 Backspace 与上一行合并；空行 Enter 不再拆分；首行 Backspace 和末行连按 Enter 的退出行为不变。未验证真实输入法。

## 21. V8-21 文件附件行内排列

- 问题：文件附件是独立块，每个附件独占一行。
- 方案（**纯显示，不改数据格式**）：附件节点保持块级，样式改为 `inline-block`（`.react-renderer.node-fileAttachment`），相邻附件在同一行并排、放不下时自动换行；紧凑与卡片样式都适用；其前面的拖拽手柄锚点同样改为行内，避免打断同一行。
- 上传行为：刚插入的附件处于选中状态，下一个附件改为插入在它之后（`insertContentAt(selection.to)`），不再替换它，因此连续上传的附件相邻、同行显示。
- 验证（Chrome）：已有笔记中紧凑样式 2 个、卡片样式 3 个各自同行；连续上传两个文件得到两个相邻附件、顶部坐标一致。未验证窄屏、表格单元格内多附件和真实触屏拖动。
- 光标在附件间移动不再跳动：附件之间的“间隙光标”（ProseMirror gap cursor）此前没有样式，作为普通块元素插入会让同一行的附件重新换行；现已改为绝对定位；附件之间的间隙光标显示为同一行内的竖线（其静态位置落在行内，不再掉到下一行左侧），其他块之间仍为横线；并让紧邻间隙光标的拖拽手柄锚点保持行内。Chrome 实测在三个相邻附件间连续按方向键，卡片坐标始终不变。
- 选中附件后可用左右方向键移动光标：此前点击附件会让“附件操作”弹层抢走焦点，方向键只在弹层内生效。现在鼠标点击时焦点留在编辑器（`Popup` 新增 `autoFocus` 参数），弹层随选区变化或文档更新自动关闭；键盘 Enter/Space 打开时焦点仍进入弹层。Chrome 实测点击第二个附件后连按左右键，选区在附件与间隙之间逐步移动且弹层关闭。
- 标签/行内图片拖拽（后续修复）：(1) 标签连续拖动经常不成功：上一次拖放后留下的选区会让浏览器拖动“选区文字”而不是指针下的标签（dragstart 目标是文本节点），现在在标签、行内图片手柄、笔记链接上按下鼠标时清除原生选区，ProseMirror 才能发起干净的节点拖动，实测同一单元格内拖动后立刻拖到另一个单元格成功；标签同时设为 `cursor: grab; user-select: none`，悬停/选中时在左上角显示小抓手。(2) 行内图片新增拖拽手柄：悬停或选中时左上角出现 20×20 手柄（`data-drag-handle`），可从手柄拖动整张图片到其他位置，只读时不显示；Chrome 实测把图片从第一段拖到第二段成功。(3) 拖动图片本体报“图片必须引用当前实例附件”：`<img>` 自带原生图片拖拽，拖放时携带的是绝对地址的外部图片 HTML，被当作外部图片拒绝；现将块级/行内图片的 `<img>` 设为 `draggable={false}`，让拖动落到节点本身，并给行内图片的 `<img>` 同样标记 `data-drag-handle`（TipTap 只允许从拖拽手柄发起节点拖动），本体与手柄都可拖。Chrome 实测从图片本体把图片拖到另一段、拖回段首均成功且无错误提示。块级图片仍通过块拖拽手柄移动。未验证触屏与窄屏。
- 附件本身可拖动：文件附件节点声明 `draggable` 并把整张附件标为拖拽手柄（TipTap 只允许从手柄发起节点拖动），因此表格单元格、引用、列表项内的附件也可以直接拖动（这些位置没有块拖拽手柄），可在单元格之间、单元格与正文之间移动，落点仍受内容模型约束。Chrome 实测：单元格内的卡片附件拖到另一个单元格、正文中的紧凑附件拖进单元格均成功且无错误提示；点击附件仍打开操作菜单。未验证拖进列表项/引用、触屏和窄屏。
- 表格单元格内附件的光标：(1) 点击单元格里附件下方的空白区域，原先会把光标放进附件前面的段落，现在在附件之后放置间隙光标（`CellTailClick`，仅当附件是单元格最后一个块），可以接着输入文字（输入后在附件后新建段落）；(2) 紧凑样式的附件旁间隙光标按一行高显示（约 1.6em），卡片样式仍与卡片等高（84px），此前一律为 84px。Chrome 实测紧凑/卡片两种单元格：点击附件右侧与下方均出现间隙光标、输入文字落在附件之后，竖线高度分别为 22px / 84px。
- 键盘：选中单元格（或任意容器）内最后一个附件后，按 ArrowRight 本就进入附件后的间隙光标；ArrowDown 与 End 此前停留在“选中附件”状态，此时输入文字会替换附件本身，现在同样移到附件后的间隙光标（`CellTailClick` 的 `handleKeyDown`，仅当附件后没有其他块；带修饰键不拦截）。Chrome 实测紧凑/卡片两种单元格，三个按键后均出现间隙光标，输入文字落在附件之后，附件保留。
- 说明：附件仍是块级节点，因此它们不能与文字出现在同一行（仅附件之间并排）；若需要与文字混排，需要像行内图片那样新增行内节点并升级 schema，本次未做。

## 23. V8-23 代码块折叠状态持久化（content schema 14）

- 需求：代码块的折叠/展开状态保存到笔记中，刷新、换设备后保持。
- 数据格式：`codeBlock` 新增可选布尔属性 `collapsed`（缺省/null/false 表示展开，true 表示折叠）。校验：非布尔值返回 `INVALID_CODE_BLOCK`；`collapsed: true` 在低于 14 的 schema 下被拒绝（`UNSUPPORTED_CONTENT_SCHEMA`）。`CURRENT_SCHEMA_VERSION` 升为 14，兼容读取 1–13；沿用 0010 的 1–99 范围约束，无新增迁移；产生 schema 14 内容后禁止回滚旧 Worker，旧客户端不得覆盖。
- 行为：可编辑时点击“折叠/展开”通过 `setNodeMarkup` 写入 `collapsed`（不进撤销栈，避免撤销到折叠切换）；只读模式和最近删除的笔记不能修改内容，这时折叠/展开只是当前页面内的会话状态，不保存；之后回到编辑模式再点击会写入。少于 9 行的代码块不显示折叠按钮，已保存的折叠标记在其不足 9 行时不生效。复制粘贴通过 `data-collapsed` 保留；Markdown/ZIP 导出不包含该状态。
- 保存时机（折中方案）：折叠/展开只改变编辑器中的 `collapsed` 属性，事务带 `uranus-fold-only` 标记，**不单独触发保存**——不产生新版本、不改变 revision 和“更新时间”、不让笔记因折叠跳到列表顶部，也不出现“待同步”；该属性在下一次真实编辑保存时随完整正文一起写入。代价：只折叠、没有后续编辑就刷新或离开页面，折叠状态不会保存（页面内保持，刷新后回到上次已保存的状态）。此前曾做过“折叠后立即保存”，因副作用较多已撤销。
- 版本历史预览：预览按“版本自身的 `content_schema_version`”校验与渲染（此前沿用当前笔记缓存的版本号，当缓存仍是 13 而历史版本含 `collapsed: true` 时会误报“代码块折叠状态需要新版客户端”）；预览区不再显示格式工具栏和“只读模式”标记，只显示正文。预览区上方原有的版本标题（`<h3>`）与编辑器自带的标题重复，已移除前者；预览编辑器内部容器改为不截留滚轮（`.editor-content` 的 `overscroll-behavior: contain` 会吞掉滚动，导致整个预览无法用鼠标滚动），由预览面板统一滚动，Chrome 实测滚轮可连续滚动。版本面板宽度由 `min(390px, 90%)` 加大到 `min(680px, 90%)`，预览正文更宽、换行更少（版本列表同宽）。
- 验证：单元测试覆盖布尔与版本校验；Chrome 实测：折叠后服务端 revision 与更新时间不变（等待 32 秒也不同步），随后输入一个字符并保存，服务端写入 `collapsed: true`、revision 加一，刷新后仍折叠；只读下展开不改动已保存内容与 revision。未验证多标签页并发、历史版本恢复和真实触屏。

## 24. V8-24 登录有效期改为 7 天

- 变更：默认会话有效期 24 小时 → 7 天（`SESSION_TTL_SECONDS` 默认 604800，上限仍为 30 天）。代码默认值和滑动续期期限 `ACTIVE_SESSION_TTL_MS` 同为 7 天，前台真实操作后的成功业务请求每小时最多续期一次，续期到当前时间后 7 天；客户端续期尝试节奏固定为每小时一次（原按 24 小时期限推算）。切换账号抽屉文案改为“7 天内免密切换”。
- 模板与类型：`wrangler.example.jsonc`、本地 `wrangler.jsonc` 与生成的 `cloudflare-env.d.ts` 同步为 604800；相关单元/集成测试期望值同步。
- 发布注意：**生产环境需要重新部署并在生产配置中设置 `SESSION_TTL_SECONDS=604800`（或移除该变量使用代码默认值）后才生效**；已签发的 24 小时会话保持原到期时间，下次成功续期时才会延长到 7 天；7 天期限意味着设备被他人获取后的有效窗口更长，需要时可在设置中退出所有记住的账号。
- 验证：`npm test` 126 项通过；未在真实浏览器中等待跨日续期，也未部署生产。

## 25. V8-25 选中样式统一

- 问题：各元素选中高亮不一致：标签是写死的蓝色 `#2878e8`，块级图片用 `--accent-deep`（偏移 3px），行内图片和附件用 `--accent`（偏移 2px/0），笔记链接没有选中样式；深黄轮廓过于抢眼。
- 方案（`src/styles.css`，两个公共变量）：`--select-ring`（`--accent-deep` 的 50% 不透明度，深/浅主题各自适配）和 `--select-bg`（`--accent` 的 10%）。块级图片、行内图片、文件附件（紧凑/卡片）、标签、笔记链接选中时统一为 2px 实线轮廓、偏移 2px（笔记链接 1px），附件、标签、笔记链接再加淡的强调色底；表格选中单元格（淡填充 + 细边框）、按钮/输入框的键盘焦点环（可访问性）和表格行列手柄悬停蓝色不变。
- 笔记链接外观：平时只显示淡黄底（强调色 12%）的胶囊和柔和的黄色文字（`--accent-deep` 70% 与正文色混合，深/浅主题各自适配），不再常驻下划线；悬停时出现下划线、底色加深到 22%；目标不存在时保持删除线与降低透明度，不显示下划线；打印仍保留下划线。Chrome 实测深/浅主题静止无下划线、悬停有下划线与更深底色。
- 验证（Chrome）：深色与浅色主题下，标签、行内图片、块级图片、卡片附件、紧凑附件选中时轮廓均为 2px、偏移 2px、同一变量颜色（深色 rgb(248,217,110)/50%，浅色 rgb(128,100,0)/50%）。笔记链接点击会跳转，规则已添加但未实际选中验证；未逐项目视检查底色效果。

## 26. V8-26 拖入文件上传

- 需求：直接从系统文件管理器把文件拖进笔记。此前编辑器没有拖放上传入口（浏览器会在新标签页打开文件或忽略）。
- 实现（`NoteEditor.tsx` 的 `handleDrop` 与 `dropHandler`，不改后端和数据格式，完全复用现有上传/插入逻辑）：
  - 仅处理拖放数据含文件（`Files`）的情况，编辑器内部拖动标签、图片、附件、块不受影响。
  - 按落点（`posAtCoords`）放置光标，再逐个上传；图片（PNG/JPEG/WebP/GIF）插为行内图片，其他白名单类型（txt/md/csv/json/yml/pdf/zip/docx 等）插为文件附件；一次拖入多个文件按拖入顺序依次插入，任一上传失败则停止并沿用现有“重试/取消上传”提示。
  - 不在白名单的文件不上传，上传结束后给出“不支持的文件类型：…”提示；上传进行中再拖入文件，提示“正在上传，请等当前文件上传完成后再拖入”，不排队；只读模式提示“当前为阅读模式…”并阻止浏览器打开文件。提示使用自动消失的编辑器提示，不会被后续插入清除。
  - 拖拽经过编辑区时整个编辑区显示虚线轮廓与淡底色（`file-drop-active`）；打印时隐藏。
- 验证（Chrome，用合成的 `DragEvent` + `DataTransfer` 模拟）：拖入图片 + txt + exe 到第二段，图片与附件依次插入、exe 被拒绝并提示；连续两次拖入第二次提示“正在上传”；只读模式提示并被阻止；拖拽期间出现高亮、放开后消失。未验证真实文件管理器拖放、Safari/Firefox、触屏，以及拖入表格/引用/列表内的落点约束。

## 27. V8-27 行内文件附件（content schema 15）

- 需求：文件附件原为独立块，只能附件之间并排，光标只能用间隙光标放在附件后，不能与文字同一行。
- 数据格式：新增行内节点 `inlineFile`（行内、原子、可拖动，无子节点和 marks），属性与块级附件相同但没有 `display`：`attachmentId`、`fileName`、`size`、`mime`（`shared/files.ts` 的 `inlineFileAttributes`，严格模式，不接受图片类型）。只能位于段落内（含表格单元格内段落），不能位于标题。`CURRENT_SCHEMA_VERSION` 升为 15，兼容读取 1–14；schema 15 以下写入 `inlineFile` 被拒绝；沿用 0010 的 1–99 范围约束，无新迁移；产生 schema 15 内容后禁止回滚旧 Worker，旧客户端不得覆盖。块级 `fileAttachment` 保留，不自动迁移。
- 服务端：附件引用集合、元数据一致性校验（`validateFileMetadata`）、搜索文本、笔记信息统计均把行内附件当作文件附件；Markdown 导出为指向 `attachments/` 的链接，ZIP 导出包含文件。
- 编辑行为：新上传、拖入的文件默认插入为行内附件（光标在段落内直接插入，同一行可连续放多个，光标可放到前后输入文字；光标在标题、代码块或选中块时在其后新建段落）；图片仍为行内图片。行内附件是紧凑的文件名小标签，点击弹出菜单：下载、预览（txt/md/csv/json/yml/pdf）、“独立”（转为独立附件并拆分所在段落）；块级附件菜单新增“行内”（转为行内附件，单独占一个段落）。行内附件可整体拖动，复制粘贴（含跨笔记复制为目标笔记专属附件）、选中样式与其他元素一致。
- 间距：标签、行内附件、笔记链接与前后文字、彼此之间留出约 6px（各自左右外边距 3px/3px/2px，位于段首时不加左边距），不再紧贴。
- 验证：单元测试 `tests/unit/inline-file.test.ts`（版本、位置、属性、导出）；Chrome 实测：拖入两个 txt 到段落中间，在文字中间同一行出现两个标签，在最后一个标签后输入文字落在其后；菜单含下载/预览/独立，预览可用；行内与块级互转；保存后服务端为 schema 15 且内容为 `paragraph(inlineFile…)`。未验证真实 iOS/Safari、窄屏、拖入表格/引用内、旧独立附件批量转换。
